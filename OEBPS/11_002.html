11.2    Blöcke anlegen und integrieren

Mit den sogenannten Blöcken steht in Magento eine weitere Art Content-Typ zur Verfügung, den Sie beim Aufbau Ihres Content-Bereichs nutzen können. Blöcke haben vom Prinzip gewisse Ähnlichkeiten mit den Variablen, daher möchte ich in das Thema bewusst nach dem Abschnitt über Variablen einführen. Bei einem Block handelt es sich nicht um einen Inhalt, den Sie direkt per URL aufrufen können. Ähnlich wie eine Variable ist ein Block ein Datensatz, der primär dafür benötigt wird, um einen Inhalt zu speichern. Dieser Inhalt kann wiederum auf beliebigen Seiten, innerhalb der Templates oder in einer Transaktions-E‐Mail aufgerufen werden. Im Gegensatz zu einer Variable ist der statische Block jedoch nicht dafür konzipiert, eine oder wenige Informationen in Textform bzw. mit sehr abgespeckten HTML-Formatierungen zu speichern. Ein Block kann recht umfangreiche HTML-Strukturen beinhalten oder einen sehr langen Fließtext speichern. Man könnte daher sagen, Blöcke sind die logische Weiterentwicklung der Variablen. Das Grundkonzept ist identisch, die Möglichkeiten bei den Blöcken sind aber wesentlich ausgeprägter und umfangreicher.

Blöcke werden bevorzugt in Templates genutzt

Magento-Frontend-Entwickler nutzen bei der Realisierung von Templates, sprich Designs für das Frontend, gern die Blöcke und lagern in diese Inhalte aus. Nutzt ein Frontend-Entwickler beispielsweise für den Footer einen Block und hinterlegt im Block den Inhalt des Footers, so kann dieser Inhalt problemlos durch den Shop-Betreiber angepasst und erweitert werden, ohne dass am eigentlichen Template Änderungen vorgenommen werden müssen. Möchten Sie daher, unabhängig vom eigentlichen Inhalt, gewisse Bereiche, die speziell durch das Template geprägt werden, ändern, so sollten diese Bereiche und Inhalte in Blöcke ausgelagert werden.

Welche Möglichkeiten und Funktionen Ihnen bei den statischen Blöcken zur Verfügung stehen und wie Sie einen Block in das Frontend integrieren, erfahren Sie im folgenden Abschnitt.

11.2.1    Einen neuen Block erstellen

Da Sie einen Block innerhalb des Backends erstellen, müssen Sie sich im ersten Schritt mit Ihren persönlichen Zugangsdaten am Magento-Backend anmelden. Nachdem Sie sich erfolgreich angemeldet haben, klicken Sie bitte auf Inhalt • Elemente • Blöcke. Genau wie bei den Variablen wird Ihnen Magento eine Tabelle anzeigen, die jedoch komplett leer ist. Im Standard gibt es in Magento kei7ne bereits angelegten Blöcke, weshalb es an dieser Stelle vollkommen normal ist, dass keine Datensätze gefunden werden. Ignorieren Sie daher die Tabelle in diesem Moment, und klicken Sie auf den Button Neuen Block hinzufügen. Magento leitet Sie anschließend zu einer neuen Ansicht weiter. Bei dieser Ansicht handelt es sich um die Eingabemaske, mit deren Hilfe Sie den Inhalt des Blocks hinterlegen können.

An dieser Stelle möchte ich wie bei den Variablen ein konkretes Beispiel für die Anlage des Blocks heranziehen. Da ich an diversen Stellen innerhalb des Frontends gern eine Werbeaktion bestehend aus Werbebanner und Text darstellen und diese Aktion nicht auf jeder Seite einzeln pflegen möchte, soll mein Block Informationen zur Werbeaktion enthalten. Folgen Sie mir, um die Funktionsweise der Blöcke zu verstehen, daher einfach in diesem Beispiel, Abwandlungen können Sie aber natürlich gern immer und zu jeder Zeit vornehmen und Ihrer Kreativität freien Lauf lassen.

Zuallererst können Sie definieren, ob der Block aktiviert bzw. deaktiviert ist. Sie sehen das entsprechende Eingabefeld in Abbildung 11.6 direkt am oberen Bildschirmrand.

Abbildung 11.6    Im ersten Schritt müssen Sie bei einem Block definieren, ob dieser aktiv oder inaktiv ist.

Sobald Sie einen Block als deaktiviert definieren, können Sie ihn zwar weiterhin einbinden, es wird jedoch keine Ausgabe erfolgen. Sprich, der Block ist weiterhin im System vorhanden, das Frontend wird ihn jedoch ignorieren. Belassen Sie daher in diesem Moment die Option Enable Block auf Ja. Als Nächstes müssen Sie dem Block einen Namen geben, hierfür steht Ihnen das Feld Block-Titel zur Verfügung. Der Name wird innerhalb des Frontends nicht kommuniziert, daher können Sie an dieser Stelle irgendeine beliebige Bezeichnung für diesen Block wählen. Auch sind Sie bezüglich der Zeichen nicht wirklich eingeschränkt, Sonder- und Leerzeichen stehen zur Verfügung. Ich wähle als Inhalt für den Block-Titel die Bezeichnung »Werbeaktion Neukunden 2017«. Ähnlich wie bei einer Variable wird später der Block nicht über den Namen oder eine kryptische ID, sondern anhand einer selbst definierten Kennung angesprochen und eingebunden. Diese Kennzeichnung hinterlegen Sie im nächsten Feld Kennung. An dieser Stelle müssen Sie mit Sonderzeichen etwas vorsichtiger sein. Meine Empfehlung, jedenfalls gehe ich immer so vor, ist die Verwendung von kleingeschriebenen und durch Bindestriche getrennten englischsprachigen Bezeichnungen. In diesem Fall hinterlege ich die Kennung »sales-campaign-new-customers-2017«. In der Praxis kommt es häufiger vor, dass in Magento-Systemen recht viele Blöcke vorhanden sind, zum Teil einige Hundert. Um den Überblick zu behalten, ist es sinnvoll, als erstes Wort eine Art Kennung zu definieren, worum es sich bei diesem Block handelt. In meinem Fall eine »sales-campaign«. Würden Sie hingegen einen Block anlegen, der für Inhalte im Footer verantwortlich ist, würde ich als erstes Wort »footer« wählen. Sie können an dieser Stelle jedoch auch gern ein eigenes System etablieren, letztendlich ist es nur wichtig, später mit der Vielzahl der Einträge zurechtzukommen und den Überblick zu bewahren. Haben Sie die Kennung hinterlegt, müssen Sie definieren für welche Store Views, also Sprachen, der Block verfügbar sein soll. In Abbildung 11.6 sehen Sie beispielsweise mehrere Einträge, Sie dürften zum jetzigen Zeitpunkt ausschließlich einen haben. Wenn Sie später mehrere Sprachen in Ihrem Frontend aktivieren, müssen Sie einem Block immer mitteilen, in welchem Store View er angezeigt werden darf. Angenommen, ich habe 10 Sprachen, sprich 10 Store Views, und möchte meinen Block »Werbeaktion Neukunden 2017« in jeder Sprache ausgeben. Dann muss ich 10 Blöcke anlegen, jeweils mit derselben Kennung sales-campaign-new-customers-2017 und jedem dieser 10 Blöcke jeweils seinen entsprechenden Store View zuweisen. Magento wird dann im Frontend, sobald ein Block geladen werden soll, immer prüfen, in welchem Store View sich Magento befindet und welcher Block in diesem Store View ausgegeben werden soll. Mir ist bewusst, dass Ihnen zur jetzigen Zeit das Backgroundwissen zur Multistore-Fähigkeit von Magento fehlt. Das ist an dieser Stelle aber auch gar nicht so schlimm, denn ich werde Ihnen in Kapitel 17, »Magento-Multistore-Funktionalität konfigurieren und nutzen«, eine recht ausführliche Einführung in dieses Thema geben. Wählen Sie daher an dieser Stelle einfach den einzig in Ihrem System vorhandenen Eintrag bzw. den Eintrag alle Store Views aus.

Last, but not least haben Sie bei der letzten Option die Möglichkeit, Inhalt zu hinterlegen. Aktuell hat der Block nur einen Namen, eine Kennung und weiß, zu welchem Store View er gehört. Damit später im Frontend eine Ausgabe stattfinden kann, müssen Sie jetzt noch einen Inhalt hinterlegen. Magento stellt Ihnen hierzu den bereits bekannten WYSIWYG-Editor zur Verfügung. Innerhalb des WYSIWYG-Editors stehen Ihnen alle Möglichkeiten zur Verfügung, Sie können selbst Widgets integrieren. Denken Sie dabei an die Widgets, die Sie im letzten Kapitel direkt auf der Startseite eingefügt haben. Theoretisch können Sie diese Widgets auch in einen Block einfügen. Neben dem Zugriff auf Widgets können Sie zudem Variablen hinzufügen sowie auf alle erdenklichen Formatierungsmöglichkeiten zurückgreifen. Ich vergleiche den WYSIWYG-Editor immer gern mit Microsoft Word. Viele der Symbole sind recht selbsterklärend, ansonsten können Sie sich an dieser Stelle aber auch gern im Trial-and-Error-Modus durch die verschiedenen Möglichkeiten des Editors klicken.

Ein Block, der ein Widget enthält, das den Block aufruft …

In Magento existiert ein Widget, das einen Block aufrufen und darstellen kann. Das ist äußerst praktisch, denn so können Sie ohne Programmierkenntnisse in Seiten oder eben in Blöcken bereits angelegte Blöcke laden. Es kommt häufig die Frage auf, ob in einem Block ein Widget integriert werden kann, das den aktuellen Block lädt. Das wäre sozusagen eine Endlosschleife per excellence. Magento hat diese Möglichkeit tatsächlich bereits im Vorfeld berücksichtigt und fängt diesen Fehler direkt ab. Sie können also keine Endlosschleife erzeugen. Ich muss zugeben, auch ich bin auf die Idee gekommen und habe es getestet und war gespannt, ob Magento an dieses Szenario gedacht hat …

Wie angekündigt, möchte ich diesen Block nutzen, um eine Werbeaktion abzubilden. Aus diesem Grund füge ich eine schöne Grafik mit etwas Text darunter ein. Abgerundet wird der Inhalt durch einen Button, der auf die Kategorie »Angebote« verweist. Als Endergebnis sieht mein Inhalt daher wie in Abbildung 11.7 aus.

Abbildung 11.7    Der Inhalt eines statischen Blocks lässt sich recht frei und ohne größere Einschränkungen definieren.

Nachdem Sie alle Eingabefelder entsprechend ausgefüllt haben, wobei Sie an dieser Stelle auch anderen Content hinterlegen können, klicken Sie auf den Button Block speichern. Damit haben Sie Ihren ersten Block angelegt und erfolgreich gespeichert!

11.2.2    Vorhandene Blöcke verwalten

An dieser Stelle werde ich Ihnen relativ wenig Neues berichten können, dafür kennen Sie das Magento-System zum jetzigen Zeitpunkt schon zu gut. Wenn Sie bestehende Blöcke editieren oder auch löschen möchten, können Sie dies tun, indem Sie den Link Inhalt • Elemente • Blöcke aufrufen. Magento zeigt Ihnen daraufhin eine Liste mit allen existenten Blöcken an. Sie können einen Block auswählen und werden zur Bearbeitungsmaske geleitet. In dieser Maske können Sie alle hinterlegten Informationen editieren oder den gesamten Block löschen. Diese Vorgehensweise und Funktionen kennen Sie bereits von den Variablen, bei den Blöcken gibt es hierbei keine Besonderheiten, die Sie berücksichtigen müssen.

11.2.3    Blöcke im Frontend einbinden

Wie eingangs erwähnt, können Sie einen Block nicht einfach per URL aufrufen. Ein Block kann nur innerhalb einer Seite oder Kategorie dargestellt werden. Dementsprechend haben Sie auch diese zwei Möglichkeiten, um einen Block zu laden. Interessant ist speziell die Möglichkeit, einen Block relativ einfach innerhalb einer Kategorie einzubinden, daher werde ich Ihnen zuallererst diese Option zeigen.

Klicken Sie im Backend auf Produkte • Kategorienamen, und wählen Sie in dem jetzt dargestellt Kategorie-Baum die Kategorie Angebote aus. Wenn Sie dies getan haben, scrollen Sie zum Abschnitt Anzeigeeinstellungen und öffnen diesen, indem Sie auf den Namen bzw. Bereich klicken. Sehen Sie die Optionen des Bereichs, wählen Sie bei Display Mode bitte die Option Statische Blöcke und Produkte aus. Nachdem Sie die Auswahl getroffen haben, scrollen Sie etwas nach oben, bis Sie zum Abschnitt Inhalt gelangen. Sollte dieser nicht geöffnet sein, öffnen Sie ihn, und scrollen Sie daraufhin zur Option Add CMS Block. Mithilfe des Dropdown-Menüs können Sie anschließend den soeben von Ihnen erstellten Block auswählen, was Sie an dieser Stelle bitte tun. Speichern Sie daraufhin die Kategorie-Einstellungen, und wechseln Sie ins Frontend. Wenn Sie, im Frontend angekommen, nun die Kategorie »Angebote« auswählen, werden Sie im oberen Bereich sofort den von Ihnen angelegten Block sehen. Sie müssten daher eine ähnliche Darstellung wie in Abbildung 11.8 vorfinden. Zugegebenermaßen enthält der Block relativ viel Text, weswegen Sie in der Abbildung auch die Produkte nicht sehen, diese sind jedoch vorhanden und werden am unteren Ende des Blocks ausgegeben. Wie Sie daher sehen, sollten Sie es mit dem Inhalt eines Blocks nicht übertreiben, wenn Sie diesen innerhalb einer Kategorie darstellen möchten.

Der Vorteil eines Blocks liegt, speziell bei diesem Beispiel, auf der Hand. Wenn Sie in vielen Kategorien die Werbeaktion darstellen möchten, so müssen Sie immer nur auf den Block verweisen. Ändert sich der Inhalt oder die Grafik, können Sie diese Änderungen zentral und einmalig im Block selbst vornehmen, müssen aber nicht die ganzen Stellen anfassen, an denen der Block inkludiert wurde. Ein Block ermöglicht daher die zentrale Pflege eines Inhalts, der an vielen verschiedenen Stellen im System beliebig oft eingebunden und dargestellt werden kann.

Abbildung 11.8    Ein Block kann problemlos in einer Kategorie dargestellt werden.

Abgesehen von Kategorien, können Sie Blöcke auch problemlos in Seiten einbinden. Rufen Sie innerhalb des Backends den Menüpunkt Inhalt • Elemente • Seiten auf. Wie auch bei den Variablen wählen Sie in der Auflistung aller Seiten bitte die Startseite aus, und scrollen Sie anschließend bis zum Abschnitt Inhalt. Sie sehen wiederum den WYSIWYG-Editor, den Sie jetzt sicherlich aus dem Effeff beherrschen. Um innerhalb einer Seite einen Block einzufügen, müssen Sie ein Widget nutzen. Klicken Sie daher in der ersten Reihe des WYSIWYG-Editors auf den zweiten Button, mit dessen Hilfe Sie Widgets einfügen können. Daraufhin öffnet sich eine neue Ansicht, in der Sie den Widget-Typ auswählen müssen. Wählen Sie aus dem Dropdown-Menü den Eintrag Statischer CMS-Block aus. Ihnen ist bestimmt schon aufgefallen, dass die Übersetzung der Blöcke je nach Ansicht ein wenig schwankt. In manchen Ansichten spricht Magento von Blöcken, in anderen wieder von statischen Blöcken. In Magento 1 wurde das Feature konsequent mit »statische Blöcke« übersetzt, in Magento hat sich jedoch der Begriff »Blöcke« etabliert. Egal, wie das Feature auch in den jeweiligen Ansichten übersetzt ist, gemeint ist immer dieselbe Funktionalität.

Da für diesen Widget-Typ nur eine Vorlage vorhanden ist, können Sie bei den Vorlagen, hierbei handelt es sich um das nächste Feld, keine Änderungen oder Anpassungen vornehmen. Dafür können und müssen Sie jetzt den Block auswählen, wofür Sie bitte auf den Button Block wählen… klicken. Magento zeigt Ihnen daraufhin alle im System vorhandenen Blöcke an, wie Sie in Abbildung 11.9 sehen.

Abbildung 11.9    Beim Widget »Statischer CMS-Block« können Sie mittels grafischer Oberfläche den gewünschten Block auswählen.

Da Sie vermutlich genau wie ich nur einen Block angelegt haben, fällt die Auswahl an dieser Stelle einfach. Wählen Sie den einzig vorhandenen Eintrag aus, und klicken Sie anschließend auf Widget einfügen. Ist dies erledigt, landen Sie wieder im WYSIWYG-Editor der ausgewählten Seite. Speichern Sie die Seite ab, und wechseln Sie ins Frontend. Rufen Sie die Home page auf, werden Sie anschließend, je nachdem an welcher Stelle Sie den Block eingefügt haben, die Ausgabe des Blocks direkt auf der Startseite sehen. Bei mir ist beispielsweise der Block recht weit oben inkludiert, wie Sie in Abbildung 11.10 sehen können. Sie haben jedoch die Möglichkeit und die Wahl, den Block an jeder beliebigen Stelle in der Seite einzubinden und darzustellen.

Neben der Möglichkeit, Blöcke in Seiten und Kategorien einzubinden, das hatte ich bereits in einem Nebensatz erwähnt, können Blöcke zudem direkt in Templates oder auch in Transaktions-E‐Mails geladen werden. Dadurch ist der Nutzen nochmals höher, und Ihnen stehen noch mehr Szenarien zur Verfügung, bei denen die Nutzung von Blöcken sinnvoll ist. Speziell bei den Templates und Transaktions-E‐Mails müssen Sie jedoch ganz tief auf die technische Ebene herabsteigen, weswegen ich Ihnen Details an dieser Stelle erspare. In Summe handelt es sich bei den Blöcken um eine wirklich nützliche und durchdachte Funktionalität, die Sie definitiv nutzen sollten.
