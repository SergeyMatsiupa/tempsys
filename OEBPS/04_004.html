4.4    Magento an die eigenen Bedürfnisse anpassen

Eine sehr große Stärke von Magento besteht in den umfangreichen Konfigurationsmöglichkeiten. Je konfigurierbarer eine Software ist, desto mehr Aufwand sparen Sie sich bei der Entwicklung. Sollte ein Anpassungswunsch auftreten, können Sie diesen über die Oberfläche, sprich das Backend, erfüllen und müssen nicht immer zur Entwicklung greifen. Diese Eigenschaft ist bei Magento seit Beginn der Version 1.x enorm ausgeprägt, denn äußerst viele Dinge lassen sich über das Backend einstellen und konfigurieren. Das erzeugt jedoch auch eine gewisse Komplexität, da man sich in der Vielzahl von Konfigurationsmasken und den Hunderten Einstellungsmöglichkeiten verlieren kann. Damit dies nicht passiert, möchte ich mit Ihnen die Basiskonfiguration Schritt für Schritt durchgehen und Ihnen bei den verschiedenen Möglichkeiten zudem die Best-Practice-Einstellungen mit an die Hand geben.

Allgemein

Use system value – so überschreiben Sie den Standardwert

Bei vielen Konfigurationsoptionen können Sie direkt keine Änderung vornehmen, da das jeweilige Text- bzw. Dropdown-Feld ausgegraut ist. Sie müssen zuerst den Haken bei der Checkbox Use system value entfernen. Dadurch haben Sie die Möglichkeit, den Standard-Konfigurationswert, der vom System vorgegeben wird, zu überschreiben.

Neben dem Standardland können Sie zudem die im System erlaubten Länder definieren. Hierbei handelt es sich um eine Liste von 245 Ländern, von denen jedes in der Standardkonfiguration von Magento freigeschaltet ist. Die erlaubten Länder haben zunächst einmal keinen Einfluss, beispielsweise auf den Bestellprozess. Denn es kann ein Land erlaubt sein, für das aber keine Versandmethode vorliegt, wodurch eine Bestellung bzw. Lieferung in dieses Land letztendlich unmöglich ist. Die erlaubten Länder spielen aber bei der Anlage einer Rechnungs- bzw. Lieferadresse eine Rolle. Grenzen Sie die erlaubten Länder im Vorfeld nicht ein, können Ihre Kunden aus diesen 245 Ländern jedes beliebige Land auswählen. Da es sich hierbei um ein Dropdown-Feld handelt, wird die Auswahl doch sehr unübersichtlich. Je länger die Liste ist, desto schwieriger wird es auch, letztendlich sein gesuchtes Land zu finden. Werfen Sie, um dies ein wenig besser nachvollziehen zu können, einen Blick auf Abbildung 4.8, welche die Anlage einer Rechnungs- bzw. Lieferadresse im Frontend abbildet. Innerhalb dieser Abbildung können Sie ein Dropdown-Feld erkennen, das alle erlaubten Länder darstellt. Wie Sie sich vorstellen können, ist die Übersichtlichkeit mäßig, da auch keine spezielle Suchfunktion innerhalb des Dropdown-Felds vorhanden ist.

Entfernen Sie bitte den Haken bei Use System value, und wählen Sie bei den erlaubten Ländern Deutschland, Österreich, das Vereinigte Königreich und die Schweiz aus. Auf diese Länder werden Sie im späteren Verlauf des Buches noch öfter treffen, an dieser Stelle können Sie hierfür bereits den Grundstein legen. Nachdem Sie die erlaubten Länder definiert haben, fragt Sie Magento nach Ländern, für welche die Postleitzahl optional ist. Im Frontend – es geht hierbei wieder um die Anlage der Rechnungs- bzw. Lieferadresse – gibt es bei der Eingabe der Anschrift ein Feld namens Postleitzahl (PLZ). Dabei handelt es sich in der Regel um ein Pflichtfeld. Bei der Konfigurationsoption PLZ / Postleitzahl ist optional für können Sie konfigurieren, für welche Länder die Postleitzahl ein Pflichtfeld ist und für welche nicht. Würden Sie in dieser Option beispielsweise nur Deutschland auswählen, müssten Ihre Kunden bei der Eingabe einer deutschen Adresse keine Postleitzahl eingeben, wäre die Adresse in Österreich, der Schweiz oder dem Vereinigten Königreich, hingegen schon. Erfahrungsgemäß benötigen Sie, speziell in Europa, bei jeder Adresse zwingend eine Postleitzahl, weswegen Sie an dieser Konfigurationsoption keine Anpassung vornehmen müssen. Denn wenn Sie Ihren Kunden später ohne Probleme die Ware bzw. Rechnung zusenden möchten, ist das Vorhandensein einer Postleitzahl und die damit verbundene Pflichtangabe notwendig.

Auch die nächste Konfigurationsoption hat etwas mit Ländern zu tun. Sie können innerhalb von Magento die der EU zugehörigen Länder definieren. Diese Option hat im ersten Schritt keinerlei Auswirkung auf Ihre Kunden. Speziell bei der Modulentwicklung kann es aber vorkommen, dass Sie gewisse Funktionen nur für EU-Länder freischalten möchten, weswegen eine Liste, welche die EU-Länder definiert, definitiv sinnvoll ist. Betrachten Sie diese Option daher im ersten Schritt als Definitionsliste, auf die bei Bedarf von Erweiterungen zurückgegriffen werden kann. Eine Anpassung der Konfiguration müssen Sie an dieser Stelle aber nicht durchführen, die im Standard konfigurierten EU-Länder sind so weit in Ordnung. Ähnlich wie mit den EU-Ländern verhält sich die folgende Option namens Top-Ziele. Es handelt sich ebenfalls um eine Liste von Ländern, die Sie frei definieren können. Im Frontend bzw. Backend hat diese Option erst einmal keine Auswirkung, wenn Erweiterungen entwickelt werden, kann aber auf den Wert Top-Ziele zurückgegriffen werden. Dies ist denkbar, wenn Sie gegebenenfalls Kunden, die aus einem Top-Ziel kommen, einen gewissen Rabatt oder einen kostenfreien Artikel einräumen möchten. Die Ideen und Möglichkeiten hierfür sind vielfältig, im Standard ist aber keine entsprechende Funktionalität integriert, weswegen Sie diese Option an dieser Stelle getrost ignorieren können.

Im nächsten Konfigurationsabschnitt verlassen Sie die Länderkonfiguration und gelangen zu den Bundesländern. Wenn Sie in der Konfigurationsoption Bundesland ist erforderlich für ein Land auswählen, wird für dieses Land bei der Anlage bzw. Bearbeitung einer Adresse im Frontend automatisch das Bundesland abgefragt. Würden Sie an dieser Stelle beispielsweise Deutschland auswählen, müssten Ihre Kunden bei der Anlage einer Rechnungs- bzw. Lieferadresse in Deutschland zwangsläufig auch ein Bundesland auswählen. In Deutschland ist diese Auswahl aber unnötig, da zum einen von der Postleitzahl auf das Bundesland geschlossen werden kann, zum anderen hilft Ihnen die Information des Bundeslandes nicht weiter. Denn Warensendungen und Rechnungen können problemlos ohne Angabe eines Bundeslandes zugestellt werden. Im Gegenteil, die Abfrage des Bundeslandes ist eher schädlich, denn Eingabemasken sollten möglichst einfach und kompakt gehalten werden, d. h., Sie sollten Ihre Kunden auch nur nach den Informationen fragen, die Sie unbedingt benötigen. Da Sie das Bundesland aber nicht zwangsläufig benötigen, sollten Sie es in Ihrem Online-Shop auch nicht abfragen. Sie können die Abfrage des Bundeslandes deaktivieren, indem Sie das entsprechende Land bei der Option Bundesland ist erforderlich für abwählen. Sobald Sie das entsprechende Bundesland an dieser Stelle abgewählt haben – Deutschland ist beispielsweise von Haus aus abgewählt –, ist die Angabe des Bundeslandes zwar keine Pflichtangabe mehr, aber Ihre Kunden und Besucher werden dennoch nach dem Bundesland gefragt. Dieses Verhalten können Sie unterdrücken, indem Sie die nächste Option namens Bundeslandauswahl erlauben, wenn es optional für das Land ist auf Nein stellen. Diese Option bewirkt, dass die Auswahl des Bundeslandes tatsächlich nur dann angezeigt wird, sobald das Bundesland ein Pflichtfeld ist. Ist für ein ausgewähltes Land die Eingabe des Bundeslandes nicht notwendig, fragt Magento erst gar nicht nach dem Bundesland, und Ihre Kunden bzw. Besucher müssen im Frontend eine Information weniger hinterlegen.

Die Validierung im Backend spielt meiner Meinung nach keine sehr große Rolle, letztendlich können Sie an dieser Stelle diejenige Information hinterlegen, die Sie hinterlegen möchten.

Die Multistore-Fähigkeit ist ein sehr großer USP von Magento, der Ihnen eine Vielzahl von Möglichkeiten bietet. Web

Im Gegensatz zum vorherigen Bereich befinden sich im Konfigurationsabschnitt Web vor allem technische Konfigurationsoptionen, die von Ihren Besuchern und Kunden optisch nicht direkt wahrgenommen werden, aber sehr wohl das Handling und das Einkaufsverhalten in Ihrem Online-Shop beeinflussen können. Die erste Konfigurationsoption betrifft die URL-Struktur Ihres Online-Shops. Bei dem Punkt Store Code den URLs hinzufügen haben Sie die Wahl, ob Sie den sogenannten Store Code zu der URL hinzufügen möchten. Wenn Sie einen Magento-Shop in zwei Sprachen betreiben und jede Sprache als Store Code den eigenen Ländercode nutzt, z. B. de für Deutschland und uk für das Vereinigte Königreich, so könnten Sie diesen Code mit in die URL aufnehmen. Dadurch ändert sich die Basis-URL des Shops von z. B. http://www.foodbaer.de in http://www.foodbaer.de/de sowie http://www.foodbaer.de/uk.

Dieses Verhalten hat Vor- und Nachteile. Laut Aussage von Magento kann dieser Store Code zu Problemen bei den Schnittstellen von Drittanwendungen führen, unter anderem PayPal. Aus diesem Grund ist diese Option standardmäßig ausgeschaltet. Allerdings können Sie Sprachversionen besser über die URL identifizieren und auch auf die verschiedenen Sprachversionen einfacher verweisen, sollten Sub- oder lokalisierte Domainnamen nicht zur Verfügung stehen. Für diesen Einsatzzweck gibt es jedoch auch alternative Ansätze. Sollten Sie einen Magento-Shop in mehreren Sprachen betreiben, ist für den Betrieb nämlich ein Store Code in den URLs nicht zwingend notwendig. Mehr hierzu erfahren Sie in Kapitel 17, »Magento-Multistore-Funktionalität konfigurieren und nutzen«. Lassen Sie daher an dieser Stelle bitte die Store-Code-Option deaktiviert.

In der nächsten Einstellung namens Automatische Umleitung auf die Basis-URL können Sie definieren, wie Magento reagieren soll, wenn Sie bei der Eingabe der Domain im Browser das www vergessen, d. h. statt http://www.foodbaer.de nur http://foodbaer.de eingeben. Im Standard würden Sie auf die www-Version weitergeleitet werden. Diese Weiterleitung erfolgt mit einem sogenannten 302 Statuscode, alternativ können Sie auch eine Weiterleitung mit einem 301 Statuscode oder gar keine Weiterleitung hinterlegen.

HTTP-Statuscode

301: Die aufgerufene Seite bzw. Ressource ist nicht länger unter der eingegebenen URL erreichbar.

302: Die aufgerufene Seite bzw. Ressource ist vorübergehend unter der neuen URL erreichbar.

Der Unterschied bei den beiden Statuscodes liegt primär in der zeitlichen Eingrenzung. Bei Code 301 handelt es sich um eine permanente Weiterleitung, bei 302 um eine zeitlich begrenzte Weiterleitung.

Weitere Informationen hierzu finden Sie unter https://de.onpage.org/wiki/HTTP_Status_Code.

Ich persönlich verwende an dieser Stelle den Statuscode 301, da es sich für mein Empfinden um eine konstante, d. h. permanente Weiterleitung handelt. Eine Weiterleitung, egal ob 301 oder 302, sollten Sie aber auf jeden Fall einstellen. Ansonsten müssen Sie über die Webserver-Konfiguration eine Weiterleitung erstellen. In jedem Fall sollten Ihre Besucher und Kunden in Ihrem Online-Shop landen, ganz egal, ob die Domain mit oder ohne www eingegeben wird. Der darauffolgende Konfigurationspunkt betrifft direkt das Thema Suchmaschinenoptimierung. Als Shop-Betreiber haben Sie ein begründetes Interesse, mit Ihrem Online-Shop bei Google gute Positionen im organischen Ranking zu erzielen. Durch eine höhere Sichtbarkeit und bessere Platzierungen generieren Sie mehr Traffic und daraus abgeleitet mehr Umsatz. Bei der Suchmaschinenoptimierung spielen Hunderte Faktoren eine Rolle, es gibt (leider) nicht den einen Hebel, den Sie umlegen können, um erfolgreich zu sein. Einer dieser Bausteine ist die URL-Struktur, die Sie im Folgenden beeinflussen können. Sie können definieren, ob Sie Webserver Rewrites verwenden möchten oder auch nicht.

Lassen Sie mich Ihnen die Auswirkung an einem konkreten Beispiel erläutern. Angenommen, Sie haben einen Artikel namens »Testprodukt« im System angelegt, dann lässt sich dieser Artikel mit aktivierten Webserver Rewrites unter der URL http://www.foodbaer.de/testprodukt.html aufrufen. Es handelt sich um eine sprechende URL, in dem Fall ist der Artikelname in der URL inkludiert. Wie Sie später sehen werden, können noch weitere Keywords bzw. Begrifflichkeiten in der URL auftauchen. Hier sind Sie relativ frei und ungebunden und können sich frei ausleben. Sind die Webserver Rewrites hingegen nicht aktiv, lautet die URL für denselben Artikel http://www.foodbaer.de/catalog/product/view/id/1. Ganz im Gegensatz zur sprechenden URL handelt es sich nun um eine URL, die Parameter und Informationen enthält, mit denen der Besucher nichts anfangen kann. Das Ergebnis ist in beiden Fällen identisch, Sie landen beim Aufruf der URL auf der Produktdetailseite. Der Unterschied besteht jedoch darin, dass bei der sprechenden URL Google Informationen aus der URL herausziehen kann und die URL ebenso für Ihre Kunden leichter verständlich, merkbar und klar ist. Aus diesem Grund sollten Sie die Webserver Rewrites aktiviert lassen, da diese Option zusammengefasst viele Vorteile und keine Nachteile bringt. Der einzige Grund, diese Option zu deaktivieren, besteht meiner Ansicht nach darin, dass die Voraussetzung hierfür, aktiviertes mod_rewrite bei Ihrem Apache-Webserver, nicht zur Verfügung steht und die Option daher nicht genutzt werden kann. Das ist jedoch das einzige Szenario, warum Sie diese Option deaktivieren sollten.

Der nächste Konfigurationsabschnitt mit dem Titel Basis-URLs, den Sie in Abbildung 4.10 sehen, behandelt allgemeine Konfigurationseinstellungen in Bezug auf die von Ihnen verwendete Domain. Bei der Domain handelt es sich um die Adresse, unter der Ihr Online-Shop im Netz erreichbar ist. In meinem Fall handelt es sich bei der Domain um http://www.foodbaer.de, aktuell dürfte an dieser Stelle bei Ihnen im Entwicklungssystem eine lokale URL wie http://127.0.0.1/magento hinterlegt sein.

Die Basis-URL ist speziell für Magento selbst von großer Bedeutung, da auf dieser Basis Links und Verweise auf JavaScript- und CSS-Dateien sowie Bilder erstellt werden. Sollte an dieser Stelle eine falsche URL hinterlegt sein bzw. hinterlegt werden, wird Ihr Magento-System zu großen Teilen unbrauchbar und es muss eine Rettungsaktion direkt über die Datenbank erfolgen. Ändern Sie daher die Basis-URL nie ab, außer es ist aufgrund eines System- bzw. Domainumzugs notwendig.

Abbildung 4.10    Die Konfiguration der sicheren bzw. unsicheren Basis-URLs

Basis-URL direkt über die Datenbank zurücksetzen

Sollten Sie aus Versehen im Magento-Backend eine fehlerhafte Basis-URL hinterlegen und damit Ihren Online-Shop »zerstören«, können Sie diese direkt über die Datenbank editieren, da Ihnen das Magento-Backend nach Eingabe einer fehlerhaften Basis-URL nicht mehr zur Verfügung stehen wird. Nutzen Sie in einem solchen Fall phpMyAdmin oder ein alternatives Administrations-Tool und öffnen Sie die Tabelle core_config_data. In dieser Tabelle müssen Sie die Werte bei web/unsecure/base_url bzw. web/secure/base_url abändern, um die Basis-URL zu ändern.

Neben der Basis-URL gibt es eine sogenannte Basis-Link-URL. Der hier hinterlegte Wert ist primär für die Erzeugung der Links in Ihrem Online-Shop verantwortlich, beispielsweise zu Produkten oder Kategorien. Ihnen wird sicherlich auffallen, dass der dort hinterlegte Wert etwas merkwürdig aussieht. Magento hinterlegt an dieser Stelle eine Variable, also eine Art Platzhalter, der auf die Basis-URL verweist. Die dort hinterlegte Variable {{unsecure_base_url}} sorgt letztendlich dafür, dass die Basis-URL geladen wird.

Ähnlich verhält es sich, wobei im Standard keine Werte hinterlegt sind, bei den folgenden zwei Optionen namens Basis-URL für Dateien der statischen Ansicht und Basis-URL für Benutzermediendateien. Sie können für die Bereitstellung von statischen Dateien, gemeint sind JavaScript- und CSS-Dateien, sowie Grafiken unterschiedliche URLs hinterlegen. Statische Dateien könnten beispielsweise über http://static.foodbaer.de und Grafiken über http://img.foodbaer.de geladen werden. Die Aufteilung der Inhaltselemente auf verschiedene Domains bzw. Subdomains hatte ursprünglich den Sinn und Zweck, die Ladezeit einer Seite zu optimieren, da Browser-Dateien aus unterschiedlichen Domains bzw. Subdomains parallel laden, wobei dieser Effekt in den letzten Jahren etwas eingeschränkt wurde. Magento erlaubt es Ihnen an dieser Stelle aber dennoch und unterscheidet bei den Domains zwischen einer Basis-Link-URL, welche die Erzeugung der Links auf Seiten im Frontend regelt, der Basis-URL für statische Ansichten, die JavaScript- und CSS-Dateien lädt, sowie einer Basis-URL für Benutzermediendateien, die für Produkt- und Kategoriebilder verantwortlich ist. Belassen Sie an dieser Stelle ruhig die bereits vorhandenen Einstellungen; Anpassungen müssen an dieser Stelle nicht durchgeführt werden.

Der nächste Konfigurationsabschnitt namens Basis-URLs (sicher) enthält zum großen Teil nochmals identische Optionen. Der Unterschied besteht hier schlicht darin, dass Sie die sichere URL konfigurieren können. Magento unterscheidet zwischen einer unsicheren und sicheren URL. Die unsichere URL wird in weiten Teilen des Online-Shops genutzt, immer dann, wenn keine Formulareingaben getätigt, Passwörter übermittelt oder Logins durchgeführt werden. Wenn Sie sich im Frontend nur ein Produkt anschauen, muss dies nicht über eine sichere URL geschehen. Für alle kritischen Bereiche, in denen persönliche Daten abgefragt bzw. übermittelt werden, unterstützt Magento sichere URLs. Eine sichere URL ist in der Regel eine URL, bei der ein SSL-Zertifikat zur Verfügung steht. Sie kennen dies sicherlich von Online-Shops, in denen Sie Einkäufe getätigt haben, z. B. Zalando (siehe Abbildung 4.11). Sobald Sie in den Checkout-Prozess gehen oder in das Benutzerkonto navigieren, leuchtet im Browserfenster bei der Adressleiste ein grünes Symbol auf und anstelle von http:// wird https:// verwendet. Dieses Verhalten zeigt Ihnen als Besucher, dass die Verbindung nun verschlüsselt und sicher ist. Dadurch können eingegebene Informationen wie Kreditkartendaten oder Passwörter nicht abgefangen werden.

In Magento können Sie an dieser Stelle konfigurieren, wie Ihre sichere URL lautet. Bei mir ist per Default https://www.foodbaer.de/ hinterlegt. Theoretisch könnte die sichere URL jedoch auch https://www.foodbaer-sicher.de heißen oder einen komplett anderen Namen tragen. Da dies technisch alles denkbar wäre, erlaubt Ihnen Magento die freie Eingabe einer URL. Exakt wie die unsichere URL bezieht sich die sichere URL wiederum auf drei Bereiche: die Basis-Link-URL, die Basis-URL für statische Inhalte sowie eine Basis-URL für Benutzermediendateien. Zudem haben Sie, gefolgt von diesen Eingabeoptionen, die Möglichkeit, die sicheren URLs für das Frontend und das Backend zu aktivieren bzw. zu deaktivieren. Da Sie lokal kein SSL-Zertifikat haben und dadurch keine HTTPS-URLs verwenden können, ist die Deaktivierung beider Optionen an dieser Stelle sinnvoll. Sobald Sie mit Ihrem Online-Shop jedoch live gehen und ein SSL-Zertifikat zur Verfügung steht, sollten Sie diese Konfigurationsoptionen anpassen und sowohl das Backend als auch das Frontend absichern, indem Sie auf sichere URLs zurückgreifen. Abschließend haben Sie zudem die Möglichkeit, den Offloader-Header zu definieren. Im Standard ist der Eintrag X-Forwarded-Proto hinterlegt, dabei handelt es sich um eine Art Standard zur Identifizierung des ursprünglichen Protokolls einer HTTP-Anforderung, Diese Option können Sie getrost ignorieren und überspringen, da dies für Sie höchstens interessant werden könnte, wenn es zu Problemen mit Ihrer verschlüsselten HTTPS-Verbindung kommen sollte.

Nachdem Sie die sicheren bzw. unsicheren Basis-URLs konfiguriert haben, wobei Sie an dieser Stelle eigentlich keine Einstellungen vornehmen mussten, können Sie im folgenden Abschnitt die von Magento verwendeten Standardseiten definieren. Bei den Standardseiten handelt es sich um Seiten aus dem Content-Management-System, die Sie selbstständig in Magento pflegen und verwalten können. Wichtige Standardseiten sind hierbei:

  • CMS-Startseite
  • CMS-Seite ohne Route
  • CMS-Seite ohne Cookies

Bei der CMS-Startseite geht es schlussendlich darum, welche Seite geladen wird, wenn ein Besucher Ihren Online-Shop besucht und auf der Startseite landet, also nicht direkt eine Kategorie oder Produktseite aufruft. In diesem Fall können Sie definieren, welche der im Content-Management-System angelegten Seiten als Startseite fungiert. Sobald Sie eine URL aufrufen bzw. einen Link anklicken, der zu einer nicht existenten Seite führt, wird immer die CMS-Seite ohne Route geöffnet. Auf dieser Seite können Sie Ihrem Besucher dann eine entsprechende Fehlermeldung zurückliefern, z. B. dass die von ihm aufgerufene Seite nicht gefunden wurde. Bei der CMS-Seite ohne Cookies wird, sollte Ihr Besucher Cookies im Browser deaktiviert haben, eine Weiterleitung zu genau dieser Seite erfolgen. Mithilfe dieser Seite können Sie Ihrem Besucher anschließend mitteilen, dass für die fehlerfreie Nutzung des Online-Shops Cookies notwendig sind und diese akzeptiert werden müssen.

Warum Cookies wichtig sind

Cookies sind Informationen, die lokal auf dem Computer des Nutzers gespeichert werden. Beispielsweise kann eine Session-ID in einem Cookie auf dem Computer des Nutzers gespeichert werden, damit der Online-Shop den Inhalt des Warenkorbs dem Nutzer zuordnen kann. Sollten Cookies im Browser deaktiviert sein, Magento also wichtige Informationen nicht auf dem Computer des Besuchers ablegen können, treten Fehler und Probleme auf, und der Magento-Shop wird für den Besucher stellenweise unbrauchbar. Aus diesem Grund hat Magento eine entsprechende Warnfunktion implementiert, die den Besucher auf die Wichtigkeit von Cookies aufmerksam macht.

Zusätzlich zur Definition der CMS-Standard-Seiten können Sie darüber hinaus noch weitere Einstellungen an dieser Stelle vornehmen. Hierzu zählt die Festlegung von zwei URLs, einmal für den Standard-Web-Aufruf und zum zweiten für die No-Route-Seite. Beide Optionen können und sollten Sie wie im Standard belassen, d. h., Sie müssen an dieser Stelle keine Änderungen vornehmen. Zudem können Sie noch entscheiden, ob Sie auf den CMS-Seiten eine Breadcrumb-Navigation möchten oder nicht. Die Breadcrumb-Navigation hilft Ihren Besuchern dabei, sich in Ihrem Online-Shop zu orientieren, da über diese Navigation ein Rücksprung zur Startseite recht einfach möglich ist. Sie sehen die Breadcrumb-Navigation in Abbildung 4.12 am oberen Bildschirmrand, direkt zwischen Logo und Seitenüberschrift.

Auch hier können Sie auf Änderungen verzichten, da eine aktivierte Breadcrumb-Navigation meiner Meinung nach einen Vorteil für die Besucher darstellt.

Der nächste Konfigurationsabschnitt enthält alle relevanten Einstellungsmöglichkeiten und Optionen in Bezug auf Cookies. Cookies sind, wie bereits auf den vorherigen Seiten erwähnt, essenziell für die Funktionsfähigkeit des Magento-Systems. Denn Cookies erlauben Magento, gewisse Informationen bzw. Informationsfetzen auf dem Computer des Besuchers zu speichern. Diese Funktionalität wird für viele Bereiche innerhalb von Magento benötigt, beispielsweise für das Benutzerkonto oder den Checkout-Prozess. Im Konfigurationsabschnitt Standard-Cookie-Einstellungen haben Sie jetzt die Möglichkeit, gewisse Einstellungen und Verhaltensweisen anzupassen. Die Cookie-Lebensdauer, das ist die erste Option in diesem Konfigurationsabschnitt, erlaubt Ihnen, die Konfiguration der Lebensdauer, also den Zeitraum, in dem ein Cookie auf dem Computer des Besuchers gespeichert wird, zu definieren. Im Standard ist hier ein Wert von 3600 eingestellt. Hierbei handelt es sich um Sekunden, d. h., ein Cookie »lebt« exakt 60 Minuten. Der Cookie-Pfad und die Cookie-Domain sind Informationen, die beim Cookie selbst gespeichert werden. Interessant sind diese beiden Werte speziell dann, wenn Sie auf Basis Ihrer Magento-Instanz mehrere Online-Shops mit mehreren Domains betreiben. Dann kann es passieren, dass Sie für alle Online-Shops mit den jeweiligen Domains eine Hauptdomain für das Cookie festlegen müssen. Was an dieser Stelle hinterlegt werden kann bzw. muss, kommt jedoch immer auf die jeweilige Situation bzw. Anforderung an. Im Standard können Sie die beiden Felder, wie bereits vorgegeben, leerlassen. Die nächste Konfigurationsoption namens Nur HTTP verwenden ist aufgrund der Wichtigkeit extra mit einer Warnmeldung ausgestattet, die Sie in Abbildung 4.13 sehen.

Gegebenenfalls kann dieser Zugriff durch Skriptsprachen in einem Projekt notwendig werden, stellt dann aber letztendlich eine gewisse Sicherheitslücke dar. Daher sollten Sie an dieser Stelle sehr gut evaluieren, ob diese Option auf Nein gesetzt werden muss. Falls Sie sich unsicher sind, belassen Sie es bei der Standardeinstellung und führen an dieser Stelle keine Änderung durch. Die am unteren Bildschirmrand befindliche Meldung bezüglich der Akzeptanz von Cookies verweist, sollte der Besucher auf den Link klicken, auf eine CMS-Seite, die weitere Informationen zur Nutzung und zum Handling der Cookies beinhaltet. Hierbei handelt es sich um eine ganz normale Seite, die Sie innerhalb des Content-Management-Systems anpassen und erweitern können. Editieren Sie hierfür einfach die Seite »Datenschutz und Cookie-Richtlinien«. Wie das im Detail funktioniert, erfahren Sie in Kapitel 11, »Content Management mit Magento«.

Nachdem Sie sich durch die Cookie-Einstellungen geklickt haben, wird es wieder ein wenig technischer. Im Konfigurationsabschnitt Session-Prüf-Einstellungen können Sie verschiedene Einstellungen anpassen, die Einfluss auf das Verhalten der Sessions haben. Sollten Sie den Begriff Session bislang noch nicht gehört haben, hier eine kurze Erklärung. Eine Session ist eine Art Sitzung, die beim Aufruf des Online-Shops durch den Besucher gestartet wird. Durch die Session wird ein Besucher konstant im Online-Shop identifiziert und wiedererkannt. Das ist notwendig, wenn der Besucher sich von Seite zu Seite klickt, in den Checkout geht und sich im Warenkorb aufhält. Die Session-Information wird dabei unter anderem im Cookie gespeichert. Belassen Sie bitte an dieser Stelle die Einstellungen im Standard, es ist nicht notwendig, etwas abzuändern. Falls doch, ist dieser Bereich vor allem für Entwickler interessant, da die Optionen und Auswirkungen auf einem technischen Level zu diskutieren sind. Aus diesem Grund möchte ich Sie an dieser Stelle auch nicht weiter mit Details zu diesen Optionen überfrachten.

Lassen Sie mich Ihnen abschließend den letzten Konfigurationsabschnitt im Konfigurationsbereich Web vorstellen. Es handelt sich hierbei um Einstellungen hinsichtlich der Browserfunktionserkennung. In der ersten Konfigurationsoption können Sie entscheiden, ob Magento den Besucher auf eine CMS-Seite weiterleiten soll, wenn die Cookies beschädigt sind. Das ist durchaus sinnvoll, denn mit fehlerhaften oder nicht existenten Cookies gibt es Probleme im Frontend, und nicht alle Funktionen und Möglichkeiten können problemlos genutzt werden. Neben der Möglichkeit, Cookies zu nutzen, setzt Magento darüber hinaus stark auf die Skriptsprache JavaScript. Ohne JavaScript können das Frontend und das Backend ebenfalls nicht genutzt werden. Es kann jedoch vorkommen, dass JavaScript im Browser deaktiviert ist. Das kommt speziell bei Computern bzw. Browsern in größeren Unternehmen vor. Hier deaktiviert die IT-Abteilung ganz gern aus Sicherheitsgründen die JavaScript-Funktionalität im Browser. Keine Sorge, ein aktiviertes JavaScript, was in jedem gängigen Browser der Normalfall ist, stellt keinesfalls eine Sicherheitslücke da. Aber IT-Abteilungen ticken in solchen Fällen oftmals etwas anders. Sollte jedoch JavaScript deaktiviert sein, haben Sie die Möglichkeit, Magento mitzuteilen, dass in diesem Fall eine entsprechende Nachricht im Frontend ausgegeben werden soll, und genau dieses Verhalten steuert die Option Benachrichtigung anzeigen, wenn JavaScript beschädigt ist. Zum guten Schluss können Sie zudem einstellen, ob eine Nachricht bzw. Warnung ausgegeben werden soll, wenn der lokale Speicher beschädigt ist oder, anders gesagt, keine Möglichkeit besteht, lokal Daten abzulegen. In allen drei Fällen können Sie die Standardeinstellungen beibehalten, da sich diese in der Praxis bewährt haben und Ihnen Magento an dieser Stelle bereits die perfekte Konfiguration vorgibt.

Design

Navigieren Sie nun mithilfe des linken Navigationsmenüs in den nächsten Konfigurationsbereich namens Design. Sollten Sie bereits mit Magento 1 gearbeitet haben, werden Sie sich an dieser Stelle sicherlich etwas wundern. In der Vorgängerversion von Magento 2 war dieser Bereich nämlich recht stark ausgeprägt, und es gab eine Fülle an verschiedenen Optionen. In Magento 2 wurde jedoch genau dieser Konfigurationsbereich verschoben und befindet sich im Menüpunkt Inhalt • Design • Konfiguration. Ich stelle Ihnen diesen Punkt in Kapitel 14 aber noch im Detail vor, nämlich dann, wenn es um die Entwicklung und die Anpassung des Designs geht. Ungeachtet der Möglichkeiten, die in Magento 1 verfügbar waren, bietet Ihnen der Konfigurationsbereich Design einige wichtige Funktionen.

Die erste Option namens Standard-Roboter gibt Ihnen die Möglichkeit, das Verhalten von Google bzw. des Google Bot zu beeinflussen. Im Standard ist die Option Index, Follow ausgewählt. Ist diese Option gewählt, indiziert der Google Bot alle Seiten des Online-Shops und folgt den darauf enthaltenen Links. Wenn Sie über Google gefunden werden möchten, sollten Sie diese Option beibehalten. Alternativ hierzu können Sie auch noindex, nofollow auswählen. Diese Option eignet sich hervorragend für Testsysteme, die über das Internet erreichbar sind, aber nicht im Google-Index landen sollen. Speziell beim Aufbau eines Online-Shops bzw. des Testsystems möchten Sie letztendlich vermeiden, dass unvollständige, fehlerhafte und unter einer internen Domain publizierte Inhalte von Google aufgenommen werden. Zudem gibt es noch die verschiedenen Kombinationsmöglichkeiten aus den Optionen index, noindex, follow sowie nofollow. Bei Ihrem lokalen Testsystem ist diese Auswahl im Prinzip egal, da dieses nicht von Google aufgerufen werden kann. Dementsprechend können Sie die im Standard definierte Option an dieser Stelle belassen.

Währungseinstellung

Nachdem Sie im Bereich Design relativ wenige Einstellungsmöglichkeiten vorgefunden haben, wird der nächste Bereich namens Währungseinstellung wieder etwas interessanter. Wenn Sie diesen Konfigurationsbereich geöffnet haben, finden Sie zuallererst allgemeine Währungseinstellungen. Sie können definieren, welche Basiswährung im Online-Shop verwendet werden soll. Auch können Sie die Standardwährung bei der Darstellung definieren. Da in Ihrem Online-Shop theoretisch mehrere Währungen existieren könnten, legen Sie nun über die Option Standard-Anzeigewährung fest, welche Währung ohne vorherige Auswahl dargestellt wird. Zusätzlich haben Sie bei der nächsten Option die Möglichkeit, die im Online-Shop erlaubten Währungen auszuwählen. Sie können aus einer Liste mit allen auf der Welt verfügbaren Währungen beliebig viele auswählen. Eine direkte Auswirkung auf das Frontend hat diese Auswahl aber noch nicht. An dieser Stelle definieren Sie tatsächlich nur, welche Währungen überhaupt im System zur Verfügung stehen sollen.

Mit der bloßen Verfügbarkeit einer Währung hat es sich allerdings noch nicht getan. Unter anderem spielen Umrechnungskurse eine große und wichtige Rolle. In den folgenden drei Abschnitten namens Yahoo Finance Exchange, Fixer.io und Webservicex geht es exakt um die Festlegung der Umrechnungskurse. Bei diesen drei Diensten handelt es sich um solche, die Ihrem Magento-System tagesaktuelle Umrechnungskurse zurückliefern. Sie können – das erfolgt an späterer Stelle – sich für einen dieser drei Webservices entscheiden, der daraufhin als Datenlieferant fungiert. In diesem Konfigurationsbereich können Sie den Timeout, gemessen in Sekunden, bei der Abfrage der Währungskurse einstellen. Der Standardwert von 100 Sekunden ist mehr als in Ordnung, Änderungen in diesem Bereich müssen Sie also nicht vornehmen.

Bei dem letzten Bereich namens Einstellungen für geplante Imports, Sie sehen diesen in Abbildung 4.15, können Sie den zeitlich terminierten Abruf der Wechselkurse konfigurieren.

Abbildung 4.15    Sie können für den Abruf der Wechselkurse einen Automatismus aktivieren, wodurch die Kurse täglich abgerufen werden.

Grundsätzlich haben Sie die Möglichkeit, diese Funktion zu aktivieren bzw. zu deaktivieren. Gegebenenfalls ist es in Ihrem Fall nicht von Vorteil, tagesaktuelle Währungskurse im Online-Shop abzubilden. In der Praxis wird dies in der Tat in den seltensten Fällen gemacht. Würden Sie jeden Tag die Währungskurse abrufen, hätten Ihre Kunden jeden Tag unterschiedliche Preise. Um genau diesen Effekt zu vermeiden, ist diese Funktion in Magento häufig deaktiviert. An dieser Stelle wissen Sie jedoch, dass es theoretisch möglich wäre, automatisiert und einmal am Tag die Währungskurse abzufragen. An dieser Stelle müssen Sie in Bezug auf die Währungen noch keine Anpassungen und Einstellungen vornehmen. Die Frage ist aber, was passiert, wenn Sie diese Felder nicht ausfüllen. Sie können für alle vier Informationen an dieser Stelle Platzhalter definieren. Die Platzhalter werden bei der Anlage des Produktes anschließend automatisch ausgefüllt. Abbildung 4.19    Definierte Platzhalter für verschiedene Produkteigenschaften

Bei der Maske für SKU ist der Platzhalter {{name}} hinterlegt. Das bedeutet, dass auf das Produktattribut Name zurückgegriffen wird. Sie können an dieser Stelle Produktattribute ansprechen, indem Sie den Attributnamen in zwei geschweifte Klammern schreiben. Würden Sie jetzt einen Artikel anlegen und keine SKU hinterlegen, würde als SKU automatisch der Produktname verwendet werden. Neben der SKU können Sie ein solches Muster ebenfalls für den Meta-Titel, die Meta-Schlüsselworte und die Meta-Beschreibung definieren. Speziell bei den Meta-Informationen ist diese Vorgehensweise sehr praktisch, da Sie diese auf Basis von zu definierenden Attributen definieren können und sich bei der Produktanlage viel Zeit sparen.

Produktattribute

Attribute, hierbei handelt es sich im Prinzip um Produkteigenschaften, nehmen in Magento einen hohen Stellenwert ein. Die Attribute sind die Basis jedes Artikels und bieten enorm viele Möglichkeiten. Eine exakte und detaillierte Beschreibung, was es mit den Attributen auf sich hat, finden Sie in Kapitel 7, »Aufbau und Verwaltung des Produktsortiments«.

An dieser Stelle ist eine Anpassung der verwendeten Attribute aber eigentlich noch nicht sinnvoll. Sinn und Zweck der Attribute besteht darin, ein Produkt möglichst genau zu beschreiben und benötigte Produkteigenschaften abzubilden. An diesem Punkt sind Sie aber momentan noch gar nicht, weswegen Sie höchstens auf im Standard vorhandene Attribute zurückgreifen könnten. Kehren Sie am besten in diesen Konfigurationsbereich zurück, nachdem Sie die ersten Attribute, Attributsets und Produkte angelegt haben.

Im nächsten Abschnitt können Sie einstellen, ob Gäste Produktbewertungen abgeben dürfen. Produktbewertungen können im Frontend zu einem Produkt hinterlegt werden. Neben einem Text haben Ihre Besucher und Kunden die Möglichkeit, verschiedene Kriterien eines Produktes zu bewerten. Die Konfigurationsoption steuert letztendlich, ob Sie Gästen diese Möglichkeit erlauben möchten oder ob Produktbewertungen nur durch registrierte Kunden durchgeführt werden können. Aufgrund meiner Erfahrung, die ich in den letzten Jahren gesammelt habe, rate ich tendenziell zu Bewertungen durch Gäste ab. Das Risiko, sich viele Spam-Nachrichten einzufangen und diese täglich zu säubern, ist enorm hoch. Wenn nur registrierte Kunden Bewertungen schreiben können, besteht zumindest eine Hürde durch die Account-Registrierung. Gäste hingegen könnten einfach, wenn sie ein Produkt aufrufen, eine Bewertung absenden. Ein solches Verhalten öffnet Spammern Tür und Tor.

Der auf diesen Konfigurationsabschnitt folgende Punkt Frontend betrifft direkt die Darstellung des Produktkatalogs im Frontend. Magento unterstützt mehrere Darstellungsformen des Produktkatalogs. Neben einer Listendarstellung kann alternativ oder zusätzlich eine Rasterdarstellung gewählt werden. Im Punkt Listenmodus können Sie festlegen, ob Sie Ihren Besuchern die Wahl der Darstellung überlassen möchten oder ob Sie den Listen- bzw. Rastermodus festlegen.

Raster oder Liste

Letztendlich hängt die Form der Darstellung immer vom gewählten bzw. erstellten Design ab. Der Unterschied zwischen dem Raster- bzw. Listenmodus besteht aber letztendlich darin, dass bei der Rasterdarstellung drei oder vier Artikel nebeneinander dargestellt werden. Bei der Liste gibt es pro Zeile nur einen Artikel, der dafür etwas mehr Detailinformationen enthält. Die Rasterdarstellung eignet sich vor allem dann, wenn Sie eine Vielzahl von Artikeln in übersichtlicher Form auf einen Blick abbilden möchten. Die Listendarstellung ist immer dann empfehlenswert, wenn es sich um erklärungsbedürftige Artikel handelt und Sie schon innerhalb der Kategorieseite mehr Informationen zu einem Artikel bereitstellen müssen.

Sie haben in diesem Konfigurationspunkt folgende Auswahlmöglichkeiten:

  • Nur Raster
  • Nur Liste
  • Raster (Standard)/Liste
  • Liste (Standard) Raster

Die auf die Darstellungskonfiguration folgenden Optionen beziehen sich auf die Anzahl der im Frontend darzustellenden Artikel. Bei der Option Zulässige Werte für Artikel pro Seite als Raster können Sie durch die kommagetrennte Eingabe von Werten festlegen, wie viele Artikel pro Kategorie sich Ihre Besucher im Frontend anzeigen lassen können. Im Standard sind die Werte 9, 15 sowie 30 hinterlegt. Das heißt, auf einer Kategorieseite, bei der als Darstellungsform das Raster gewählt ist, werden mindestens 9 und maximal 30 Artikel angezeigt. Sind der Kategorie mehr als 30 Artikel zugewiesen, muss geblättert werden. An dieser Stelle können Sie beliebig viele Werte ergänzen. Wenn Sie nach der 30 noch den Wert 100 hinzufügen, könnten im Frontend maximal 100 Artikel dargestellt werden usw.

Zeigen Sie nicht zu viele Artikel pro Seite an

Es ist an dieser Stelle durchaus sinnvoll, ein Limit von 30 oder 40 Artikeln pro Seite zu setzen. Stellen Sie sich vor, was für ein Chaos gegebenenfalls herrscht, wenn auf einer Kategorieseite 200 oder 300 Artikel auf einmal dargestellt werden. Neben der Übersichtlichkeit spielt aber auch die Performance eine Rolle. Je mehr Artikel innerhalb einer Kategorie geladen werden müssen, desto stärker beansprucht dies die Server. Letztendlich hängt dies auch immer von Ihrer Hosting-Infrastruktur ab, aber seien Sie an dieser Stelle vorsichtig und verwenden Sie nicht zu hohe Werte.

Nachdem Sie die zulässigen Werte definiert haben – an dieser Stelle müssen Sie vorerst keine Änderungen vornehmen –, werden Sie nach dem Standardwert Artikel pro Seite als Raster gefragt. Hier können Sie nicht einfach nur eine Zahl hinterlegen. Die hier verwendete Zahl muss aus den zulässigen Werten stammen. Dementsprechend könnten Sie an dieser Stelle beispielsweise nicht eine 10 oder 20 hinterlegen, da Sie bei den zulässigen Werten 9, 15 sowie 30 hinterlegt haben. Im Standard ist die Zahl 9 hinterlegt, was dazu führt, dass im Frontend im Standard immer 9 Artikel pro Kategorie dargestellt werden. Haben Sie die zulässigen Werte sowie den Standardwert für die Rasteransicht definiert, können Sie dies in den folgenden zwei Optionen ebenso für die Listenansicht tun. Werfen Sie hierfür bitte einen Blick auf Abbildung 4.20.

Das Prinzip dahinter ist identisch, einzig die Werte unterscheiden sich. Bei der Rasteransicht geht man im Standard von 3 Artikeln pro Zeile aus, weswegen bei den zulässigen Werten ungerade Zahlen verwendet werden. Bei der Listenansicht spielt es letztendlich keine Rolle, ob die Zahlen gerade oder ungerade sind, da hier kein Raster beeinflusst wird, sondern die Liste nur etwas länger oder eben kürzer ausfällt.

Abbildung 4.20    Definieren Sie, wie viele Artikel in der Listenansicht bzw. Rasteransicht dargestellt werden.

Unabhängig von der gewählten Ansicht, können Sie ebenso definieren, ob alle Artikel einer Kategorie dargestellt werden sollen. Die Option Alle Artikel pro Seite erlauben ist im Standard deaktiviert, da Sie sich hierbei in Sachen Performance ein Ei ins Nest legen könnten. Denn wenn Sie in einer Kategorie einige Hundert Artikel haben und ein Besucher im Frontend sich alle Artikel einer Kategorie anzeigen lassen möchte, kann das System gut und gern, abhängig von der Hosting-Infrastruktur, in die Knie gehen. Aus Sicherheitsgründen ist diese Option daher deaktiviert, und es wird im Frontend unterbunden, alle Artikel einer Kategorie darzustellen. Ich empfehle Ihnen an dieser Stelle daher, diese Option deaktiviert zu lassen, außer Sie haben ein sehr überschaubares Produktportfolio und pro Kategorie nur eine Handvoll Artikel. Mit der nächsten Option Artikellisting sortieren nach können Sie Einfluss auf die Standard-Sortierreihenfolge im Frontend nehmen. Wenn ein Besucher eine Kategorie in Ihrem Online-Shop aufruft, wird auf den hier eingestellten Wert zurückgegriffen. Als Wert steht hier unter anderem der Name oder der Preis zur Verfügung. Wie Sie später jedoch sehen werden, können Sie jedes selbst angelegte Attribut an dieser Stelle verwenden und dadurch auch eine Sortierreihenfolge anhand einer von Ihnen erstellten Produkteigenschaft abbilden. Hier bietet Ihnen Magento, wie an so vielen anderen Stellen im System, eine enorme Flexibilität und weitreichende Möglichkeiten.

Die nächsten beiden Konfigurationsoptionen (siehe Abbildung 4.21) sind relativ spannend und haben weitreichende Auswirkungen.

Abbildung 4.21    Der Flat Catalog führt zu spürbaren Verbesserungen der Performance.

Wenn Sie Benutze Flat Catalog-Kategorie sowie Benutze Flat-Catalog-Produkt aktivieren, hat dies auf die Darstellung im Frontend oder im Backend keinerlei Auswirkung. Dennoch passiert im Hintergrund einiges. Magento verfügt über eine enorm komplexe Datenbankstruktur. Wenn beispielsweise eine Kategorie oder auch ein Produkt im Frontend dargestellt wird, kommen die hierzu benötigten Werte nicht aus einer Tabelle, sondern werden zum Teil über 20 bis 30 Tabellen verknüpft abgefragt. Dadurch ist die Abfrage von Informationen recht komplex und aufwendig. Das schlägt sich letztendlich in der Performance nieder, was durch Caching-Strategien abgefangen wird. Die Flat Catalogs umgehen das Problem mit der komplexen Datenbankstruktur ein wenig, indem alle Produkt- und Kategorie-Informationen jeweils in nur eine Tabelle geschrieben werden. Die Flat Catalogs verhalten sich wie eine Art Zwischenspeicher, indem in zeitlichen Abständen durch den Aufbau von Indizes aggregierte Informationen hinterlegt werden. Im Frontend wird beim Auslesen der Kategorie- bzw. Produktinformationen anschließend auf diese aggregierten Daten zurückgegriffen und keine Abfrage über 20 bis 30 Tabellen erzeugt. Dadurch spielt die im Hintergrund liegende komplexe Datenbankstruktur erst einmal keine Rolle mehr, und Magento kommt wesentlich schneller und einfach an die benötigten Daten. Da es sich um eine Art Zwischenspeicher handelt, werden getätigte Änderungen jedoch nicht sofort sichtbar. Sobald etwas an einem Produkt geändert wird, müssen die Daten zuerst aggregiert und anschließend in den Flat Catalog geschrieben werden. Speziell auf dem Produktivsystem kann die Aktivierung dieser Option sinnvoll sein. Sie müssen an dieser Stelle nur aufpassen, dass Erweiterungen von Drittanbietern mit dieser aktivierten Option funktionieren. Bei Magento 1 kam es hier häufiger zu Problemen, da Dritterweiterungen oftmals inkompatibel mit den Flat Catalogs waren. An dieser Stelle empfehle ich Ihnen, diese Option deaktiviert zu lassen, denn dann ersparen Sie sich im späteren Verlauf des Buches das ständige Neuaufbauen dieser beiden Indizes, sobald Sie Produktdaten ändern.

Die Option Dynamische Medien-URLs in Produkten und Kategorien erlaubt Ihnen die Nutzung von Variablen bei der Integration von Grafiken. Sie müssen, wenn diese Option aktiviert ist, nicht immer die komplette URL, z. B. http://www.foodbaer.de/pub/static/frontend/Magento/luma/de_DE/images/logo.svg, hinterlegen, sobald Sie bei einem Produkt oder innerhalb einer Kategorie eine Grafik hinzufügen möchten. Stattdessen haben Sie die Möglichkeit, mithilfe von Variablen eine Grafik einzubinden, z. B. {{media url="path/to/image.jpg"}}. Die Nutzung von Variablen ist besonders dann hilfreich, wenn Sie die URL Ihres Online-Shops ändern. Sie haben auf Ihrem Testsystem z. B. eine vollständige lokale URL. Wenn Sie aber später mit diesem Online-Shop live gehen und ihn unter www.irgendeinname.de betreiben, müssten Sie alle Verweise auf Grafiken aktualisieren. Nutzen Sie Variablen, haben Sie dieses Problem nicht, da keine vollständige URL hinterlegt wird, sondern nur der Verweis auf die Ordner und die Datei selbst. Auch wenn sich später die URL Ihres Online-Shops nochmals ändert, kann Magento die Verweise aufgrund der Variablen problemlos auflösen. Abschließend können Sie in der nächsten Option definieren, wie viele Farbfelder pro Produkt im Standard dargestellt werden sollen. Was es mit den Farbfeldern auf sich hat, möchte ich Ihnen später noch bei der Produktanlage im Detail erklären.

Scrollen Sie bitte zum nächsten Konfigurationsabschnitt namens Produktwarnungen. Dieser Abschnitt beschäftigt sich mit der automatisierten Benachrichtigung Ihrer Kunden, sobald mit einem Produkt etwas passiert. Insgesamt gibt es zwei Fälle, die eintreten können. Magento stellt eine Benachrichtigung bei einer Preisänderung sowie eine Benachrichtigung beim Lagerbestand zur Verfügung. Wenn Sie die erste Option Alarm bei Produktpreisänderung erlauben aktivieren, steht Ihren Besuchern im Frontend eine neue und zusätzliche Funktionalität bereit, die Sie in Abbildung 4.22 sehen können.

Abbildung 4.22    Besucher werden bei Änderungen des Preises und des Lagerbestandes automatisch informiert.

Direkt unter dem Produktpreis erscheint ein neuer Link namens Notify me when the price drops. Dieses Feature ist nur für registrierte Kunden verfügbar, nicht für Gäste. Registrierte Kunden können sich durch einen Klick auf diesen Link informieren lassen, wenn der Artikel günstiger wird. Tritt dieser Fall ein, sendet Magento automatisch an die jeweiligen Kunden eine E-Mail. Diese Option gibt es, wie erwähnt, neben dem Preis auch für den Lagerbestand. In meinem Beispiel (siehe Abbildung 4.22) ist der Artikel zudem nicht verfügbar, da der Lagerbestand 0 beträgt. Magento stellt in diesem Fall einen weiteren Link namens Notify me when this product is in stock zur Verfügung. Diese Funktion ist, ähnlich wie beim Preis, nur für registrierte Kunden verfügbar. Sie können sich als Kunde auf eine Liste setzen lassen, und sobald das Produkt wieder auf Lager ist, sendet Magento automatisch eine E-Mail. Diese Funktion ist in der Praxis enorm hilfreich, denn es kann immer wieder vorkommen, dass ein Artikel bei Ihnen kurzzeitig vergriffen ist. Als Kunde kann man sich aber recht schnell und einfach informieren lassen, sobald der Artikel wieder auf Lager ist, und diesen anschließend kaufen. Bei der automatisierten Benachrichtigung hinsichtlich der Verfügbarkeit handelt es sich um eine Option, die Sie definitiv aktivieren sollten. Anders ist es bei der automatisierten Benachrichtigung hinsichtlich des Preises, denn eine Preisreduktion für einen bestimmten Artikel kommt zwar vor, ist aber selten.

Benachrichtigung bei einem günstigeren Preis

Ich persönlich bin kein Fan der Benachrichtigung im Falle eines günstigeren Preises. Denn der Link bzw. Button impliziert doch letztendlich, dass der Artikel irgendwann günstiger werden muss. Warum sollten Sie sonst einen Link oder Button darstellen, der über einen günstigeren Preis bei diesem Artikel informiert? Und aus diesem Grund werden die Besucher vermutlich beim Kauf eher abwarten und zögern, eben um einen günstigeren Preis abzuwarten. Dieses Verhalten möchten Sie aber exakt nicht haben, denn sobald ein Besucher bei Ihnen auf Ihrem Online-Shop aktiv ist, soll dieser so schnell wie möglich zu einem Kunden konvertieren und einen Einkauf tätigen.

Wie auch bei anderen Einstellungen für Transaktions-E-Mails können Sie bei den Produktwarnungen wiederum eine E-Mail-Vorlage sowie einen Absender auswählen. Beim Absender stehen Ihnen die im Punkt Allgemein • Store-E-Mail-Adressen konfigurierten Absender zur Verfügung, aus denen Sie sich per Dropdown-Menü einen Absender auswählen können. Zudem könnten Sie, falls Sie an dieser Stelle ein weiteres E-Mail-Template angelegt hätten, ein alternatives E-Mail-Template auswählen. Wie Sie weitere E-Mail-Templates anlegen, werden Sie noch im Verlauf dieses Buches erfahren. Der nächste Abschnitt namens Produktalarm-Einstellungen, den Sie direkt nach den Produktwarnungen finden, regelt den zeitlich terminierten Versand der »Produktalarm«-E-Mails. Hier können Sie also definieren, zu welchem Zeitpunkt Ihre Kunden informiert werden, wenn beispielsweise ein Artikel wieder auf Lager ist.

Sollte ein Artikel wieder verfügbar sein, versendet Magento nicht direkt eine E-Mail an die hinterlegten Kunden. Das hat zum Teil Gründe hinsichtlich der Performance, würde aber auch in der Praxis zu Problemen führen. Wenn Sie beispielsweise ein ERP-System an Magento angebunden haben und immer nachts die Lagerbestände übertragen werden, würden die Produktalarm-E-Mails ebenfalls nachts versendet werden. Das ist für eine E-Mail aber nicht unbedingt der perfekte Zeitpunkt. Vermutlich möchten Sie Ihre Kunden in der Mittagspause informieren, nämlich dann, wenn man am Computer sitzt, im Internet surft und auch Zeit für etwas Online-Shopping hat. Aus diesem Grund bietet Ihnen Magento die Möglichkeit, den Versandzeitpunkt der E-Mails zu konfigurieren. Im ersten Schritt können Sie eine Frequenz auswählen, bei der im Standard täglich hinterlegt ist. Bei dieser Konfigurationsoption würden also einmal am Tag entsprechende E-Mails versendet werden. Alternativ können Sie die Optionen monatlich bzw. wöchentlich auswählen. Für meinen Geschmack sind diese Alternativen jedoch uninteressant, da sich innerhalb einer Woche bzw. eines Monats bezogen auf ein Produkt viel tun kann. Auch wenn der Artikel nach einem Tag wieder auf Lager wäre, könnte dieser nach vier Tagen bereits wieder ausverkauft sein. Daher ist es definitiv sinnvoll, den Kunden so früh wie möglich zu informieren. Die Frequenz täglich ist daher an dieser Stelle auch meine Empfehlung.

Neben der Frequenz können Sie den Startzeitpunkt des Mailversands festlegen. Definieren Sie die Stunde, Minute und sogar Sekunde, wann die E-Mails versendet werden sollen. Letztendlich hängt die an dieser Stelle richtige Konfiguration von Ihrem Geschäftsmodell und Ihren Kunden ab. Pauschale Ratschläge sind an dieser Stelle schwierig, wie eingangs erwähnt habe ich jedoch sehr gute Erfahrungen mit Mailings zwischen 11:30 und 13:30 Uhr gemacht. Hier können und müssen Sie aber letztendlich selbst Erfahrungen sammeln; konfiguriert und angepasst ist der Versandzeitpunkt recht schnell.

Es kann immer zu einem Fehler kommen, daher haben Sie zu guter Letzt die Möglichkeit, einen Empfänger, Absender sowie eine Vorlage für Fehler-E-Mails zu hinterlegen. Sollte beim Mailversand ein Problem auftauchen, kann Magento eine Person darüber informieren. Die hier hinterlegte E-Mail-Adresse würde bei einem Problem daher einen Report bzw. eine Information enthalten und wüsste dadurch zudem, dass der E-Mail-Versand nicht reibungslos funktioniert hat. Idealerweise hinterlegen Sie an dieser Stelle Ihre E-Mail-Adresse oder alternativ einen E-Mail-Verteiler, wodurch auch Ihre Kollegen die Fehlermeldung zugesendet bekommen. Wie bei jeder Transaktions-E-Mail-Konfiguration in Magento können Sie zudem noch ein E-Mail-Template sowie einen Absender auswählen.

Lassen Sie uns an dieser Stelle aber die Fehler bzw. Warnungen vergessen und zum nächsten Konfigurationsabschnitt namens Produktbild-Platzhalter fortschreiten. Bilder sind im E-Commerce das A und O. Aus diesem Grund haben Sie, das werden Sie in Kapitel 7, »Aufbau und Verwaltung des Produktsortiments«, sehen, in Magento die Möglichkeit, verschiedene Bilder für einen Artikel hochzuladen und zu verwenden. Magento arbeitet für die Differenzierung der Produktbilder mit einer Kategorisierung, die definiert, wofür das Produktbild verwendet wird. Diese Kategorisierungen lauten:

  • Base
  • Klein
  • Farbfeld
  • Thumbnail

Der Unterschied bzw. die Auswirkung der Kategorisierung besteht im Platz bzw. Ort, an dem das Bild verwendet wird. Das Base-Bild wird immer als Hauptbild beim Laden der Produktansicht ausgegeben, das Thumbnail hingegen ist nur ein kleines Vorschaubild innerhalb der Kategorieseite. Wo welche Bildkategorie aber tatsächlich zum Einsatz kommt, hängt letztendlich auch immer vom Magento-Template ab, da das Template den Verwendungsort definiert. In dem Konfigurationsabschnitt, in dem Sie sich aktuell befinden, können Sie für die verschiedenen Kategorien Platzhalter hochladen, die immer dann zum Einsatz kommen, wenn das Produkt selbst nicht über ein Bild der jeweiligen Kategorie verfügt. Legen Sie ein Produkt ohne Bild an, würde Magento im Zweifelsfall ein eigenes Platzhalterbild anzeigen, was Ihnen eventuell aber optisch nicht zusagt. Wenn Sie mit Platzhaltern arbeiten möchten, können Sie die Bilder an dieser Stelle hochladen.

Sinnhaftigkeit von Produktbild-Platzhaltern

Auch wenn es immer auf die Produkte und die Zielgruppe ankommt, so nehmen Bilder im E-Commerce einen hohen Stellenwert ein. Denn Ihre Kunden haben leider, was im stationären Handel ein gewisser Vorteil ist, nicht die Möglichkeit, ein Produkt anzufassen und von allen Seiten bzw. aus allen Blickwinkeln optisch zu erfassen. Daher sind gute Produktbilder eigentlich eine Selbstverständlichkeit. Platzhalter sind aus meiner Sicht daher wenig sinnvoll, denn wenn Sie ein Produkt anlegen und dafür keine Bilder haben, sollten Sie das Produkt gar nicht erst freischalten. Es gibt tatsächlich nur ganz wenige Fälle, in denen ein Produkt gekauft werden kann, ohne ein entsprechend gutes Bild davon zu haben. Die Platzhalter-Funktion von Magento ist daher zwar praktisch, in der Praxis aber wenig sinnvoll. Sie würden ja letztendlich auch keine Produkte komplett ohne Text bzw. Informationen online stellen. Warum sollten Sie es dann ohne Bilder tun?

Die beiden nächsten Optionen haben Auswirkung auf die URL in Ihrem Online-Shop. Sowohl bei einer Kategorie- als auch einer Produktdetailseite wird in der URL die Endung .html hinzugefügt. Wenn Sie eine andere Endung wünschen, können Sie diese in den folgenden zwei Konfigurationseinstellungen hinterlegen. Ihnen sind hierbei keine Grenzen gesetzt. Auch können Sie die Endung komplett entfernen, indem Sie das Wort .html löschen. Anschließend können Sie die Kategorie- bzw. Produktseite ohne Endung aufrufen. Auch diese Option ist meiner Meinung nach wieder eine gewisse Spielerei, da die Endung an sich keine große Auswirkung auf die organischen Rankings innerhalb von Google hat. Dafür hat die darauffolgende Option namens Kategoriepfade für Produkt-URLs verwenden eine recht große Auswirkung auf Ihren Online-Shop. Im Standard ist diese Option deaktiviert, was bedeutet, dass Sie eine Produkt-URL ohne Kategoriepfad aufrufen können und Magento die Produktlinks ohne Kategoriepfad generiert. Dadurch ergeben sich URLs wie beispielsweise http://www.foodbaer.de/small-roasting-dish.html. Auch wenn das Produkt »Small Roasting Dish« der Kategorie »Teller & Schüsseln« zugewiesen ist, finden Sie in der URL nicht den Kategorienamen. Das hat einen großen Vorteil. Wenn Sie diesen Artikel mehreren Kategorien zuweisen, was in Magento möglich ist und in der Praxis auch häufig passiert, können Sie den Artikel über unterschiedliche URLs aufrufen. Weisen Sie den Artikel beispielsweise zehn Kategorien zu, hat der Artikel zehn URLs, über die er aufgerufen werden kann, da pro Kategorie eine individuelle URL generiert wird. Dieses Verhalten findet jedoch Google nicht gut und bestraft Duplicate Content. Duplicate Content entsteht immer dann, wenn ein identischer Inhalt unter mehreren URLs aufrufbar ist. Genau diesen Effekt hätten Sie, wenn Sie die Option Kategoriepfade für Produkt-URLs verwenden aktivieren. Die Aktivierung dieser Option hat jedoch auch einen positiven Effekt. Die URL würde um den Namen der Kategorie ergänzt werden, wodurch weitere Keywords, nämlich die Kategorie Bezeichnung, zur URL hinzugefügt werden. Dies kann tatsächlich einen positiven Effekt auf das Ranking der Produktseite innerhalb des Google-Indexes haben.

Entscheiden Sie sich für eine Aktivierung der Option, wodurch ein Produkt mehrere URLs besitzen kann, sollten Sie auf jeden Fall die weiter unten aufgeführte Option Verwenden Sie den Canonical Link-Meta-Tag für Produkte aktivieren. Ein Canonical Tag ist eine Information, die im Quellcode vorhanden, für den Benutzer im Frontend aber nicht ersichtlich ist. Das Canonical Tag verweist im Quellcode, sollte eine Seite unter mehreren URLs aufrufbar sein, immer auf die Hauptseite. Dadurch wird Google mitgeteilt, dass zwar mehrere URLs für ein und denselben Inhalt existieren, dies jedoch bekannt und bewusst so gehalten ist. Zugleich erhält Google die Information, welche der vielen URLs sozusagen die führende URL ist. Diese Verhaltensweise verhindert die Duplicate-Content-Problematik, die ich bereits angesprochen habe.

Weshalb der Kategoriename in URLs mehr Probleme als Vorteile bringt

Neben der genannten Duplicate-Content-Thematik hat der Name der Kategorie in den URLs einen weiteren Nachteil. Wenn für einen Artikel je nach zugewiesener Kategorie eine URL erzeugt wird, kann bei einer Vielzahl von Produkten und Kategorien eine recht große Anzahl an Produkt-URLs entstehen, die Magento in der Datenbank speichert. In der Praxis ist es schon oft vorgekommen, dass dadurch ein URL-Index mit mehreren Millionen Einträgen entsteht, der im Hinblick auf die Performance nicht förderlich ist. Sollten in Ihrem konkreten Fall keine stichhaltigen Argumente für die Nutzung des Kategorienamens in den Produkt-URLs bestehen, rate ich von der Aktivierung dieser Option ab.

Da sich die Produkt- oder auch Kategorie-URL immer aus dem Namen oder einem frei definierten Begriff zusammensetzt, kann es bei Änderungen eines Produktes oder eine Kategorie ebenso zu einer Änderung der URL kommen. Magento legt in diesem Fall automatisch eine neue URL an, wie Sie später sehen werden, wenn Sie Produkte und Kategorien anlegen. Wenn Sie die Option Permanent Redirect für URLs erstellen, wenn sich der URL-Key geändert hat aktiviert lassen, wird zudem automatisch eine Weiterleitung von der veralteten URL auf die neue URL angelegt. Diese Option ist äußerst sinnvoll, denn wenn ein Produkt oder eine Kategorie im Google-Index gut gefunden wird, möchten Sie letztendlich dem Besucher keine Fehlerseite anzeigen, nur weil sich bei Ihnen aufgrund einer Umbenennung die URL geändert hat. Zu guter Letzt können Sie zudem den Seitentitel-Separator, d. h. das Trennzeichen beim Meta-Titel, definieren. Der Meta-Titel wird neben der reinen Ausgabe im Quellcode zudem immer in der Browserleiste angezeigt. Der Bindestrich ist an sich in Ordnung, weshalb Sie diese Option nicht unbedingt ändern müssen. Abgeschlossen wird die Konfiguration durch die Option der Canonical Tags für Produkte bzw. Kategorien, die Sie je nach Einstellung der Kategoriepfade aktivieren sollten.

Beim nächsten Konfigurationsbereich können Sie in Summe nur eine Einstellung vornehmen. Bei der Kategorie-Top-Navigation handelt es sich um die Hauptnavigation, die im Frontend dargestellt wird.

Wie Sie im späteren Verlauf dieses Buches sehen werden, kann eine Kategorie beliebig viele Unterkategorien haben. Magento setzt Ihnen hierbei keine Grenzen. Bei der Darstellung im Frontend, die Sie exemplarisch in Abbildung 4.29 sehen, kann es aber definitiv sinnvoll sein, die dargestellten Ebenen zu limitieren, da die Navigation ansonsten sehr unübersichtlich ist, worunter die Usability in Ihrem Online-Shop leidet. Behalten Sie den Standardwert 0 bei, gibt es keine Limitierung in der Darstellung.

In Herunterladbare Produktoptionen, dem nächsten Konfigurationsbereich, können Sie Einstellungen in Bezug auf downloadbare Produkte vornehmen. Magento kann nämlich neben physikalischen zusätzlich mit herunterladbaren Produkten umgehen. Da das Verhalten im Online-Shop auf downloadbare Produkte abgestimmt werden muss, haben Sie an dieser Stelle einen separaten Konfigurationsbereich hierfür. Bei der ersten Option Artikelbestellstatus um Downloads zu ermöglichen können Sie definieren, zu welchem Zeitpunkt die bestellten Dateien heruntergeladen werden können. Der Zeitpunkt ist dabei direkt an den Bestellstatus geknüpft. Wählen Sie ausstehend, kann direkt nach der Bestellung der Download gestartet werden. Wählen Sie in Rechnung gestellt, was gleichzeitig die Standardoption ist, kann der Download erst nach einer ausgestellten Rechnung gestartet werden. Als Nächstes können Sie einstellen, wie oft die Dateien heruntergeladen werden können. Hinterlegen Sie eine 0, so existiert de facto keine Limitierung. Der Kunde kann die gekaufte Datei bzw. Dateien beliebig oft herunterladen. Speziell wenn Sie große Dateien zum Download anbieten, ist eine Limitierung aufgrund des möglichen Datenvolumens (Traffic) definitiv sinnvoll. Wenn Ihre Dateien hingegen eine eher überschaubare Dateigröße haben, müssen Sie die Anzahl der möglichen Downloads nicht zwangsläufig eingrenzen. Wählen Sie an dieser Stelle einfach die Option, die für Ihren Online-Shop bzw. Ihr Geschäftsmodell am sinnvollsten ist, ich bleibe an diesem Punkt bei dem hinterlegten Standardwert, wodurch die Kunden eine Datei beliebig oft herunterladen können. Wenn Sie den oder die Downloads Gemeinsam nutzbar machen möchten, können Sie diese Option aktivieren. Sobald ein Kunde einen herunterladbaren Artikel gekauft hat, kann er bei aktivierter Option theoretisch den Link einem Bekannten oder Freund senden und dieser könnte die Datei ebenfalls herunterladen. Ist diese Option deaktiviert, ist ein Download nur mit den Benutzerdaten des Käufers möglich. Meiner Meinung nach sollten Sie daher diese Option deaktiviert lassen, um ein reges Tauschen von gekauften Downloadartikeln zumindest zu erschweren. Mithilfe der beiden nächsten Optionen können Sie Standardwerte definieren, zum einen für den Beispieltitel, zum anderen für den Linktitel. Was dies im Detail bedeutet, werden Sie in Abschnitt 7.3.2 bei der Anlage eines Downloadartikels aber noch im Detail sehen. Soll sich der Download in einem neuen Fenster öffnen, können Sie dies über die Option Öffnet Links in neuem Fenster festlegen. Mithilfe der Option Inhalts-Anordnung benutzen können Sie zudem die Darstellung der Downloads ein wenig modifizieren. Bei diesen beiden Optionen müssen Sie keine Änderungen vornehmen, da Sie mit der Standardkonfiguration problemlos arbeiten können. Abschließend haben Sie die Möglichkeit, den Checkout beim Kauf eines downloadbaren Artikels für einen Gast, d. h. eine Person, die nicht angemeldet ist und nicht über ein Benutzerkonto verfügt, zu unterbinden. Dadurch können downloadbare Artikel nur von angemeldeten bzw. registrierten Kunden gekauft werden. Diese Option ergibt definitiv Sinn, da beispielsweise über das Benutzerkonto die Download-Links ersichtlich sind. Da ein Gast nicht über ein Benutzerkonto verfügt, müssten Sie ihm dann gegebenenfalls manuell Download-Links zukommen lassen. Auch existiert die Koppelung des Downloads an ein Benutzerkonto, was bei einem Gast zu Problemen führen würde. Belassen Sie daher ruhig an dieser Stelle die Standardeinstellung, die Gästen den Kauf von downloadbaren Artikeln nicht ermöglicht.

Der nächste und letzte Konfigurationsabschnitt steuert die Darstellung der Datumseingabe. So können Sie einstellen, ob ein JavaScript-Kalender für die Datumseingabe verwendet werden soll. Auch können Sie die Reihenfolge der Datumsfelder, das Zeitformat und einen Jahresbereich festlegen. Ein aktivierter JavaScript-Kalender erhöht die Usability im Frontend, wodurch für Ihre Besucher und Kunden ein Mehrwert entsteht. Aus diesem Grund ist die Aktivierung dieser Option definitiv sinnvoll, auch wenn sie zu diesem Zeitpunkt nicht ausschlaggebend ist.

Nachdem Sie einen Einblick in den äußerst umfangreichen Konfigurationsbereich für den Katalog erhalten haben, klicken Sie im linken Navigationsmenü bitte auf den nächsten Unterpunkt namens Lagerbestand. Innerhalb dieses Punktes finden Sie diverse Einstellungen rund um den Lagerbestand und die Behandlung der Bestände (siehe Abbildung 4.30).

Abbildung 4.30    Magento bietet eine umfangreiche Konfiguration in Sachen Lagerbestände.

Im ersten Konfigurationsbereich Lageroptionen können Sie direkt einstellen, was passiert, wenn eine Bestellung storniert wird. Soll in diesem Moment der Lagerbestand der gekauften Artikel wieder erhöht werden, oder hat die Stornierung keinen Einfluss auf den Lagerbestand? Auch wenn in der deutschen Übersetzung die Wortwahl nicht ganz sauber ist, können Sie mit der ersten Option den von mir beschriebenen Fall steuern.[ 10 ] Bei der nächsten Option geht es ebenfalls um die Zählung des Lagerbestandes. Wenn Sie Bestand verringern bei Auftragserteilung aktivieren, wird der Lagerbestand der Artikel direkt nach der Bestellung verringert. Da dies in der Regel die gewünschte Funktionalität ist, ist diese Option im Standard aktiviert. In der Praxis kann es vorkommen, dass gewisse Artikel temporär nicht auf Lager und damit nicht verfügbar sind. Mit der nächsten Option können Sie definieren, ob Magento die nicht verfügbaren Produkte dennoch im Produktkatalog anzeigen soll oder nicht. Wenn nicht verfügbare Artikel nicht angezeigt werden, können diese über die Kategorien bzw. Suche nicht gefunden oder aufgerufen werden. Ein direkter Aufruf über die Produkt-URL wäre aber dennoch möglich. Wenn Sie auf der Produktdetailseite eine Meldung wie »Nur noch 5 Stück verfügbar« anzeigen möchten, die beispielsweise auch Amazon nutzt, obwohl Amazon nicht auf Magento setzt, können Sie dies mithilfe der Option Grenzwert, ab dem »Nur X übrig« angezeigt wird konfigurieren. Hinterlegen Sie an dieser Stelle beispielsweise die Zahl 5, wird ab einem Lagerbestand von 5 Artikeln immer die Nachricht »nur noch x Stück verfügbar« dargestellt. Abschließend, das ist die nächste Option, haben Sie grundsätzlich die Möglichkeit, die Verfügbarkeit darzustellen, im Sinne von der Artikel ist verfügbar oder nicht verfügbar. Sie könnten Magento dahingehend konfigurieren, dass diese Information im Frontend gar nicht dargestellt wird, was ich Ihnen aber nicht empfehle. Es ist durchaus sinnvoll, Ihren Besuchern bzw. Kunden die Information, ob ein Artikel verfügbar ist oder nicht, bereitzustellen. Grundsätzlich können Sie, das ist meine persönliche Empfehlung, die besprochenen Konfigurationsoptionen bei den Standardeinstellungen belassen, da Magento von Haus aus eine sehr gute Standardkonfiguration besitzt.

Scrollen Sie bitte ein wenig nach unten, bis Sie zum Konfigurationsabschnitt Produktbestandsoptionen kommen. Mithilfe der ersten Option können Sie die Verwaltung der Lagerbestände global aktivieren bzw. deaktivieren. Wenn Sie die Lagerverwaltung grundsätzlich definieren, können alle Produkte in Ihrem Online-Shop in jeder Menge gekauft werden. Magento errechnet keine Verfügbarkeit, und jedes Produkt ist zu jedem Zeitpunkt verfügbar. In seltenen Fällen kann die Deaktivierung der Lagerbestände tatsächlich sinnvoll sein. Wenn Sie als Unternehmen im Prinzip jeden Artikel innerhalb von 24 Stunden produzieren bzw. beschaffen können, müssen Sie im Online-Shop nicht unbedingt mit Lagerbeständen arbeiten, da Sie sowieso zu jedem Zeitpunkt lieferfähig sind. Für gewöhnlich stellt diese Situation aber die Ausnahme und nicht die Regel dar.

Wenn Sie Rückstände, also negative Lagerbestände, akzeptieren möchten, können Sie die Option Rückstände dahingehend konfigurieren. Im Standard sind negative Lagerbestände nicht möglich. Wenn ein Artikel ausverkauft ist, ist dieser ausverkauft und nicht verfügbar. An dieser Stelle können Sie jedoch auch Bestellungen von Artikeln mit einem Lagerbestand von 0 erlauben und haben darüber hinaus sogar die Möglichkeit, dem Kunden direkt mitzuteilen, dass die Bestellung möglich ist.

Die Erlaubte Maximalmenge im Einkaufswagen definiert, wie der Name der Option bereits impliziert, die maximale Menge der im Einkaufswagen befindlichen Produkte. Von Haus aus ist in Magento ein abstrus großer Wert hinterlegt, was letztendlich in der Praxis nie zu einer Limitierung führt. Auch kenne ich persönlich aus der Praxis kein Szenario, in dem die Menge der Artikel im Einkaufswagen limitiert wird. Je mehr Ihre Kunden kaufen, desto besser ist das in der Regel für Ihr Geschäft. Dennoch haben Sie an dieser Stelle die Möglichkeit, eine Limitierung einzustellen. Bei der nächsten Option »Nicht auf Lager«-Grenze können Sie hinterlegen, ab welchem Lagerbestand Ihren Besuchern und Kunden die Information angezeigt wird, dass der Artikel nicht auf Lager ist. Im Standard wird die Meldung in Magento bei einem Lagerbestand von 0 ausgegeben, theoretisch können Sie aber auch einen höheren Wert hinterlegen, wenn Sie selbst bei jedem Artikel noch mit einem gewissen Notbestand rechnen möchten. Neben einer maximalen Menge an Artikeln im Warenkorb können Sie im Folgenden zudem eine minimale Menge definieren. Diese Option kommt in der Praxis schon häufiger vor, da sie ähnlich wie ein Mindestbestellwert eingesetzt werden kann. Im Gegensatz zur maximalen Menge kann bei der minimalen Menge an Artikeln eine Differenzierung in Bezug auf die Kundengruppe vorgenommen werden. So können Sie für jede Kundengruppe einen anderen Wert hinterlegen und gezielt für die jeweilige Kundengruppe eine optimale Einstellung hinterlegen.

Mithilfe der nächsten Option Benachrichtigen bei Menge unter können Sie definieren, ab welcher Menge über einen geringen Lagerbestand informiert werden soll. Im Standard ist die Zahl 1 hinterlegt, d. h., sobald der Lagerbestand bei 0 steht, gibt es eine Information von Magento. Die darauffolgende Option Mengenzunahmen aktivieren ist wiederum eine äußerst praktische und auch in der Praxis hilfreiche Funktion. Werfen Sie hierfür bitte einen Blick auf Abbildung 4.31.

Wenn Sie diese Option aktivieren, erscheint ein weiteres Eingabefeld namens Mengenzunahmen mit dem Standardwert 1. Dieser Wert bedeutet, dass Ihre Kunden immer in 1er-Schritten Produkte kaufen können, also 1, 2, 3, 4 etc. Stück pro Produkt. Hinterlegen Sie an dieser Stelle beispielsweise die Zahl 6, dann können Ihre Kunden bzw. Besucher die Produkte nur in 6er-Schritten kaufen also 6, 12, 18 usw. Je nach Geschäftsmodell kann dies eine äußerst nützliche Funktion sein, beispielsweise, wenn Sie aufgrund der Verpackungen immer nur Produkte in gewissen Stückzahlen vertreiben können. Abschließend haben Sie mit der Option Gutschrift-Artikel automatisch zum Bestand zurückgeben noch die Möglichkeit, Artikel automatisch wieder ins Lager zurückzubuchen, wenn Sie bei einer Bestellung eine Gutschrift erstellt haben, wodurch sich der Lagerbestand entsprechend erhöht. Diese Option sollten Sie bei den Standardeinstellungen auf Nein belassen und immer situativ prüfen, ob ein gutgeschriebener Artikel tatsächlich erneut verkauft werden kann oder nicht. Würden Sie die Option Ja wählen, würde eine Gutschrift immer die Erhöhung des Lagerbestandes bewirken, was in der Praxis zu falschen Lagerbeständen führen könnte. Denn ob der Artikel tatsächlich erneut verkauft werden kann, hängt letztendlich von dem Retourengrund und der Qualität der zurückgesendeten Ware ab. Weitere Optionen in Bezug auf den Lagerbestand haben Sie an dieser Stelle nicht, weswegen ich Ihnen nun den nächsten Konfigurationspunkt zeigen kann.

XML Sitemap

Klicken Sie bitte im linken Navigationsmenü auf den nächsten Konfigurationsbereich namens XML Sitemap. Bei der XML Sitemap handelt es sich, wie der Name bereits verrät, um eine XML-Datei, die Links und Informationen zu den in Magento enthaltenen Seiten erzeugt. Dazu zählen Produktdetailseiten, aber auch Kategorie- und CMS-Seiten. Der Vorteil einer solchen XML Sitemap ist die Lesbarkeit für Suchmaschinen.

Wenn Sie Google eine XML Sitemap bereitstellen, kann Google wesentlich schneller und einfacher die gesamten URLs Ihres Magento-Systems erfassen, durchsuchen und in den Index aufnehmen. Ohne XML Sitemap müsste sich Google letztendlich alle Informationen selbst zusammensuchen. Hierbei besteht die Gefahr, dass manche URLs nicht oder erst sehr spät entdeckt werden. Die Nutzung einer XML Sitemap ist daher äußerst sinnvoll, und Magento hat diesbezüglich out of the box auch bereits eine sehr gute Standardkonfiguration.

In den ersten drei Konfigurationsabschnitten können Sie im Prinzip dieselben Einstellungen vornehmen, die sich dann jeweils nur auf Kategorien, Produkte oder CMS-Seiten beziehen. Bei der Frequenz haben Sie die Auswahl zwischen:

  • Immer
  • Stündlich
  • Täglich
  • Wöchentlich
  • Monatlich
  • Jährlich
  • Niemals

Die hier ausgewählte Frequenz wird in der XML-Datei jeweils bei den Produkt-, Kategorie- und CMS-Seiten hinterlegt. Im Standard verwendet Magento den Wert Täglich, der in der Praxis sicherlich gut geeignet ist. Neben der Frequenz wird zudem noch eine sogenannte Priorität angegeben, d. h. wie wichtig eine Kategorie-, Produkt- oder CMS-Seite ist. Magento stuft die Produktdetailseite als am wichtigsten und CMS-Seiten als am unwichtigsten ein. Diese Verteilung wird sicherlich bei Ihnen ähnlich sein. Denn Ihr Ziel muss darin bestehen, dass eine Produktseite in Google gute Platzierungen erhält, da diese die Vorstufe zum Kauf darstellt. Eine CMS-Seite hingegen, beispielsweise das Impressum, muss nicht zwangsläufig eine gute Platzierung aufweisen. Wenn Sie darüber gefunden werden sollten, kann nicht direkt ein Einkauf eingeleitet werden. Der einzige Unterschied in der Konfiguration der Produkt-, Kategorie- und CMS-Seiten besteht in der Möglichkeit, bei den Produktseiten noch Bilder hinzuzufügen. Wenn diese Option aktiviert ist, werden neben dem Produktnamen und der URL noch das Hauptbild, alternativ alle Bilder, in der Sitemap aufgeführt. Da zu viele Informationen in diesem Kontext nicht schaden, belassen Sie diese Option bitte bei dem Wert Alle.

Scrollen Sie nun ein wenig nach unten, um zu den Generationseinstellungen zu gelangen. Aktivieren Sie bitte an dieser Stelle die Generierung der Sitemap, und geben Sie, ähnlich wie bei dem Versand der Warn-E-Mails, eine Startzeit bestehend aus der Stunde, Minute und Sekunde an. Neben der Startzeit können Sie die Frequenz definieren, d. h., wie oft die Sitemap generiert werden soll. Ein sehr guter Wert ist an dieser Stelle Täglich. Dadurch können Sie Google oder alternativen Suchmaschinen täglich den aktuellen Stand in Sachen URLs übermitteln.

Zudem haben Sie wiederum die Möglichkeit, eine E-Mail-Adresse zu hinterlegen, an die eine E-Mail gesendet wird, wenn Fehler bei der Generierung der XML Sitemap auftreten sollten. Neben dem Empfänger können Sie zudem einen Absender dieser Fehler-E-Mail definieren sowie eine E-Mail-Vorlage auswählen. Wie Sie an dieser Stelle sehen, haben Sie bei der Konfiguration der zu versendenden E-Mails immer die identischen Optionen bestehend aus Empfänger, Versender und E-Mail-Vorlage.

Abschließend gibt es in Bezug auf die Konfiguration der Sitemap noch zwei weitere Abschnitte namens Sitemap Datei-Limits und Suchmaschinen-Einstellungen. Im Abschnitt Sitemap Datei-Limits können Sie festlegen, wie viele URLs in einer einzigen Sitemap-Datei enthalten sein können und wie groß die maximale Dateigröße sein darf. Diese Limits spielen primär für die Generierung der Sitemap XML-Datei eine wichtige Rolle. Wenn Sie mehrere Hundert Millionen URLs in Magento hätten und diese alle in eine Datei müssten, gäbe es sicherlich bei der Generierung dieser dann sehr großen Datei ein Problem. Aus diesem Grund lässt sich ein Limit einstellen. Im Zweifelsfall würden dann mehrere XML-Dateien erstellt werden. Im Abschnitt Suchmaschinen-Einstellungen ist die letzte Option Aktiviere Vorlage an Robots.txt ist ebenso recht wichtig, weshalb ich Sie an dieser Stelle bitte, diese zu aktivieren. Dadurch wird die URL Ihrer Sitemap automatisch zur robots.txt-Datei hinzugefügt, die von den Suchmaschinen durchsucht wird. Dadurch können Sie den Suchmaschinen direkt die URL zur XML Sitemap Ihres Online-Shops mitteilen.

Als Ergebnis erhalten Sie, nachdem Sie die Sitemap konfiguriert haben, eine XML-Datei, die wie in Abbildung 4.32 aussieht.

RSS-Feeds

Nachdem ich Ihnen die Möglichkeiten der XML-Sitemap-Funktion gezeigt habe, bleibe ich thematisch bei XML-Dateien. Klicken Sie bitte auf den nächsten Konfigurationsbereich namens RSS-Feeds, den Sie im linken Navigationsmenü direkt unter dem Punkt XML Sitemap finden. Bei RSS-Feeds handelt es sich um automatisch erzeugte XML-Dateien, die in der Regel dynamische Inhalte enthalten. RSS-Feeds spielen speziell bei Blogs eine große Rolle. Sobald ein neuer Beitrag veröffentlicht wird, wird dieser zudem in den RSS-Feeds hinzugefügt. Der RSS-Feed selbst lässt sich mithilfe von speziellen Programmen, unter Windows beispielsweise Nextgen Reader, abonnieren. Das Programm informiert Sie direkt über neue Einträge, und Sie sehen auf einen Blick den neu erstellen Beitrag. Diese Verhaltensweise ist recht praktisch, wenn Sie täglich auf vielen verschiedenen Nachrichtenseiten bzw. Blogs aktiv sein möchten, diese aus zeitlichen Gründen aber nicht direkt aufrufen. Sie fügen nur die jeweiligen RSS-Feeds Ihrem RSS-Reader-Programm hinzu und erhalten in diesem Programm zentral alle Informationen aus den verschiedensten Quellen.

Magento ist ebenfalls in der Lage, solche RSS-Feeds zu generieren. Zu Demonstrationszwecken bitte ich Sie daher, an dieser Stelle alle Optionen in dem Konfigurationsbereich RSS-Feeds zu aktivieren und die Konfiguration zu speichern. Dadurch erscheint im Frontend automatisch ein Link zu der neu erstellten Ansicht RSS-Feeds, die Sie in Abbildung 4.33 sehen.

Abbildung 4.33    Im Frontend haben Ihre Besucher und Kunden die Möglichkeit, alle verfügbaren RSS-Feeds einzusehen.

In dieser Ansicht werden alle aktivierten RSS-Feeds aufgelistet, beispielsweise Neue Produkte. Klicken Sie auf Feed abrufen, gelangen Sie direkt zur XML-Datei, die an dieser Stelle jedoch noch etwas leer und einsam sein dürfte. Im Verlauf des Buches, wenn Sie Produkte und Rabatte anlegen, werden Sie diese Funktionsweise besser nachvollziehen können, da dann Daten geladen und dargestellt werden. In der Praxis findet diese Funktion relativ wenig Zuspruch. Das liegt weniger an der technischen Umsetzung von Magento, sondern viel mehr an der Sinnhaftigkeit. Warum sollten Kunden einen RSS-Feed abonnieren, der sie über neue Produkte oder Kategorien informiert? Bei Nachrichtenseiten und Blogs ist es wichtig, immer aktuelle Inhalte zu erhalten, ohne gezielt die jeweiligen Seiten im Browser abzuklappern. Im E-Commerce sieht dies meiner Meinung nach etwas anders aus. Denn hier gehe ich nicht jeden Tag gezielt auf einen Shop und schaue mir die neuen Produkte an. Im E-Commerce bin ich als Kunde tendenziell »bedarfgetrieben«, wodurch ich nicht täglichen Input in Form von RSS-Feeds benötige. Aber auch dies ist wieder eine pauschale Aussage. Gegebenenfalls ergibt es in Ihrem Geschäftsmodell ja tatsächlich Sinn und Ihre Besucher und Kunden fordern eine entsprechende Funktionalität. In diesem Fall ist Magento gerüstet und bietet Ihnen die Bereitstellung von RSS-Feeds. Falls nicht, können Sie diese Funktion im Backend jedoch wieder getrost deaktivieren.

4.4.3    Kunden

Neben der allgemeinen Magento-Systemkonfiguration sowie den geballten Konfigurationsoptionen in Bezug auf den Produktkatalog bzw. das Warensortiment steht mit der Kundenkonfiguration der nächste größere Konfigurationsbereich zur Verfügung. Newsletter

Magento bietet sowohl die Möglichkeit, Newsletter-Empfänger zu sammeln und zu speichern, als auch Newsletter zu versenden. Klicken Sie bitte im linken Navigationsmenü auf den Punkt Newsletter, der sich direkt unter dem Hauptpunkt Kunden befindet.

Der Konfigurationspunkt Newsletter mit seinem Konfigurationsbereich Abonnement-Optionen bezieht sich an dieser Stelle rein auf die Newsletter-Anmeldung durch Kunden, nicht aber auf den Versand der Newsletter. Der Versand, das werde ich Ihnen aber in Abschnitt 10.1 noch aufzeigen, sollte grundsätzlich über einen externen Dienstleister erfolgen, da Magento im Standard nur sehr rudimentäre Funktionen in Bezug auf den Versand von Newslettern bietet.

Versenden Sie Newsletter über Tools wie Mailchimp, Cleverreach & Co.

Magento hat Schwächen beim Versand von Newslettern, wodurch E-Mails nach einer gewissen Zeit bei den Empfängern als Spam gekennzeichnet werden. Darüber hinaus sind die Gestaltung und das nachträgliche Reporting einer Mailing-Kampagne praktisch nicht möglich. Nutzen Sie aus diesen Gründen daher spezialisierte Dienstleister wie beispielsweise Mailchimp oder Cleverreach. Diese verfügen über Integrationen für Magento und lassen sich somit auf einfache Art und Weise integrieren.

Die erste Konfigurationsoption namens Vorlage für Erfolgs-E-Mail erlaubt Ihnen die Auswahl eines E-Mail-Templates, das nach der erfolgreichen Anmeldung am Newsletter versendet wird. Im ersten Schritt meldet sich Ihr Besucher innerhalb des Frontends nämlich für Ihren Newsletter an. Als Bestätigung, dass die Anmeldung erfolgreich war, versendet Magento anschließend eine E-Mail an den besagten Besucher. Den Inhalt bzw. die Vorlage für diese Auswahl können Sie daher an dieser Stelle definieren. Neben dem eigentlichen Inhalt können Sie zudem einen Absender definieren. Interessanterweise können Sie dies aber nicht über die nächste Konfigurationsoption steuern, sondern müssen ein wenig nach unten zum Punkt Absender für Erfolgs-E-Mail scrollen. Vermutlich ist Magento an dieser Stelle selbst ein wenig mit der Reihenfolge der Konfigurationsoptionen durcheinandergekommen.

Neben einer E-Mail-Bestätigung für die erfolgreiche Anmeldung am Newsletter können Sie im nächsten Schritt die Vorlage und den Absender für die Abmeldung definieren. Rein rechtlich müssen Sie Ihren Kunden und Besuchern die Möglichkeit bieten, sich schnell und einfach von Ihrem Newsletter abzumelden. Erfolgt eine Abmeldung, versendet Magento anschließend eine Bestätigung, sodass Ihr Besucher bzw. Kunde direkt eine Rückmeldung erhält. Die Konfiguration der Abmeldungsbestätigung können Sie in den Punkten Absender für Abbestellungs-E-Mail bzw. Vorlage für Abbestellungs-E-Mail vornehmen. Grundsätzlich müssen Sie meiner Meinung nach an diesen Stellen erst einmal nicht eingreifen und keine Anpassungen vornehmen. Jedoch sollten Sie definitiv den Inhalt der beiden angesprochenen E-Mail-Vorlagen prüfen und gegebenenfalls erweitern bzw. modifizieren. Von Haus aus ist der in den Magento-Transaktions-E-Mails verwendete Text in Ordnung, und eine solche E-Mail kann problemlos versendet werden. Eine Anpassung an Ihr Unternehmen ergibt jedoch inhaltlich wie optisch in der Regel Sinn. Immerhin möchten Sie in den E-Mails eine persönliche und individuelle Note setzen.

Die nächsten beiden Konfigurationsoptionen sind wieder etwas spannender, da Sie nicht nur die Vorlage und den Absender einer E-Mail definieren, sondern einen Workflow. Wenn Sie etwas nach unten scrollen, werden Sie die beiden Konfigurationsoptionen namens Vorlage für Bestätigung-E-Mail und Muss bestätigt werden vorfinden. Die Letztere der beiden Optionen definiert, ob Ihr Besucher bzw. Kunde nach der Anmeldung am Newsletter diese Anmeldung bestätigen muss. Dieses Double-Opt-in-Verfahren ist in Deutschland gesetzlich vorgeschrieben. In der Praxis bedeutet dies, dass nach einer Anmeldung am Newsletter an diese E-Mail-Adresse eine E-Mail gesendet wird, die einen Bestätigungslink enthält. Erst wenn man auf diesen Bestätigungslink innerhalb der E-Mail klickt, wird man für den Newsletter freigeschaltet. Bei dem Konfigurationsabschnitt Kunden-Konfiguration im linken Navigationsmenü direkt unter dem Navigationspunkt Newsletter handelt es sich um das Herzstück der Kundenkonfiguration. Innerhalb dieser Option können Sie nämlich definieren, in welchem Zeitraum ein Kunde als online eingestuft wird. Der Standardwert hierfür beträgt 15 Minuten, wobei der Standardwert immer dann greift, wenn diese Konfigurationsoption leergelassen wird. Sie werden sich nun sicherlich fragen, was diese Option im Detail bewirkt. Sie haben im Magento-Backend im Punkt Kunden • Jetzt online die Möglichkeit, alle Kunden anzeigen zu lassen, die aktuell online sind. Nun kommt es aber vor, dass ein Kunde oder Besucher für einige Minuten keine Aktion ausführt. Vielleicht ist der Kunde, nachdem er auf einer Produktdetailseite war, kurz auf die Toilette verschwunden und denkt dort über den Kauf nach. Ab einem gewissen Punkt muss Magento diesen Besucher bzw. Kunden jedoch als »offline« kennzeichnen, und dieses Zeitintervall zwischen der letzten Aktion und der zu diesem Zeitpunkt ermittelten Zeit wird in dieser Option definiert. Im Standard würde ein Besucher bzw. Kunde nach einer Inaktivität von 15 Minuten als offline gekennzeichnet werden, wodurch er aus der Liste unter dem Punkt Kunden • Jetzt online herausfällt. Da ich persönlich recht wenig Magento-Nutzer kenne, die überhaupt einen Blick in die Liste der aktiven Gäste bzw. Kunden werfen, finde ich diese Konfigurationsoption bzw. die Funktionalität als solche eher überflüssig, weswegen Sie zum einen nichts anpassen müssen und zum anderen zum nächsten Punkt springen können.

Sofern Sie auf Basis einer Magento-Instanz mehrere Stores betreiben und diese Stores unterschiedliche übergeordnete Websites besitzen, ist die nachfolgende Option für Sie relevant. Kundenkonten teilen definiert, ob ein Kundenkonto pro Website limitiert ist oder global genutzt werden kann. Angenommen, Sie nutzen die Magento-Multistore-Funktionalität und verkaufen auf Basis einer Magento-Installation Apple-Produkte und Frauenhandtaschen. Aufgrund dieser komplett unterschiedlichen Produktarten legen Sie zwei Websites an, die jeweils einen Store und einen Store View besitzen. Wenn Sie nun das Kundenkonto pro Website limitieren, müsste ein Kunde, der bei Ihnen im ersten Shop ein iPhone gekauft hat, sich im zweiten Shop, wenn er für seine Freundin eine Handtasche kaufen möchte, erneut registrieren. Der Kunde müsste daher zwei Kunden-Accounts anlegen, die an sich vollkommen autark funktionieren und keine Überschneidungen aufweisen. Würden Sie jedoch die Limitierung pro Website aufheben und die Option global wählen, könnte ein Kunde das Benutzerkonto, das er im ersten Shop mit den Apple-Produkten angelegt hat, zudem im zweiten Shop, der Handtaschen verkauft, nutzen. Dem Kunden wird also ein Registrierungsprozess erspart, und er verfügt über ein übergreifendes Benutzerkonto. Sie sehen also, bei dieser Option gibt es kein richtig oder falsch bzw. gut oder schlecht. Es kommt in erster Linie auf die Rahmenbedingungen in Ihrem Online-Shop an. Wenn Sie mehrere Websites nutzen, die Produkte aber recht ähnlich sind, kann ein globales Konto sinnvoll sein. Wenn Sie hingegen mit völlig autarken Online-Shops arbeiten, diese nichts miteinander zu tun haben und für Ihre Besucher bzw. Kunden eine Relation nicht ersichtlich ist, ergibt ein globales Kundenkonto wenig Sinn.

Magento bietet Ihnen an dieser Stelle die Möglichkeit, Kunden automatisch in Kundengruppen einzuordnen. Im ersten Schritt wird ein Kunde nach einer erfolgreichen Registrierung immer in die Standardkundengruppe eingeordnet. Diese Standardkundengruppe können Sie an dieser Stelle über die Option Standardgruppe festlegen. Ohne jegliche Anpassung landet der Kunde in der Kundengruppe General. Dies ist im ersten Schritt auch in Ordnung, Anpassungen müssen Sie an dieser Stelle nicht vornehmen. Aktivieren Sie jedoch die automatische Zuordnung zur Kundengruppe, landet ein Kunde nicht immer automatisch in der Standardkundengruppe General, sondern wird basierend auf den Steuereinstellungen in eine alternative Kundengruppe verschoben. Diese Verschiebung basiert letztendlich auf der Prüfung der Umsatzsteueridentifikationsnummer. Registriert sich ein Kunde, kann er eine Umsatzsteueridentifikationsnummer angeben, die direkt mit einem Webservice geprüft wird. Anhand dieser Prüfung wird Magento zurückgemeldet, ob diese Nummer valide ist und, falls ja, ob es sich um ein europäisches bzw. deutsches Unternehmen handelt. Diese Rückmeldung kann nun an dieser Stelle dazu verwendet werden, diesen Kunden direkt in eine entsprechende Kundengruppe zu verschieben. Aus diesem Grund haben Sie innerhalb dieses Konfigurationsabschnittes die folgenden Optionen:

  • Standardgruppe
  • Gruppe für gültige MwSt.-ID – Inländisch
  • Gruppe für gültige MwSt.-ID – Innerhalb der Union
  • Gruppe für ungültige MwSt.-ID
  • Validierungs-Fehlergruppe

Sie können also fünf Kundengruppen definieren und basierend auf der Prüfung der Umsatzsteueridentifikationsnummer ordnet Magento automatisch den Kunden der richtigen Kundengruppe zu. Interessant ist dieser Mechanismus, da sich die Steuerkalkulation unter anderem anhand der Kundengruppe ergibt. Dementsprechend ist es notwendig, Kunden entsprechend zu kategorisieren, um die korrekte Steuersumme anzeigen und errechnen zu können.

Validierungs-Fehlergruppe

Die Validierungs-Fehlergruppe greift immer dann, wenn keine Rückmeldung oder eine fehlerhafte Rückmeldung bei der Validierung der Umsatzsteueridentifikationsnummer erfolgt. Magento verschiebt diesen Kunden dann nicht in die Standardgruppe, sondern in die Validierungs-Fehlergruppe. Anhand der dort enthaltenen Kunden können Sie zudem recht einfach prüfen, wie viele fehlerhafte Validierungen vorliegen, und dann gezielt auf diese Kunden zugehen.

Speziell wenn Sie international tätig sind und sowohl End- als auch Geschäftskunden beliefern, werden Sie diese Option aller Wahrscheinlichkeit nach benötigen. Pro Auswahl können Sie nun eine entsprechende Kundengruppe wählen. Da im Standard nicht allzu viele Kundengruppen vorhanden sind, müssen Sie in der Praxis zuerst die Kundengruppen anlegen. Wie dies im Detail erfolgt, erfahren Sie im weiteren Verlauf dieses Buches. Kapitel 9, »Kundenkonto und Kundenverwaltung«, widmet sich ausschließlich dem Umgang mit Kunden sowie Kundengruppen.

Neben der Auswahl der jeweiligen Kundengruppen haben Sie an dieser Stelle zudem weitere Einstellungsmöglichkeiten. Mit der Option Steuerberechnung basierend auf können Sie definieren, ob die Steuern anhand der Rechnungs- oder Versandadresse errechnet werden sollen. Das spielt dann eine Rolle, wenn Sie beispielsweise eine Bestellung erhalten, bei der die Rechnung nach Deutschland gesendet, die Ware jedoch nach Frankreich geliefert wird. Hier müssen Sie definieren, ob die Steuern basierend auf der Rechnungs- oder der Versandadresse berechnet werden sollen. Etwas weiter unten im Punkt Bei jeder Transaktion bestätigen geht es um die Häufigkeit der Umsatzsteueridentifikationsnummer-Prüfung. Sie können diese entweder initial bei der Registrierung oder tatsächlich bei jeder vom Kunden durchgeführten Transaktion, sprich Bestellung, validieren. In der Regel sollte sich in diesem Punkt bei Ihren Kunden nicht häufig etwas ändern, weshalb eine Prüfung bei jeder Transaktion meiner Meinung nach zu viel des Guten ist. Interessant wird es letztendlich nur in den Fällen, in denen Unternehmen die Geschäftstätigkeit einstellen, Ihnen das aber nicht mitteilen. Magento würde den Kunden dann immer noch als Unternehmen behandeln, auch wenn der Kunde zu diesem Zeitpunkt kein Unternehmen mehr betreiben würde. Prüfen Sie die Umsatzsteueridentifikationsnummer bei jeder Transaktion, würde diese neue Situation umgehend auffallen und der Kunde würde automatisch einer anderen Kundengruppe zugeordnet werden. Bei der nächsten Option, die in der deutschen Übersetzung leider etwas irreführend ist, können Sie die automatische Kundengruppenzuweisung bei Registrierungen deaktivieren. Hinterlegen Sie hierfür bei der Option Standardwert für das Deaktivieren der automatischen Gruppen-Änderungen auf Grundlage der MwSt.-ID den Wert nein, dadurch wird der Kunde bei einer Registrierung nicht automatisch einer Kundengruppe zugeordnet. Ob die Umsatzsteueridentifikationsnummer übrigens im Benutzerkonto angezeigt wird, können Sie mithilfe der nun folgenden Option namens Zeige MwSt.-Nummer im Storefront festlegen. Falls Sie die Option aktivieren, wird im Benutzerkonto, wie in Abbildung 4.37 zu sehen ist, die Identifikationsnummer bei den angelegten Adressen angezeigt.

Abbildung 4.38    Im Umgang mit den Passwörtern der Kunden bietet Magento eine Vielzahl von Möglichkeiten und Konfigurationsoptionen.

Wenn ein Kunde sein Passwort vergisst, kann er dieses über das Frontend, genauer gesagt bei der Login-Maske anfordern. Die Anforderung eines Passworts kann in der Theorie jedoch auch mit einer bösartigen Absicht von einer anderen Person als dem Kontoinhaber erfolgen. Dementsprechend ist die Funktion Passwort vergessen mit gewissen Rahmenparametern zu schützen. So können Sie mit der Option Max Number of Password Reset Requests einstellen, wie oft pro Stunde ein Passwort angefordert werden kann.

Standardmäßig ist der Wert 5 hinterlegt, d. h., Sie können pro Stunde fünfmal ein Passwort für einen bestimmten Account anfordern. Doch wie überprüft Magento, wie oft welche Person ein Passwort für einen bestimmten Account anfordert? Die darüber liegende Konfigurationsoption namens Password Reset Protection Type definiert die Zählweise der Versuche. Im Standard ist die Prüfung per IP-Adresse und E-Mail hinterlegt. Magento würde im Fall eines Passwort-Resets sowohl die IP-Adresse des Besuchers prüfen, der diese Aktion anstößt, als auch die E-Mail-Adresse, die beim Kunden-Account, für den das Passwort angefordert werden soll, hinterlegt wurde.

Alternativ kann die Prüfung auch nur anhand der IP-Adresse oder nur anhand der E‐Mail erfolgen. Im schlimmsten Fall wählen Sie an dieser Stelle die Option Keine, d. h., es gibt de facto keine Limitierung. In der Regel können Sie die vorausgewählte Option beibehalten, denn diese ist die sicherste. Eine reine Prüfung auf Basis der IP-Adresse würde ich Ihnen nicht empfehlen, denn gerade in größeren Netzwerken, beispielsweise innerhalb eines Unternehmens, haben alle Nutzer nach außen hin dieselbe IP-Adresse. Wenn ein Nutzer dieses Netzwerks innerhalb einer Stunde fünfmal sein Passwort anfordern würde, könnte ein anderer Nutzer aus diesem Netzwerk kein Passwort für seinen Benutzer-Account anfordern, da aus diesem Netzwerk bereits fünf Anfragen erfolgten. Dementsprechend ist die Standardoption, die letztendlich nicht nur die IP-Adresse, sondern auch die E-Mail-Adresse berücksichtigt, wesentlich sinnvoller. Neben der Limitierung pro Stunde können Sie zudem die Abstände gemessen in Minuten zwischen einem Passwort-Reset definieren, das ist mithilfe der nächsten Option möglich. Von Haus aus ist in dieser Option namens Min Time Between Password Reset Requests der Wert 10 hinterlegt, d. h., nach der Anforderung eines Passworts muss man 10 Minuten warten, um erneut ein Passwort anfordern zu können. Sie können jedoch einen beliebigen Wert hinterlegen und mit dem Wert 0 diese Sicherheitsfunktion sogar gänzlich deaktivieren. Belassen Sie ruhig den Standardwert, denn eigentlich müssen Sie an dieser Einstellung keine Anpassung vornehmen.

Wenn ein neues Passwort angefordert wird, gibt es, wie könnte es in Magento auch anders sein, wieder E-Mails, die versendet werden. Daher drehen sich die nächsten Konfigurationseinstellungen um die Definition der E-Mail-Templates. Seien Sie an dieser Stelle aufmerksam, da die deutsche Übersetzung stellenweise etwas irreführend ist. Die Option Vorlage für vergessene E-Mail dreht sich nämlich nicht, wie man aufgrund des Namens vermuten könnte, um eine vergessene E-Mail-Adresse. Vielmehr wird diese E-Mail versendet, wenn der Kunde initial ein neues Passwort anfordert. Daraufhin erhält der Nutzer zuerst per E-Mail einen Passwort-Reset-Link. Genau diese E-Mail versendet diese Informationen und erlaubt es dem Kunden, ein neues Passwort zu setzen. Zusätzlich können Sie eine E-Mail-Vorlage definieren, die bei der Erinnerung eines Nutzers bezüglich seines Passwort-Resets versendet wird. Die Option hierfür lautet Vorlage für Erinnerungs-E-Mail und wird durch eine weitere Vorlage namens Passwortvorlage zurücksetzen ergänzt. Neben der eigentlichen Auswahl der E-Mail-Vorlagen können Sie etwas weiter unten den E-Mail-Absender definieren, wobei hier im Standard der Kundensupport ausgewählt ist. Bei Bedarf können Sie diese Option ändern, je nachdem welche Kontaktdaten Sie bei der E-Mail-Konfiguration im Bereich Kunden-Konfiguration hinterlegt haben. Da Magento seit geraumer Zeit bei einem Passwort-Reset nur einen Reset-Link und nicht das neue Passwort im Klartext versendet, haben Sie zudem die Möglichkeit, die Lebenszeit des Passwort-Reset-Links zu setzen. Der hinterlegte Wert entspricht der Einheit Stunden, d. h., im Standard ist der Passwort-Reset-Link 2 Stunden gültig. Klickt der Nutzer später auf diesen per E-Mail zugesendeten Link, erhält er eine Fehlermeldung und muss das Passwort erneut anfordern.

Die nächsten Optionen befassen sich mit dem grundsätzlichen Aufbau eines Passworts und dem Verhalten beim Login. Mit der Option Number of Required Character Classes definieren Sie die Komplexität des Passworts. Die Komplexität ergibt sich aus der Notwendigkeit, Kleinbuchstaben, Großbuchstaben, Zahlen sowie Sonderzeichen nutzen zu müssen. Ergänzend hierzu kann zudem die minimale Passwortlänge festlegt werden, die Sie über die Option Minimum Password Length definieren. Für den Fall, dass sich ein Kunde mehrmals fehlerhaft anmeldet, kann Magento das Kundenkonto sperren. Im Standard passiert dies nach 10 fehlerhaften Anmeldeversuchen. Die Anzahl lässt sich jedoch mithilfe der Option Maximale Anmeldefehler bis zur Sperrung des Kontos beliebig definieren. Gekoppelt daran ist die Option Sperrzeit (Minuten), die definiert, nach wie vielen Minuten das gesperrte Benutzerkonto wieder aktiv ist. Abgesehen von den Inhalten der Transaktions-E-Mails, d. h. der immer möglichen Individualisierung der Optik und Texte, müssen Sie bei den soeben erläuterten Optionen normalerweise, außer Sie haben eine sehr spezielle Anforderung, keine Änderungen vornehmen und können sich ganz auf den Magento-Standard verlassen.

Wie Sie in Kapitel 10, »Marketingmaßnahmen planen und durchführen«, noch erfahren werden, bietet Magento verschiedenste verkaufsfördernde Maßnahmen. Mit der Codelänge können Sie die Anzahl der Buchstaben bzw. Zahlen definieren und somit direkt die Länge der Gutscheincodes vorgeben. Denken Sie daran, je kürzer ein Code ist, umso besser kann er gemerkt bzw. eingetippt werden. Dementsprechend sollten Sie auf zu lange Gutscheincodes verzichten, der Standardwert von 12 ist meiner Meinung nach eine ganz gute und passende Einstellung. Neben der Länge ist zudem das Code-Format eine sehr wichtige Option, denn Sie haben hier die Wahl zwischen Alphanumerisch, Alphabetisch sowie Numerisch. Dadurch können Sie sehr gut steuern, ob Sie nur Zahlen, Buchstaben oder eine Mischung von beidem innerhalb der generierten Codes wünschen. Zudem haben Sie die Möglichkeit, ein Präfix sowie Suffix zu definieren. Hinterlegen Sie beispielsweise als Präfix das Wort »aktion«, als Suffix das Wort »code« und haben Sie einen alphanumerischen Code mit einer Zeichenlänge von 12, könnte ein Gutscheincode wie folgt aussehen: aktion-k4b6iy1aqe32-code. Hinterlegen Sie bei der Option Bindestrich alle x Zeichen die Zahl 3, würde der oben aufgeführte beispielhafte Gutscheincode plötzlich wie folgt aussehen: aktion-k4b-6iy-1aq-e32-code. Oftmals hilft der automatisiert eingefügte Bindestrich tatsächlich, die Lesbarkeit des Gutscheincodes zu erhöhen, speziell dann, wenn Sie relativ lange Gutscheincodes verwenden.

Bestehender Warenkorb

Der letzte Konfigurationsbereich innerhalb des Oberpunktes Kunden lautet auf den Namen bestehender Warenkorb und ermöglicht Ihnen, Einfluss auf die Verhaltensweise des Warenkorbs zu nehmen. Öffnen Sie daher, nachdem Sie sich gerade noch durch den Aufbau der Gutscheincodes geklickt haben, diesen nächsten und letzten Konfigurationsbereich.

Magento bietet Ihnen an dieser Stelle die Möglichkeit, die Persistenz zu aktivieren, was Sie auch tun sollten. Wenn Sie diese Option aktivieren, erweitert sich der Funktionsumfang des in Magento vorhandenen Warenkorbs ein wenig. Was im Deutschen mit bestehender Warenkorb übersetzt wurde, bedeutet in der englischen Originalausgabe persistent cart. Die persistent-cart-Option soll dafür sorgen, Warenkorbabbrüche zu minimieren, da die im Warenkorb befindlichen Artikel wesentlich länger an den Nutzer geknüpft werden. Das heißt, ein Benutzer behält die Artikel auch im Warenkorb, wenn er sich von einem anderen Endgerät am System anmeldet. So können Sie beispielsweise mittels Ihres iPhones einen Artikel zum Warenkorb hinzufügen, später am Tag mit einem Tablet den Warenkorb vervollständigen und am nächsten Morgen mit Ihrem Desktop-Computer diesen Warenkorb kaufen. Voraussetzung hierfür sind letztendlich ein Benutzerkonto und der angemeldete Zustand. Würden Sie die Option Persistenz aktivieren deaktiviert lassen, wäre die gemeinsame Nutzung des Warenkorbs über verschiedenste Endgeräte hinweg nicht möglich. Zudem laufen Sie bei einer Aktivierung der Persistenz nicht Gefahr, dass der Warenkorb plötzlich leer ist, wenn die Sessions bzw. Cookies in Ihrem Browser gelöscht werden, da diese Informationen auf eine andere Art und Weise gespeichert bzw. hinterlegt werden.

Nachdem Sie die Persistenz aktiviert haben, Sie sehen dies in Abbildung 4.42, haben Sie zudem weitere Konfigurationsmöglichkeiten.

Dies ist für Sie als Shop-Betreiber praktisch, da dadurch der Benutzer direkt identifiziert werden kann. Für den Nutzer entsteht zudem ein Bequemlichkeitsvorteil, da er sich nicht manuell am System anmelden muss. Abschließend möchte ich an dieser Stelle erwähnen, dass die Aktivierung der Persistenz sowie der Erhalt des Warenkorbs meiner Meinung nach zwei wichtige Funktionen sind, die genutzt werden sollten. Letztendlich hängt es immer ein wenig von Ihren Produkten und der Branche ab, oftmals werden Kaufentscheidungen aber nicht sofort getroffen, sondern der Warenkorb dient als eine Art »Merkliste«. Dementsprechend ist es besonders ärgerlich, wenn man mühevoll Produkte auf diese Merkliste klickt und diese dann nicht mehr zur Verfügung steht und man von Neuem beginnen muss. Dementsprechend rate ich Ihnen zur Aktivierung der besagten Optionen, da sowohl für Sie als Shop-Betreiber als auch für Ihre Kunden und Besucher Vorteile entstehen.

Speziell in komplexeren Projekten ist Magento in der Regel nicht für die Dokumentengenerierung zuständig. Magento unterstützt einen Checkout mit mehreren Adressen. Das bedeutet, Sie können als Kunde einen Warenkorb befüllen, die Produkte aber an unterschiedliche Adressen liefern lassen. Mehrere Sendungen, sprich Pakete, bedeuten auch immer zusätzliche Versandkosten, höhere Prozesskosten und, wie in diesem Fall auch, eine Auswirkung auf den Mindestbestellwert. Denn diesen setzen Sie gegebenenfalls, da eine Sendung einen gewissen Wert haben muss, damit Sie am Ende des Tages einen Profit erwirtschaften. Zurück zur aktuellen Konfigurationsansicht, denn diese beschäftigt sich genau mit dieser letzten Frage. Wenn Sie die Option Jede Adresse im Multi-Adressen-Checkout einzeln bestätigen auf Ja setzen, wird der Mindestbestellwert bei jeder Adresse geprüft. Belassen Sie den Wert auf Nein, dann wird der Mindestbestellwert nur für den gesamten Warenkorbwert geprüft. Abschließend können Sie zudem wieder eine Beschreibung und eine Fehlermeldung definieren, diese haben Sie etwas weiter oben bereits kennengelernt, und es bedarf an dieser Stelle daher keiner gesonderten Erklärung.

Gast eine unterschiedliche Vorlage auswählen, die den Inhalt der E-Mail bestimmt. Wie Sie den eigentlichen Inhalt der Vorlage editieren, werden Sie übrigens noch im Verlauf des Buches kennenlernen. Steuer

Die Steuerkonfiguration in Magento ist an und für sich ein komplexes und erklärungsbedürftiges Thema. Aus diesem Grund erfahren Sie in Kapitel 6 im Detail, wie Sie bei der Konfiguration von Steuersätzen und Steuerregeln vorgehen müssen. Hierfür sind in Magento zudem verschiedene Konfigurationsbereiche notwendig, der jetzt folgende Bereich Steuer deckt nur einen kleinen Teil der gesamten Steuerkonfiguration ab. Im ersten Konfigurationsabschnitt können Sie die Steuerklasse für den Versand, Artikel und Kunden hinterlegen. Auf das Thema Steuerklassen werde ich in Kapitel 6, »Steuerregeln und Währungen«, im Detail eingehen. An dieser Stelle müssen Sie nur wissen, dass Sie in Magento verschiedene Steuerklassen anlegen können. Die Steuerklassen können beliebige Namen wie Versand, Artikel oder Kunden tragen. An dieser Stelle der Konfiguration können Sie nun die von Ihnen definierten Steuerklassen dem Versand, den Produkten und den Kunden zuweisen. Letztendlich handelt es sich hierbei um eine initiale Konfigurationseinstellung, an die Sie nie mehr Hand anlegen müssen. Überfliegen Sie an dieser Stelle diesen Punkt, und scrollen Sie etwas weiter nach unten.

Die Berechnung, der nächste Konfigurationsabschnitt, ermöglicht Ihnen, Einfluss auf die Berechnung der Mehrwertsteuer zu nehmen. Im Feld Steuerberechnungsmethode basiert auf haben Sie insgesamt drei Optionen, aus denen Sie wählen können. Wenn Sie sich für Einzelpreis entscheiden, errechnet Magento die Mehrwertsteuer für jeden einzelnen Artikel im Warenkorb. Stellen Sie sich dabei einen klassischen Warenkorb wie beispielsweise bei Zalando vor. Wenn Sie also 15 Artikel im Warenkorb haben, greift Magento auf den Einzelpreis aller 15 Artikel zu und errechnet dann die Mehrwertsteuer. Wenn Sie sich für die zweite Option namens Zeilensumme entscheiden, berücksichtigt Magento nicht jeden einzelnen Artikel, sondern die Zeilensumme. Haben Sie 15 Artikel im Warenkorb, darunter sind aber nur 5 unterschiedliche Produkte und Sie haben jeweils die Menge 3 hinterlegt, greift Magento auf die 5 Zeilensummen zu und errechnet auf dieser Basis die Mehrwertsteuer. Als dritte und letzte Option gibt es noch die Gesamtsumme. Hierbei berücksichtigt Magento die einzelnen Produktpreise nicht und errechnet die Mehrwertsteuer auf Basis der Warenkorbsumme. Sie fragen sich nun an dieser Stelle berechtigterweise, warum es drei unterschiedliche Berechnungsmechanismen in Magento gibt. Grundsätzlich ist in Magento die Steuerberechnung ein wenig tricky, und speziell die Version 1 von Magento hatte immer damit zu kämpfen, dass oftmals die Mehrwertsteuer zu einer Gesamtpreisverschiebung von 1 Cent geführt hat, sprich Magento hat eigentlich falsch gerechnet. Dadurch wurden Warenkorbwerte verfälscht. Das Problem rührt daher, dass Magento die Mehrwertsteuer mit vier Stellen nach dem Komma rechnet. Diese Vorgehensweise kann dazu beitragen, dass, je nach gewählter Berechnungsmethodik, die oben beschrieben wurde, die gesamte Mehrwertsteuer bzw. die Gesamtsumme des Warenkorbs um einen Cent variiert. Dieser Effekt tritt speziell dann auf, wenn sich eine Vielzahl von Produkten im Warenkorb befindet. Lassen Sie sich an dieser Stelle davon aber nicht irritieren, und belassen Sie die Einstellung wie im Standard angegeben, vermutlich wird das in Ihrem Szenario zu einer korrekten Errechnung der Steuer führen.

Neben der Berechnungsmethodik können und sollten Sie im nächsten Schritt die Basis für die Steuerberechnung festlegen. Im Punkt Steuerberechnung basierend auf haben Sie die Wahl zwischen Versandadresse, Rechnungsadresse und Herkunft. Wenn Sie die Herkunft auswählen, zählt der Steuersatz des Landes, in dem sich Ihr Online-Shop befindet. Vermutlich wird es sich hierbei um Deutschland handeln. Das führt also dazu, dass eine Bestellung aus Italien ebenso mit 19 % Mehrwertsteuer besteuert werden würde, da Sie den Steuersatz Ihres Landes verwenden wollen. Alternativ dazu können Sie das Land aus der Liefer- bzw. Rechnungsadresse wählen. Kauft ein Kunde also aus Italien ein und lässt die Produkte nach Italien liefern, würde der italienische Mehrwertsteuersatz fällig werden. Bei dieser Konfigurationsoption kommt es letztendlich auf die Rahmenparameter Ihres Geschäfts an bzw. darauf, von wo Sie die Ware versenden und geschäftlich aktiv sind.

Ob Sie die Preise im Magento-Backend netto oder brutto erfassen, definieren Sie im nächsten Punkt namens Katalogpreise. Hier können Sie angeben, ob Sie Ihre Produkte ohne Steuern bzw. mit Steuern einpflegen. Erfahrungsgemäß ist es in Magento etwas angenehmer, die Produkte inklusive Mehrwertsteuer zu hinterlegen, aber auch dies kann von Fall zu Fall unterschiedlich sein. Wenn Sie beispielsweise mit unterschiedlichen Umsatzsteuerbeträgen fakturieren, würde bei Brutto-Preisen im Backend gegebenenfalls Ihre Marge schrumpfen, denn Magento wüsste ja nur, dass der Artikel für beispielsweise 50 € inklusive Steuer verkauft werden soll. Wenn Sie diesen Artikel nach Deutschland liefern (19 %), wäre Ihre Marge höher, als wenn Sie diesen in Italien verkaufen (21 %). Hinterlegen Sie in einem solchen Fall die Preise netto, d. h. exklusive Steuer, dann würde sich hingegen der Verkaufspreis in Italien im Vergleich zu dem in Deutschland höher darstellen.

Die Steuerkonfiguration für den Versand können Sie im folgenden Punkt namens Versandkosten definieren. Geben Sie an dieser Stelle an, ob Sie die in Magento hinterlegten Versandkosten ohne oder mit Mehrwertsteuer hinterlegt haben. Hierbei handelt es sich im Prinzip um das Äquivalent zu den Katalogpreisen, nur, dass sich die Option eben auf den Versandpreis bezieht.

Einen weiteren Einfluss auf die Berechnung der Steuer hat die Konfigurationsoption Verwende Kundensteuerklasse. Im Prinzip geht es hier darum, ob die Steuerberechnung vor oder nach der Anwendung eines Rabattes durchgeführt werden soll. Lassen Sie diese Option wie im Standard, da hier keinerlei Anpassung notwendig ist. Ähnlich sieht es mit der nächsten Konfigurationsoption Wende Rabatt auf Preise an aus. Auch hier kann es in der Praxis zu Differenzen kommen, wenn der Rabatt auf den Netto- oder Brutto-Preis angewandt wird. Belassen Sie jedoch auch diese Option auf dem Standardwert, außer Sie stellen Unregelmäßigkeiten bei der Errechnung der Rabatte und damit verbunden bei den Steuern fest. Die beiden weiteren Punkte Steuer anwenden auf sowie Grenzüberschreitenden Handel aktivieren möchte ich Ihnen aufgrund ihrer Komplexität erst in Kapitel 6, »Steuerregeln und Währungen«, erläutern.

Magento bietet Ihnen über die Systemkonfiguration die Möglichkeit, bei der Ausgabe eines Preises zu wählen, ob der Preis inklusive, exklusive oder inklusive sowie exklusive Steuer dargestellt werden soll. Vermutlich wird dieser Bereich für Sie eine geringe Relevanz haben, weswegen ich ihn auch nicht ganz so ausführlich wie die anderen Bereiche behandeln möchte. Magento erlaubt die Aktivierung einer zusätzlichen »Produktsteuer«, das ist letztendlich über den Konfigurationsbereich möglich, in dem Sie sich aktuell befinden. Wenn Sie die FPT (Feste Produktsteuer) aktivieren, können Sie im nachgelagerten Schritt ein zusätzliches Produktattribut anlegen, das einer zusätzlichen Steuer entspricht. Tatsächlich gibt es, ganz international betrachtet, hierfür Anforderungen. Beispielsweise existieren neben der klassischen Mehrwertsteuer noch folgende zusätzliche Besteuerungsarten, die Sie über Magento mit dieser Funktionalität abbilden können:

  • California Recycling Fee
  • Gasoline Environmental Taxes
  • Tariffs on Cigarettes
  • Tariffs on Sugary Drinks

Dementsprechend hilft Ihnen diese Option dann weiter, wenn Sie parallel zur gesetzlichen Mehrwertsteuer eine zusätzliche Steuer auf bestimmte Produkte abbilden möchten.

Kasse

Nach dem meiner Meinung nach etwas trockenem Abschnitt mit der Steuerkonfiguration steht als Nächstes die Konfiguration des Checkouts an. Da Sie Ihren Kunden ein optimales Einkaufserlebnis bieten möchten und der Bezahlvorgang hierbei ein elementares Element ist, sollten Sie sich diesen Punkt auch im Detail anschauen. Klicken Sie hierzu zuerst im linken Navigationsmenü auf Kasse. Sie gelangen anschließend zum ersten Konfigurationsabschnitt namens Checkout-Optionen. Innerhalb der Checkout-Optionen haben Sie die Möglichkeit, den sogenannten Onepage-Checkout zu deaktivieren. Tun Sie dies, ist der klassische Einkauf in Ihrem Online-Shop nicht mehr möglich. Aus diesem Grund empfiehlt es sich auch nicht, diese Option zu deaktivieren, da Sie am Ende des Tages Umsätze generieren möchten, wofür ein aktivierter Checkout notwendig ist. Neben der kompletten Deaktivierung des Onepage-Checkouts haben Sie zudem die Möglichkeit, den Bezahlvorgang für Gäste zu aktivieren bzw. zu deaktivieren. Im Standard können Gäste, d. h. Personen ohne Benutzerkonto, in Ihrem Online-Shop Bestellungen durchführen. Dies ist auch ratsam, da Kunden heutzutage nicht zwangsläufig in jedem Online-Shop ein Konto eröffnen möchten. Im Fokus steht der schnelle und unkomplizierte Einkauf, und dieser erfolgt oftmals als Gast. Lassen Sie daher diese Option entsprechend unangerührt. Ebenso können Sie an dieser Stelle AGB aktivieren, wobei diese Option nicht direkt die Darstellung der AGB auslöst. Hierfür müssen Sie zuerst Bestellbedingungen anlegen, die anschließend in Kombination mit dieser Option zur Darstellung der AGB im Checkout-Prozess führen. Weiterführende Informationen zu den AGB und ihrer Aktivierung im Checkout-Vorgang erhalten Sie in den weiteren Kapiteln dieses Buches.

Abgesehen von der Aktivierung bzw. Einschränkung des Onepage-Checkouts, können Sie im nächsten Abschnitt das Verhalten des Warenkorbs beeinflussen. Dabei beeinflusst die Option Angebotsdauer (Tage) den Zeitraum, in dem der Warenkorb eines Nutzers gespeichert und erhalten wird. Die deutsche Übersetzung ist hier wieder ein wenig unsauber, hat die Option doch letztendlich nichts mit einem Angebot zu tun. Konkret geht es um die Lebensdauer eines Warenkorbs. Wenn ein Kunde ein Produkt zum Warenkorb hinzufügt, landet er im Standard wieder auf der Produktdetailseite. Wenn Sie den Kunden hingegen direkt zum Warenkorb weiterleiten möchten, können Sie dies tun, indem Sie die Option Nach Hinzufügen eines Artikels zum Warenkorb weiterleiten auf Ja setzen. Die zwei nächsten und letzten Punkte in diesem Abschnitt beziehen sich auf die Darstellung des Produktbildes im Warenkorb. Wie Sie später sehen werden, unterstützt Magento verschiedene Produkttypen. Hierbei gibt es auch sogenannte Rumpfprodukte, die im Warenkorb landen. Die beiden nächsten Optionen definieren, welches Produktbild in einem solchen Fall, sprich bei einem Rumpfprodukt, im Warenkorb dargestellt werden soll. Belassen Sie diese beiden Optionen ruhig bei der Standardeinstellung.

Scrollen Sie nach unten, bis Sie zur nächsten Option Einkaufswagen-Zusammenfassung anzeigen gelangen. Im Standard-Frontend von Magento sehen Sie auf der oberen Bildschirmhälfte einen Warenkorb, der Ihnen zudem anzeigt, wie viele Produkte sich aktuell im Warenkorb befinden. Werfen Sie hierzu kurz einen Blick auf Abbildung 4.49.

Abbildung 4.49    Magento zeigt dem Kunden im Frontend direkt die Anzahl der Artikel im Warenkorb an.

Die Zählweise der Artikel im Warenkorb können Sie schlussendlich mit der erwähnten Konfigurationsoption beeinflussen. Magento unterscheidet zwischen der Anzahl der Artikel und der Artikelmenge. Wenn Sie einen Artikel mit der Menge 4 im Warenkorb haben, würde bei der ersten Option die Zahl 1 ausgegeben werden. Bei der Option 2 würde hingegen die Zahl 4 ausgegeben. Sie haben also die Wahl zwischen der Artikelmenge und der Artikelanzahl.

Etwas unspektakulärer wird es bei der Einkaufswagen-Sidebar, denn diese können Sie aktivieren bzw. deaktivieren und gleichzeitig angeben, wie viele Artikel in dieser Sidebar dargestellt werden sollen.

Während des Bezahlprozesses kann es immer zu Fehlern und Problemen kommen. Sollte dies der Fall sein, speziell bei der Bezahlung, können Sie sich als Shop-Betreiber darüber informieren lassen. Die notwendigen Konfigurationsoptionen finden Sie im Abschnitt E-Mails zu fehlgeschlagener Zahlung. Ähnlich wie bei der Konfiguration anderer E-Mails, denken Sie an die Verkaufs-E-Mails, können Sie auch an diesem Punkt wieder einen Absender, einen Empfänger und eine Vorlage für die E-Mails definieren. Darüber hinaus erlaubt Magento an dieser Stelle den Versand an weitere Empfänger, entweder als BCC oder als separate E-Mail. An dieser Stelle empfiehlt sich die Konfiguration der jeweiligen Punkte, einfach damit Sie bei Fehlern bei der Bezahlung umgehend informiert werden.

Multishipping-Einstellungen

Gehen Sie jetzt zum nächsten Konfigurationspunkt mit dem Titel Multishipping Einstellungen. Sie erreichen die Einstellungen wie gewohnt über das Navigationsmenü auf der linken Seite. Magento unterstützt neben dem klassischen Checkout-Prozess, auch Onepage-Checkout genannt, den Einkauf mit mehreren Lieferadressen. Als Kunde können Sie beispielsweise 10 Artikel im Warenkorb haben und innerhalb des Checkout-Prozesses 10 unterschiedliche Lieferadressen definieren. Funktionieren tut dies letztendlich nur dann, wenn Sie die Lieferung an mehrere Adressen aktivieren, wobei diese Option im Standard aktiviert ist. Anschließend können Ihre Kunden im Frontend über den Checkout mit mehreren Adressen Produkte bestellen. Wenn Sie sich für die Darstellung interessieren, werfen Sie einen Blick auf Abbildung 4.51, da diese einen Checkout-Prozess mit 10 Artikeln darstellt.

Abbildung 4.51    Pro Artikel kann eine separate Lieferadresse definiert werden.

Wie Sie anhand der Abbildung erkennen können, ermöglicht der Checkout mit mehreren Adressen die Definition der Lieferadresse pro Position und bietet Ihren Kunden dadurch eine sehr große Flexibilität.

Kostentreiber Versandkosten

Als Shop-Betreiber möchten und müssen Sie versuchen, die Versand- und Prozesskosten möglichst gering zu halten. Der Checkout mit mehreren Lieferadressen würde Ihnen hierbei einen Strich durch die Rechnung machen, da pro Lieferadresse ein Paket gepackt werden muss und jeweils Versandkosten bezahlt werden müssen. Überlegen Sie sich daher gut, ob Sie die Option in Ihrem Online-Shop anbieten und aktiviert lassen oder ob Sie den Versand an mehrere Lieferadressen nicht ermöglichen.

Abgesehen von der Aktivierung dieser Option, können Sie im nächsten Schritt zudem einstellen, wie viele Produkte insgesamt an verschiedene Lieferadressen gesendet werden dürfen. Hierfür müssen Sie letztendlich nur die Zahl, im Standard ist 100 hinterlegt, bei der Option Maximal erlaubte Menge für Versand an mehrere Adressen anpassen.
