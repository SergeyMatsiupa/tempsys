14.4    Interessante Backend-Optionen für Entwickler

Abschließend möchte ich Ihnen in diesem Kapitel noch interessante und nützliche Optionen und Konfigurationseinstellungen vorstellen, die sich in erster Linie an Entwickler richten. Melden Sie sich daher an diesem Punkt mit Ihren persönlichen Zugangsdaten am Magento-Backend an. Im Backend angekommen, klicken Sie bitte auf Shops • Konfiguration • Erweitert • Entwickler, um zu den Entwickleroptionen zu gelangen, die Sie zudem in Abbildung 14.24 sehen.

Abbildung 14.24    Die Entwickleroptionen innerhalb des Backends sind umfangreich und definitiv einen Blick wert.

In der ersten Option namens Workflow-Typ können Sie definieren, ob die Kompilierung der CSS-Dateien client- oder server-seitig durchgeführt werden soll. An dieser Stelle ist bei den Auswahloptionen mit »Weniger« LESS gemeint, sprich der CSS-Präprozessor. Was an dieser Stelle die bessere Option ist, lässt sich pauschal nicht beantworten, da es auf Ihr konkretes Projekt ankommt.

Die Entwickler-Client-Einschränkung haben Sie bereits kennengelernt. Diese Option spielt speziell beim Debuggen, also im nächsten Abschnitt, eine wichtige Rolle. Denn wenn Sie an dieser Stelle keine IP-Adresse hinterlegen, wird jeder Nutzer im Frontend die Debugging-Informationen sehen oder eben auch die Inline Translation verwenden können. Da Sie genau das sicherlich nicht möchten, müssen Sie bei den Einschränkungen immer Ihre aktuelle IP-Adresse hinterlegen, die Sie beispielsweise unter www.wieistmeineip.de erhalten.

Im Abschnitt Debuggen können Sie sich verschiedene Informationen ausgeben lassen, die dann im Frontend dargestellt werden. Es handelt sich hierbei um die Vorlagenpfad-Hinweise für das Frontend sowie Backend und die Block-Namen. Die Vorlagenpfad-Hinweise geben Ihnen einen Einblick, aus welchem Template welcher Bereich geladen wird. Bei den Blöcken sieht es ähnlich aus, Sie sehen im Frontend, welches Element aus welchem Block stammt. Aktivieren Sie an dieser Stelle die Vorlagenpfad-Hinweise sowie die Block-Namen, dann sieht der Warenkorb wie in Abbildung 14.25 aus.

Abbildung 14.25    Wenn Sie nicht wissen, welches Element aus welchem Template bzw. Block kommt, hilft es, die Hinweise und Block-Namen einzuschalten.

Sie sehen alle Bereiche rot umrahmt und erhalten bei jedem Bereich die Information, aus welchem Block bzw. Template das Element geladen wird. Die Templates stehen dabei immer auf der linken Seite, die Blöcke auf der rechten und haben eine blaue Schriftart. Dadurch zerstören Sie natürlich die Darstellung Ihres Frontends, und es ist stellenweise recht schwer nachzuvollziehen, auf welches Element sich ein Hinweis bezieht. Jedoch werden Sie mit etwas Übung sicherlich klarkommen, und das Feature erspart Ihnen bei der Entwicklung eines Themes bzw. Moduls definitiv viel Zeit bei der Suche.

Scrollen Sie bitte weiter zum Abschnitt Vorlageneinstellungen. Dort haben Sie die Möglichkeit, Symlinks zu aktivieren. Dabei handelt es sich letztendlich um eine alternative Methode, wie auf benötigte Ressourcen zurückgegriffen werden kann. Daneben können Sie, und das ist an dieser Stelle definitiv der wichtigere Punkt, den HTML-Code optimieren, indem Sie die Option HTML verkürzen aktivieren. Auch an dieser Stelle wurde erneut auf eine abenteuerliche Übersetzung zurückgegriffen, das Fachwort für diese Option nennt sich Minify. Wenn Sie die Option aktivieren, wird bei der Ausgabe des HTML-Codes im Frontend alles entfernt, was nicht benötigt wird. Hierzu zählen Leerzeichen, Umbrüche und Einschübe. Dadurch wird wesentlich weniger Code übertragen, und das Frontend lädt schneller.

Führen Sie ein »setup:static-content:deploy« aus

Um die Änderungen zu übernehmen, muss Magento einige Dateien neu generieren. Sie müssen daher per Kommandozeile php bin/magento setup:static-content: deploy ausführen und anschließend den Cache leeren, damit die Änderungen übernommen werden können

Sie sehen einen Ausschnitt aus einem komprimierten und zusammengefassten HTML-Code in Abbildung 14.26. Keinerlei Leerzeichen bzw. Umbrüche oder Einschübe sind mehr vorhanden, und der gesamte HTML-Code ist so stark wie möglich komprimiert und dadurch optimiert.

Abbildung 14.26    Beispielhafte Darstellung des optimierten HTML-Codes

Die Inline Translation haben Sie bereits kennengelernt, daher erwähne ich sie hier nur noch einmal aus Gründen der Übersichtlichkeit. Wenn Sie die Inline Translation aktivieren möchten, können Sie das an dieser Stelle für Backend wie Frontend tun.

Wiederum sehr interessant ist der Abschnitt JavaScript-Einstellungen. Dort haben Sie die Möglichkeit, ähnlich wie beim HTML-Code, die JavaScript-Dateien zu optimieren. Aktivieren Sie die Option JavaScript-Dateien verkürzen, werden alle nicht benötigten Leerzeichen und Umbrüche entfernt. Zudem können Sie jedoch auch JavaScript-Dateien zusammenfassen bzw. bündeln. Magento würde anschließend, wenn z. B. zehn JavaScript Dateien eingebunden sind, alle Dateien zu einer großen JavaScript-Datei zusammenfassen und nur noch diese Datei ausgeben. Dadurch können Sie die Performance ebenfalls verbessern, denn je weniger Dateien geladen werden müssen, desto schneller ist die Seite, auch wenn dadurch die eine geladene Datei eine etwas größere Dateigröße aufweist. Die restlichen Einstellungen in diesem Abschnitt betreffen vor allem die Art und Weise der Übersetzung der JavaScript-Dateien sowie Einstellungen zum Fehler-Logging.

Im nächsten Abschnitt namens CSS-Einstellungen können Sie, ähnlich wie bei den JavaScript-Dateien, die CSS-Dateien zusammenführen und komprimieren. Wenn Sie dies auch für die CSS-Dateien aktivieren, dadurch verbessern Sie die Performance Ihres Magento-Shops, werden Sie anschließend einen sehr strukturierten und optimierten HTML-Code haben, wie Sie in Abbildung 14.27 sehen.

Abbildung 14.27    Durch »Bundeling« senken Sie die Anzahl der einzubindenden Dateien.

Magento bindet nur noch eine einzige JavaScript-Datei ein und nutzt insgesamt nur noch drei CSS-Dateien, die aufgrund von technischen Begebenheiten nicht zu einer einzigen Datei zusammengeführt werden können. Sowohl die CSS- als auch die JavaScript-Dateien und der HTML-Quellcode sind minified, d. h., unnötige Leerzeichen, Umbrüche und Einschübe wurden entfernt. Dadurch optimieren Sie die Ladezeit des Systems, weswegen ich Ihnen an dieser Stelle rate, die getätigten Änderungen ebenfalls vorzunehmen. Als einzige Ausnahme sei an dieser Stelle das Entwicklungs- bzw. Testsystem erwähnt. Durch die Bündelung der Dateien wird es schwerer, Fehler nachzuvollziehen. Daher sollten Sie in diesen Fällen auf diese Optionen verzichten und diese nur auf dem Live-System aktivieren.

Abschließend erhalten Sie noch Zugriff auf drei Bereiche, die aber jeweils aus einer Option bestehen. Daher fasse ich sie an dieser Stelle auch etwas zusammen. In der Option Bild-Adapter können Sie wählen, welche Technologie Sie für die Manipulation von Grafiken verwenden. Im Standard verwendet Magento PHP GD2, als Alternative steht jedoch auch ImageMagick zur Verfügung. Aktivieren Sie die Option Statische Dateien registrieren, so wird es einfacher zu identifizieren, ob eine neue Version einer Datei vorliegt. Eine sehr gute Erklärung, was es damit im Detail auf sich hat, erhalten Sie unter http://devdocs.magento.com/guides/v2.0/architecture/view/static-process.html?_ga=2.154516600.1558132686.1500377517-2048498745.1496039808. Abschließend können Sie zudem noch definieren, ob Sie die asynchrone Indexierung aktivieren bzw. deaktivieren möchten
