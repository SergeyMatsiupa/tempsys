17.4    Notwendige Anpassungen, damit Store Views und Websites aufgerufen werden können

Es gibt mehrere Ansätze und Möglichkeiten, wie Sie eine »Weiche« erstellen können, die je nach Domain bzw. Subdomain einen Store View bzw. eine Website aufruft. An dieser Stelle möchte ich Ihnen die einfachste und schnellste Variante zeigen, zugegebenermaßen ist diese Variante nicht die eleganteste, da bei Magento-Updates der Code überschrieben werden kann. Zur Verdeutlichung und Erklärung der Funktionsweise sollte das folgende Beispiel jedoch mehr als ausreichend sein!

In Magento ist die Datei index.php, die sich im Hauptverzeichnis befindet, für das Laden der Website zuständig. Dementsprechend können Sie an dieser Stelle auch eine Weiche einbauen, die je nach URL bzw. Subdomain eine bestimmte Website innerhalb von Magento lädt. Öffnen Sie daher die index.php und suchen Sie nach den folgenden Zeilen:

$bootstrap = \Magento\Framework\App\Bootstrap::create(BP, $_SERVER);
/** @var \Magento\Framework\App\Http $app */
$app = $bootstrap->createApplication('Magento\Framework\App\Http');
$bootstrap->run($app);

Listing 17.1    Magento steuert in der index.php den Aufruf des Store Views bzw. der Website.

Ersetzen Sie im Anschluss den Text durch die folgenden Zeilen:

switch ($_SERVER['HTTP_HOST']) {
  case 'www.foodbaer.de:
  case 'foodbaer.de':
      $params = $_SERVER; $params[\Magento\Store\Model\StoreManager::PARAM_RUN_CODE] = 'base';
      $params[\Magento\Store\Model\StoreManager::PARAM_RUN_TYPE] = 'website';
      $bootstrap = \Magento\Framework\App\Bootstrap::create(BP, $params);
    $app = $bootstrap->createApplication('Magento\Framework\App\Http');
      $bootstrap->run($app); 
      break; 
  case 'www.foodbaer.th:
  case foodbaer.th':
      $params = $_SERVER; $params[\Magento\Store\Model\StoreManager::PARAM_RUN_CODE] = 'asien';
      $params[\Magento\Store\Model\StoreManager::PARAM_RUN_TYPE] = 'website'; 
      $bootstrap = \Magento\Framework\App\Bootstrap::create(BP, $params); 
      $app = $bootstrap->createApplication('Magento\Framework\App\Http');
      $bootstrap->run($app);
  break;
  default:
      Mage::run();
  break;
}

Listing 17.2    Durch die Ergänzungen wird je nach aufgerufener URL ein bestimmter Store View geladen.

Auch wenn Sie kein PHP-Entwickler sind, ist der Code halbwegs einfach zu verstehen. Im ersten Schritt wird die Domain abgefragt, über die der Nutzer auf das Magento-System zugreift. Hierfür müssen alle Domains bzw. Subdomains, die Sie verwenden möchten, auf das Magento-System zeigen. Verantwortlich für die Prüfung ist die folgende erste Zeile, gefolgt von der Abfrage der Ergebnisse:

switch ($_SERVER['HTTP_HOST']) {
    case 'www.foodbaer.de:
    case 'foodbaer.de':

Listing 17.3    Mittels einer Weiche kann geprüft werden, welche URL vom Kunden aufgerufen wurde.

Das heißt, wenn jemand foodbaer.de bzw. www.foodbaer.de als URL verwendet, landet der Nutzer in diesem Code-Block. Im Code-Block selbst werden primär von Magento relevante Befehle ausgeführt, Sie müssen jedoch eine Anpassung in der folgenden Passage vornehmen:

$params[\Magento\Store\Model\StoreManager::PARAM_RUN_CODE] = 'base'; 
        $params[\Magento\Store\Model\StoreManager::PARAM_RUN_TYPE] = 'website';

Listing 17.4    Um den entsprechenden Store View bzw. die Website zu laden, müssen Werte an die Magento-Anwendung übergeben werden.

Denn in diesem Abschnitt hinterlegen Sie, Sie sehen das am Beispiel Base, den Code der Website. Den Code können Sie selbst definieren, wenn Sie eine neue Website anlegen bzw. eine bestehende Website editieren. Das heißt, sobald ein Nutzer nun per www.foodbaer.de oder foodbaer.de auf das Magento-System zugreift, wird die Website mit dem Code base geladen. Wenn Sie mein Beispiel auf der vorherigen Seite nochmals prüfen, werden Sie zudem eine zweite Case-Abfrage feststellen, die prüft, ob ein Nutzer das System mit der Domainendung .th aufruft. Ist dies der Fall, so wird nicht die Website mit dem Code Base geladen, sondern die Website mit dem Code Asia. Somit haben Sie eine Trennung per URL, und je nach aufgerufener URL wird eine andere Website innerhalb von Magento geladen. Selbiges Verhalten können Sie auch für Store Views und Subdomains verwenden. Hinterlegen Sie hierzu beim Run Type Parameter Store View und beim Code den entsprechenden Store-View-Code.

Da ich an dieser Stelle nicht über verschiedene Domains verfüge, werde ich die durchgeführten Änderungen und Anpassungen nicht speichern und hochladen, versuchen Sie daher bitte nicht, foodbaer.es aufzurufen, da dies nicht funktionieren wird. Wenn Sie jedoch über mehrere Domains verfügen, können Sie gern auf die beschriebene Systematik zurückgreifen. Weiterführende Informationen hierzu erhalten Sie übrigens auch direkt bei Magento unter http://devdocs.magento.com/guides/v2.0/config-guide/multi-site/ms_over.html.
