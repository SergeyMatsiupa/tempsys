16.2    Import von Daten

Neben der Möglichkeit, Daten aus dem System zu exportieren, bietet Ihnen Magento zudem die Möglichkeit, Daten zu importieren. Die möglichen Importe decken sich dabei mit den bereits vorgestellten Export-Möglichkeiten. Sprich, alle Informationen, die Sie mit Magento exportieren können, bekommen Sie mit Magento wiederum importiert. Was sie beachten müssen, möchte ich Ihnen auf den folgenden Seiten im Detail vorstellen.

Öffnen Sie hierzu im ersten Schritt die Seite Importoptionen, die Sie unter System • Datentransfer finden. Ähnlich wie beim Export landen Sie bei einer recht überschaubaren Maske, in der Sie zuerst den Datensatztyp auswählen müssen. Die Datensatztypen sind dabei absolut identisch mit den Datensatztypen, die Sie beim Export kennengelernt haben. Starten Sie im ersten Schritt mit den Produkten!

16.2.1    Produkte

Wählen Sie bitte beim Datensatztyp die Option Produkte aus, und scrollen Sie ein wenig nach unten. Sie werden sehen, dass nach Ihrer Auswahl eine Menge neuer Eingabefelder erscheinen und Ihnen neue Optionen zur Verfügung stehen. Direkt neben dem Dropdown-Menü, das Sie gerade genutzt haben, erscheint der Link Beispieldatei herunterladen. Wenn Sie auf diesen Link klicken, wird eine CSV-Datei heruntergeladen, die als Vorlage für den Produktdatenimport verwendet werden kann. Denn falls Sie im Vorfeld keine Ahnung haben, wie die Import-Datei aussehen muss, ist der besagte Link wirklich nützlich. Neben der eigentlichen Struktur der Datei sind übrigens auch Testdatensätze enthalten, an denen Sie sich orientieren können.

Etwas weiter unten können Sie mittels des Dropdown-Menüs Importverhalten definieren, was genau beim Import der Produktdaten passieren soll. Magento stellt hierfür insgesamt drei Optionen zur Auswahl, die Sie auch in Abbildung 16.7 sehen:

  • Hinzufügen/Aktualisieren
  • Ersetzen
  • Löschen

Bei ersterer Option wird ein Produkt angelegt, wenn es bereits existiert jedoch aktualisiert. Diese Option sollten Sie in der Praxis verwenden, denn Sie wollen ja nicht bei jedem Produktdatenimport nochmals alle Produkte anlegen. Das würde zu einer riesigen Anzahl an Doubletten und einem Datenchaos führen. Bei der zweiten Option werden vorhandene Produkte ausschließlich ersetzt und bei letzterer Variante werden die Produkte gelöscht.

Abbildung 16.7    Was mit den übermittelten Produktdaten passieren soll, bestimmen Sie im Feld »Importverhalten«.

Das heißt, Sie können eine Liste mit Produktdaten übermitteln, die Sie löschen möchten. Das ist besonders dann praktisch, wenn Sie Ihr Produktsortiment bereinigen und per Massenbearbeitung Produkte aus dem System entfernen möchten. Im nächsten Feld definieren Sie, was bei Fehlern passiert. Ein Fehler tritt beispielsweise dann auf, wenn eine Zeile innerhalb der CSV-Datei korrupt ist. Magento bietet hierfür zwei mögliche Optionen an. Entweder wird die Zeile einfach übersprungen und der Import wird fortgesetzt, oder der Datenimport wird gestoppt. Wenn der Datenimport gestoppt werden soll, dann können Sie im Feld Erlaubte Fehleranzahl noch die mögliche Anzahl an Fehlern festlegen. Im Standard wird der Import erst nach 10 Fehlern abgebrochen. Tragen Sie an dieser Stelle beispielsweise die Zahl 1 ein, würde der komplette Produktdatenimport beim ersten Fehler abgebrochen werden. Meiner persönlichen Meinung nach können Sie an dieser Stelle ruhig mit der erlaubten Fehleranzahl von 10 starten, da dies ein in der Praxis gängiger Weg ist. Bei enorm vielen Fehlern, d. h. einem komplett korrupten Produktdatenimport, würde der Importvorgang abgebrochen, haben jedoch nur vereinzelte Produkte Fehler, würden die restlichen Produkte dennoch importiert werden.

Die nächsten beiden Felder sind für einen korrekten Produktdatenimport besonders relevant. Beim Feldtrenner definieren Sie, durch welches Zeichen die Felder oder auch Spalten in der CSV-Datei getrennt werden. Beim Export verwendet Magento ein Komma, daher ist an dieser Stelle auch das Komma als Standardwert hinterlegt. Wenn Sie jedoch aus einem anderen Tool einen Produktdatenexport gefahren und einen anderen Feldtrenner verwendet haben, so müssen Sie an dieser Stelle das Zeichen hinterlegen. Zudem können Sie ein Zeichen definieren, wenn mehrere Werte in einer Spalte stehen und diese an sich getrennt werden müssen. Beispielsweise wenn in einer Zeichenfolge Kategorie-IDs hinterlegt sind. Wenn Sie diese Werte an sich nochmals separieren, werden Sie hierfür auch ein Trennzeichen verwenden, und genau dieses Trennzeichen können Sie an dieser Stelle angeben. Haben Sie beim Export die Werte mit Anführungszeichen umschlossen, müssen Sie die Checkbox bei Fields enclosure anhaken. Haben Sie das getan, können Sie im nächsten Feld Wählen Sie die zu importierende Datei, bei dem es sich um ein Upload-Feld handelt, die hochzuladende Datei auswählen. Wenn Sie zudem Bilder hinzufügen bzw. überschreiben möchten, müssen Sie im Feld Bilderdateiverzeichnis das Verzeichnis zu den Bildern angeben, die Sie hinzufügen möchten.

Welche Optionen in Ihrem konkreten Fall richtig sind, lässt sich pauschal nicht beantworten. Achten Sie, das ist meine Empfehlung, auf den Feld- und Wertetrenner, sodass Sie an diesen beiden Stellen das richtige Zeichen hinterlegt haben. Je nachdem ob Sie Ihre Werte mit Anführungszeichen umschlossen haben oder nicht, ist in der Checkbox bei der Option Fields enclosure ein Haken zu setzen bzw. dieser zu entfernen.

Nachdem Sie eine Datei ausgewählt haben – ich verwende zu Testzwecken an dieser Stelle die weiter oben angebotene Beispieldatei –, klicken Sie auf den Button Daten prüfen. Bevor Magento mit dem Import startet, wird zuerst die bereitgestellte Datei auf Herz und Nieren geprüft. Sollten darin Fehler enthalten sein, wird Magento Sie genau auf diese Fehler aufmerksam machen. Ironischerweise wird, wenn Sie die Beispieldatei verwenden, eine recht lange Fehlerliste herauskommen, wie Sie in Abbildung 16.8 sehen. Wenn Sie einen Blick auf die Abbildung werfen, werden Sie zudem in dem gelben Bereich einen Download-Link sehen, der zu einer detaillierten Fehlerbeschreibung führt, d. h., wenn Sie sich einmal unsicher bezüglich des Imports und der daraus resultierenden Probleme sein sollten, können Sie ein detailliertes Protokoll der Fehler einsehen.

Abbildung 16.8    Sollte die bereitgestellte Importdatei Fehler aufweisen, macht Sie Magento vor dem Import darauf aufmerksam.

Sofern bei der Prüfung der Daten keinerlei Fehler identifiziert wurden, können Sie anschließend mit dem Import der Produktdaten beginnen, und Magento wird, je nach eingestelltem Importverhalten, die Datensätze aktualisieren bzw. überschreiben oder entfernen.

16.2.2    Erweiterte Preisgestaltung

Möchten Sie anstelle von Produkten nur die Staffelpreise importieren, wählen Sie beim Datensatztyp bitte die Option Erweiterte Preisgestaltung aus. Daraus ergeben sich wiederum Konfigurationsoptionen, die Ihnen jedoch aufgrund des Produktdatenimports bekannt vorkommen sollten. Neben dem Importverhalten können und müssen Sie den Feldtrenner sowie Trenner von mehreren Werten bestimmen. Warum Sie, nachdem Sie eine Importdatei ausgewählt haben, an dieser Stelle ein Bilderdateiverzeichnis angeben können, kann ich Ihnen aber nicht beantworten. Vermutlich ist dies eine kleine Ungereimtheit, die sich in diese Magento-Version eingeschlichen hat. Denn beim Import von Staffelpreisen werden Sie niemals die Möglichkeit haben, Referenzen auf Bilddateien anzugeben. Lassen Sie sich von dieser Option aber nicht irritieren, und ignorieren Sie diese. Zu Testzwecken verwende ich beim Import der Staffelpreise nun die Datei, die ich vorhin beim Export der Staffelpreise erhalten habe. In diesem Fall werden Sie auch keine Fehler nach der Prüfung der Datei erhalten, und Sie können mit dem Import der Datei beginnen. Einen Hinweis habe ich an dieser Stelle aber noch: Achten Sie darauf, dass die Datei, die Sie importieren möchten, nicht allzu groß wird. Je nachdem wie die Systemkonfiguration Ihres Webservers sowie PHP eingestellt ist, werden Sie womöglich bei Dateien, die größer als 32 MB sind, Probleme bekommen.

16.2.3    Kunden und Adressen (einzelne Datei)

Möchten Sie Kundenstammdaten samt Adresse importieren, haben Sie zum einen die Wahl, diese Informationen aufzusplitten und zwei getrennte Importe zu verwenden. Das ist im Prinzip die Vorgabe durch den Export, denn Sie können Kundenstammdaten und Kundenadressen nicht in einer Datei exportieren. Beim Import bietet Ihnen Magento jedoch zum anderen die Möglichkeit, genau dies zu tun. Das heißt, Sie können Kundenstammdaten und Kundenadressen in einer Datei ablegen und diese in Magento einspielen. Da Sie diese Datei beim Export nicht erzeugen können, laden Sie sich bitte die Beispieldatei herunter, um einen Überblick über die Struktur und den Aufbau der Datei zu erhalten.

16.2.4    Kunden Hauptdatei

Alternativ zum aggregierten Import können Sie zudem ausschließlich die Kundenstammdaten importieren. Wählen Sie hierfür beim Datensatztyp den Eintrag Kunden Hauptdatei aus der Liste aus. Die weiteren Importoptionen sind identisch mit den bereits bekannten Möglichkeiten und Einstellungen.

16.2.5    Kundenadressen

Last, but not least können Sie ausschließlich Adressen importieren. Hierfür stellt Magento beim Import einen eigenen Datensatztyp bereit, der den Namen Kundenadressen trägt. Die Optionen decken sich erneut mit den Ihnen bereits bekannten Importmöglichkeiten. Achten Sie auch beim Import der Kundenadressen auf den korrekten Feldtrenner und Trenner von mehreren Werten. Wie auch bei den vorherigen Importen können und müssen Sie vor der Durchführung des eigentlichen Imports die zu importierenden Daten überprüfen. Erst wenn dieser Check erfolgreich ist, können Sie mit dem eigentlichen Import starten.

16.2.6    Steuersätze

Wie Sie Steuersätze exportieren, wissen Sie bereits. Da Sie die Steuersätze aus dem System exportieren können, gibt es auch eine Möglichkeit, Steuersätze erneut zu importieren. Öffnen Sie hierzu im Backend den Punkt System • Steuersätze importieren/exportieren. Innerhalb dieser Maske haben Sie nun die Möglichkeit, eine Datei auszuwählen und den Import zu starten. Anpassungen an der Struktur, beispielsweise die Definition eines Feldtrenners, können Sie an dieser Stelle nicht durchführen. Sie müssen die Datei daher exakt wie den Export aufbauen, den Sie übrigens auch in dieser Ansicht auslösen können. Orientieren Sie sich daher idealerweise am Export, d. h., exportieren Sie zuerst die Steuersätze. Anschließend können Sie Ihre Änderungen und Anpassungen auf Basis dieser Datei vornehmen. Sobald Sie die Änderungen gespeichert haben, verwenden Sie diese Datei für den Import. Bei dieser Vorgehensweise sollten Sie später beim Import auf keinerlei Probleme stoßen!

16.2.7    Import-Historie

Sobald Sie einen Import durchführen bzw. durchführen möchten, werden der Versuch und das Ergebnis protokolliert. Die hierfür zuständige Import-Historie können Sie unter System • Datentransfer • Import-Historie aufrufen. In meinem Fall, Sie sehen dies in Abbildung 16.9, existieren vier Einträge.

Abbildung 16.9    Innerhalb der Import-Historie können Sie alle Importe und Importversuche nachvollziehen.

Bei den unteren drei Einträgen handelt es sich ausschließlich um Versuche, da der Import aufgrund korrupter Daten nicht durchgeführt werden konnte. Die Import-Historie bietet an dieser Stelle sogar einen Verweis auf das erzeugte Fehlerprotokoll an, das Sie in der Spalte Fehler-Datei herunterladen können. Sobald ein Import erfolgreich verlaufen ist, bei mir ist dies in Abbildung 16.9 in der ersten Zeile zu sehen, wird keine Fehlerdatei erzeugt, dafür aber eine Durchführungszeit vermerkt. Die Durchführungszeit gibt in Sekunden an, wie lange der Import benötigt hat. Zudem sehen Sie, wie viele Datensätze erstellt, aktualisiert bzw. gelöscht wurden. Insgesamt bietet Ihnen die Import-Historie daher einen guten Überblick über die durchgeführten und gescheiterten Importversuche, und Sie finden alle diesbezüglich relevanten Informationen an einem zentralen Punkt.

Kein kontextabhängiger Import vorhanden

Im Gegensatz zum Datenexport gibt es beim Import keine kontextabhängigen Importmöglichkeiten. Das heißt, Sie können einen Import beispielsweise nicht in der Kundenübersicht starten. Auch wenn dies beim Datenexport eine äußerst praktische Möglichkeit darstellt, würde das wohl beim Import für eine zu große Komplexität sorgen. Dementsprechend können Sie die Importe ausschließlich in dem auf den vorherigen Seiten vorgestellten Bereich durchführen.
