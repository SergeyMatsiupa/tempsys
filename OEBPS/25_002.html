25.2    Typische Alltagsprobleme und passende Lösungen

Im Leben eines Magento-Shop-Betreibers bzw. Magento-Administrators gibt es typische Alltagsprobleme, zumindest bezeichne ich sie so. Damit meine ich Tätigkeiten, die Sie mal regelmäßiger, mal unregelmäßiger ausführen müssen, die aber definitiv auf Sie zukommen. Damit Sie bestmöglich vorbereitet sind, möchte ich in diesem Abschnitt genau auf diese Tätigkeiten und Vorgehensweisen eingehen und Ihnen somit einen kurzen, aber dennoch hilfreichen Leitfaden an die Hand geben.

25.2.1    MySQL-Verbindungsdaten zum Datenbankserver anpassen

Wenn Sie Ihr Magento-System zu einem neuen Webhoster übertragen bzw. intern bei Ihrem bestehenden Webhoster umziehen, erhalten Sie in der Regel neue Verbindungsdaten zum MySQL-Datenbankserver. Sofern Sie über neue Zugangsdaten verfügen, müssen Sie die Magento-Konfiguration anpassen, da ansonsten keine Verbindung zur Datenbank hergestellt werden kann. Wenn Sie die Zugangs- bzw. Verbindungsdaten zum MySQL-Datenbankserver anpassen möchten, gehen Sie bitte wie folgt vor.

Öffnen Sie im ersten Schritt die Datei env.php, die sich im Verzeichnis /app/etc befindet. Die Datei env.php enthält alle relevanten Konfigurationseinstellungen, die mehr oder weniger mit Ihrem Hosting-Setup zusammenhängen. In der Datei env.php scrollen Sie bis zur Zeile 21, in der sich das folgende Array befindet:

array (
        'host' => 'localhost',
        'dbname' => 'dbxxxyyyy-10',
        'username' => 'dbxxxyyyy-10',
        'password' => IrgendeinPasswort',
        'active' => '1',
        'model' => 'mysql4',
        'engine' => 'innodb',
        'initStatements' => 'SET NAMES utf8;',
      ),

Listing 25.1    Die Verbindungsdaten zum MySQL-Datenbankserver befinden sich in einem Array in der Datei »env.php«.

In diesem Array können Sie den Host, den Datenbanknamen sowie den Benutzernamen und das Passwort definieren. Speichern Sie, nachdem Sie die Verbindungs- bzw. Zugangsdaten geändert haben, die Datei, und öffnen Sie die Kommandozeile. Navigieren Sie zum Hauptverzeichnis Ihrer Magento-Instanz und führen Sie folgende Befehle aus:

rm -r var/cache
rm -r var/di
rm -r var/generation
rm -r var/page_cache

Da Magento unter anderem die Verbindungsdaten zwischenspeichert, müssen Sie den gesamten Cache Ihrer Magento-Instanz leeren, sodass Magento auf die neuen Verbindungsdaten zugreifen kann.

Anschließend können Sie sowohl das Magento-Backend als auch das -Frontend problemlos aufrufen, da Magento auf Basis der neu hinterlegten Zugangsdaten erfolgreich eine Verbindung zum MySQL-Datenbankserver herstellen kann.

25.2.2    Cache per Kommandozeile leeren

Wenn Sie weiterreichende Änderungen vorgenommen oder gar eine Extension installiert haben, müssen Sie anschließend den Cache löschen. Tun Sie dies nicht, laufen Sie Gefahr, dass Magento noch veraltete Informationen ausliest und somit die Darstellung bzw. das Verhalten nicht wirklich korrekt ist. Um den Cache zu löschen, haben Sie zwei Möglichkeiten. Sie können diesen per Kommandozeile oder innerhalb des Magento-Backends löschen bzw. leeren. Letztere Option ist aber eigentlich nicht die beste, denn wenn Sie beispielsweise die Zugangsdaten zur MySQL-Datenbank abändern, werden Sie im ersten Moment gar nicht mehr in das Magento-Backend kommen. Das Leeren bzw. Löschen des Caches empfiehlt sich daher, da Sie dies immer und zu jedem Zeitpunkt tun können, egal, ob Ihr Magento-System korrekt funktioniert oder aktuell noch mit Fehlern zu kämpfen hat.

Um den Cache per Kommandozeile zu leeren, rufen Sie diese auf, und navigieren Sie in das Hauptverzeichnis von Magento. Führen Sie anschließend folgenden Befehl aus: php bin/magento cache:clean. Theoretisch könnten Sie an dieser Stelle auch nur beliebige Caches leeren bzw. löschen. Fügen Sie keine Parameter hinzu, wird der gesamte Cache geleert. Sollten Sie beim Leeren des Caches Probleme haben, können Sie alternativ direkt die vorhandenen Cache-Verzeichnisse löschen. Führen Sie hierfür folgende Befehle innerhalb der Kommandozeile aus:

rm -r var/cache
rm -r var/di
rm -r var/generation
rm -r var/page_cache

Das sollte jedoch nur Ihr Plan B sein. Um den Cache zu leeren, verwenden Sie in erster Linie bitte bin/magento mit dem Parameter cache:clean.

25.2.3    Indexe per Kommandozeile erneuern

Ein Index hat gewisse Ähnlichkeiten mit einem Cache, nur dass ein Index keine Dateien auf dem Dateisystem anlegt. Wenn die verschiedenen Indexe, die in Magento existieren, nicht aktuell sind, kann das zu veralteten Ausgaben oder zu Problemen im Front- sowie Backend führen. Dementsprechend müssen Sie stets für aktuelle Indexe sorgen. Um die Aktualisierung kümmert sich eigentlich Magento, da ein Index, je nach Einstellung, entweder beim Speichern eines Datensatzes oder in zeitlich definierten Abständen aktualisiert wird. Jedoch kann es bei der Aktualisierung zu Problemen kommen, wodurch Sie den Index oder die Indexe manuell aufbauen müssen.

Im Gegensatz zum Cache-Management stellt Magento bei der Index-Verwaltung, die Sie in Abbildung 25.8 sehen, keine Möglichkeit zur Aktualisierung innerhalb der Web-Oberfläche zur Verfügung.

In Magento 1 konnten Sie die Indexe noch innerhalb des Backends neu aufbauen. Das hat jedoch regelmäßig zu »toten« Magento-Systemen und Performanceeinbrüchen geführt. Der Aufbau der Indexe ist je nach Datenmenge enorm rechenintensiv und sollte daher nur zu bestimmten Zeiten mittels Kommandozeile ausgeführt werden. Im Backend hätten Sie sofort Probleme mit dem PHP Memory_Limit bzw. Timeouts, aus diesem Grund hat Magento diese Funktionalität auch aus dem Backend entfernt.

Sie können jedoch die Indexe, wie ich bereits erwähnt habe, ganz bequem per Kommandozeile aktualisieren bzw. neu aufbauen. Sobald Sie sich im Hauptverzeichnis Ihrer Magento-Instanz befinden rufen Sie zwecks Aktualisierung einfach den folgenden Befehl auf: php bin/magento indexer:reindex. Daraufhin baut Magento alle Indexe neu auf bzw. aktualisiert diese. Sie haben übrigens auch die Möglichkeit, nur bestimmte Indexe aufzubauen, indem Sie die Namen der Indexe als Parameter übergeben. Führen Sie den Befehl hingegen ohne weitere Parameter aus, so aktualisiert Magento alle im System vorhandenen Indexe.

Abbildung 25.8    Innerhalb des Backends sehen Sie ausschließlich den Status der Indexe, können diese aber nicht neu aufbauen bzw. aktualisieren.

25.2.4    Admin-Passwort per SQL-Statement zurücksetzen

Leider passiert es mir doch ab und an, dass ich das Passwort für meinen Backend-Nutzer verlege und auch die »Passwort vergessen«-E-Mail nicht ankommt. Denken Sie nur an ein Entwicklungssystem, bei dem der E-Mail-Versand deaktiviert ist. In diesen Fällen können Sie jedoch direkt über die Datenbank das Passwort Ihres Nutzers zurücksetzen, was ich als äußerst praktisch erachte.

Um das Passwort per Datenbank zurückzusetzen, benötigen Sie einen Zugriff bzw. Zugang zur Datenbank, beispielsweise mittels phpMyAdmin. Auch könnten Sie direkt auf die Datenbank per SSH verbinden oder mit einem externen Client wie Sequel Pro auf die Datenbank zugreifen. Sobald Sie mit Ihrer Magento-Datenbank verbunden sind, führen Sie bitte den folgenden Befehl aus, wobei Sie gewisse Parameter und Variablen noch anpassen müssen: UPDATE admin_user SET password = CONCAT(SHA2('xxxxxxxYourNewPassword', 256), ':xxxxxxx:1') WHERE username = 'admin';

Anstelle von 'xxxxxxxYourNewPassword' müssen Sie Ihr gewünschtes Passwort hinterlegen. Auch müssen Sie den Wert xxxxxxx durch den Crypt Key, den Sie in der Datei app/etc/env.php finden, ersetzen. Abschließend müssen Sie dem SQL-Statement noch den zu ändernden Benutzer mitteilen. Im obigen Beispiel würde der Benutzer mit dem Namen admin abgeändert werden, vermutlich haben Sie für Ihren Nutzer aber einen anderen Namen definiert. Dementsprechend müssen Sie diese Stelle anpassen. Sobald Sie diese Änderungen vorgenommen haben, können Sie das SQL-Statement ausführen, wodurch das Passwort des ausgewählten Benutzers geändert wird. Anschließend können Sie sich mit Ihrem neuen Passwort am Magento-Backend anmelden.

25.2.5    Wartungsmodus per Kommandozeile steuern

Ab und an kann es recht nützlich sein, auf dem Live- wie auch auf dem Testsystem den Wartungsmodus zu aktivieren. Am schnellsten können Sie den Wartungsmodus definitiv per Kommandozeile aktivieren. Navigieren Sie in das Hauptverzeichnis Ihrer Magento-Instanz, und führen Sie den Befehl php bin/magento maintenance:enable bzw. php bin/magento maintenance:disable aus, um den Wartungsmodus zu aktivieren bzw. zu deaktivieren.

25.2.6    Fehlende Dateien? Statische Inhalte per Kommandozeile deployen

Es hängt zugegebenermaßen vom Setup Ihres Magento-Systems ab, ob Sie die statischen Dateien deployen müssen oder nicht. In der Regel müssen Sie dies jedoch auf Live-Systemen tun. Statische Dateien sind CSS- bzw. JavaScript-Dateien und Bilder, auf die Magento zurückgreift. Stehen diese Dateien nicht zur Verfügung, kommt es im Frontend und auch im Backend zu Fehlern. Die statischen Dateien können Sie ebenfalls mittels der Kommandozeile erstellen. Navigieren Sie ins Hauptverzeichnis Ihrer Magento-Instanz, und führen Sie den folgenden Befehl aus: php bin/magento setup:static-content:deploy. Gegebenenfalls werden Sie Probleme bezüglich des Memory Limits bekommen, wobei Sie den Parameter -d memory_limit=2048M ergänzen können. Auch sollten Sie den Sprachcode, für den Sie die Dateien erzeugen möchten, angeben. Das wäre in Ihrem Fall vermutlich de_DE. Dadurch ergibt sich der folgende Befehl, den Sie verwenden können: php -d memory_limit=2048M bin/magento setup: static-content:deploy de_DE. Wenn Sie diesen Befehl ausführen, erzeugt Magento alle statischen Dateien für die deutsche Sprachversion Ihres Systems.

25.2.7    Backup per Kommandozeile erstellen

Auch wenn die Backup-Strategie sicherlich Sache des Webhosters und somit des Systemadministrators ist, so ist ein kurzes und schnelles Backup, das Sie selbst anlegen können, in der Praxis recht nützlich. Das Backup können Sie dann für das lokale Test- bzw. Entwicklungssystem verwenden, oder es dient einfach als Sicherheit, wenn Sie im Live-System eine Konfigurationsanpassung vornehmen.

Der beste Weg, eine Sicherung zu erstellen, führt über die Kommandozeile. Navigieren Sie zum Hauptverzeichnis Ihrer Magento-Instanz, und führen Sie den Befehl php bin/magento setup:backup --code --media --db aus. Durch die drei Parameter am Ende des Befehls definieren Sie, welche Elemente Sie sichern möchten. In diesem Beispiel werden sowohl der komplette Code als auch die Datenbank und das Medienverzeichnis gesichert. Sobald Sie den Befehl ausgeführt haben, startet Magento den Backup-Prozess und informiert Sie, sobald die Sicherung zum Download sowie zum Restore zur Verfügung steht.

Speziell den Aufbau der Caches sowie den Neuaufbau der Indexe werden Sie in der Praxis sicherlich häufiger benötigen, daher empfehle ich Ihnen auch die Nutzung und Einarbeitung in das Magento CLI-Tool, mit dem Sie per Kommandozeile recht viel steuern können. Sollten Sie sich bei der Nutzung des CLI-Tools noch nicht ganz sicher fühlen, werfen Sie doch noch mal einen Blick in Kapitel 19, »Magento per Kommandozeile administrieren«, denn dieses befasst sich ausschließlich mit diesem Thema.
