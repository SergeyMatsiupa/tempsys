19    Magento per Kommandozeile administrieren

Auch wenn Sie bislang ausschließlich das Backend und Frontend kennengelernt haben, gibt es eine weitere Möglichkeit, mit Magento zu interagieren. Hierbei handelt es sich um die Kommandozeile, mit deren Hilfe Sie einen Großteil des Systems administrieren können.

Wenn Sie in den vergangenen Kapiteln Änderungen am System durchgeführt haben, so habe ich Sie immer in das Magento-Backend, in wenigen Ausnahmen auch in das -Frontend, geschickt. Das Backend ist die zentrale Stelle, an der Sie Konfigurationsoptionen anpassen, Produkte verwalten, Kunden administrieren und Bestellungen verarbeiten können. Kurz gesagt, ist es der zentrale Kanal, den Sie als Shop-Betreiber und E-Commerce-Verantwortlicher nutzen. Das Backend als alleiniges Interface zur Administration und Verwaltung des Magento-Systems zu bezeichnen ist jedoch nur die halbe Wahrheit. Denn mit der Kommandozeile können Sie ebenfalls Ihr Magento-System administrieren. Der Fokus liegt hierbei auf der Administration, d. h., Produkte werden Sie mit der Kommandozeile nicht verwalten können. Dafür können Sie aber sehr wohl Optionen und Konfigurationseinstellungen anpassen, Backups durchführen und mit dem System als solches arbeiten.

Bei Magento haben Sie, sollten Sie die Kommandozeile zur Administration nutzen wollen, die Qual der Wahl. Zum einen bietet Magento 2 von Haus aus Möglichkeiten zur Administration per Kommandozeile, zum anderen steht mit Magerun ein bereits für Magento 1 äußerst populäres Tool zur Verfügung, mit dem Sie Ihre Magento-Instanz ebenfalls verwalten können. Da es insgesamt zwei sehr starke Tools gibt, möchte ich Ihnen in diesem Kapitel beide vorstellen. Danach werden Sie sicherlich die Entscheidung treffen können, ob Sie mit den Bordmitteln so weit klarkommen oder ob Sie auf Magerun setzen möchten.

Kommandozeile, Shell, Terminal, Konsole etc.

Verzeihen Sie mir, wenn ich in diesem Kapitel als Oberbegriff Kommandozeile verwende. Wenn Sie die Kommandozeile wie ich nutzen würden, würden Sie diese vermutlich direkt als Terminal bezeichnen, unter Linux würden Sie von der Shell sprechen und unter Windows von der Eingabeaufforderung. Da mir die Differenzierung aufgrund der Vielzahl von Betriebssystemen aber zu mühselig ist, spreche ich im Folgenden nur von der Kommandozeile. Je nach verwendetem Betriebssystem wissen Sie letztendlich, was damit gemeint ist.

19.1    Magento CLI (Command Line Interface) nutzen

Werfen Sie gemeinsam mit mir direkt und ohne Umwege einen Blick auf die Möglichkeiten, die das Magento Command Line Interface, kurz gesagt, Magento CLI, bietet. Rufen Sie hierzu Ihre Kommandozeile auf, und navigieren Sie zum Hauptverzeichnis von Magento. Dort angekommen, können Sie Magento CLI mit php bin/magento starten.

Anschließend erhalten Sie als Rückgabe ein Ergebnis, wie Sie es in Abbildung 19.1 sehen. Magento zeigt Ihnen, da Sie an dieser Stelle nur die Anwendung aufgerufen haben, alle möglichen Parameter an, führt aber noch keinen Befehl aus. Einen Befehl bzw. eine Aktion können Sie schlussendlich nur dann ausführen, wenn Sie einen der aufgeführten Parameter beim Aufruf mit übergeben.

Abbildung 19.1    Wenn Sie ausschließlich »bin/magento« ohne Parameter aufrufen, erhalten Sie anschließend eine Liste aller vorhandenen Befehle.

Als Beispiel hierfür werfen Sie bitte einen Blick auf den Befehl php bin/magento info:adminuri. Die Magento-Applikation wird hier ebenfalls gestartet, doch durch die Übergabe des Parameters info:adminuri weiß Magento, was Sie tun möchten, und liefert Ihnen den im System hinterlegten URI (Uniform Resource Identifier) für das Backend als Ergebnis zurück. Die Rückgabe des Admin-URI ist natürlich nur eines von vielen Beispielen, Magento liefert an dieser Stelle auch nicht einfach nur Werte zurück, sondern kann ganze Operationen ausführen. Welche Operationen Sie ausführen können, zeige ich Ihnen auf den folgenden Seiten.

19.1.1    Befehle des Magento CLI im Überblick

Die verfügbaren Befehle untergliedern sich in verschiedene Gruppen. Jede Gruppe ist dabei mit einem oder mehreren Befehlen ausgestattet, auf die Sie zurückgreifen können.

Available commands

Genau genommen ist »Available commands« eigentlich gar keine Gruppe, unter dieser Überschrift finden sich jedoch auch zwei Befehle. Hierbei handelt es sich um help bzw. list. Mithilfe des Help-Kommandos können Sie sich, abhängig vom gewählten Befehl, weitere Informationen anzeigen lassen. Es handelt sich also um eine unterstützende Funktion, die Sie nutzen können, wenn Sie Probleme mit der Nutzung des Command Line Interfaces haben. Der List-Befehl hingegen listet alle Befehle und Kommandos auf. Dabei handelt es sich um die Rückgabe, die Sie auch erhalten, wenn Sie bin/magento ohne Parameter ausführen. Ohne Parameter erhalten Sie schlussendlich auch eine Auflistung aller Befehle; führen Sie list aus, erhalten Sie letztendlich dasselbe Ergebnis.

Admin

In der Gruppe »Admin« existieren insgesamt zwei Befehle, mit denen Sie einen Admin-Benutzer erstellen sowie einen gesperrten Admin freischalten.

Um einen Admin zu erstellen, nutzen Sie bitte den Parameter admin:user:create. An dieser Stelle können Sie ruhig den Befehl per Kommandozeile ausführen. Wenn Sie dies tun, werden Sie nämlich eine Fehlermeldung erhalten:

User Name is a required field.
First Name is a required field.
Last Name is a required field.
Please enter a valid email.
Password is required field.
Your password must be at least 7 characters.
Your password must include both numeric and alphabetic characters.

Listing 19.1    Ohne weitere Parameter können Sie keinen Admin anlegen.

Es reicht daher nicht den Parameter admin:user:create zu übergeben, da Sie an dieser Stelle noch weitere Informationen wie den Benutzernamen, den Vornamen etc. benötigen. Wenn Sie an dieser Stelle nicht wissen, welche Parameter Sie übergeben können und müssen, rufen Sie bin/magento auf, und übergeben Sie die Parameter admin:user:create help. Wenn Sie an dieser Stelle das Help-Kommando verwenden, bekommen Sie detailliert angezeigt, welche Parameter und Werte Sie übergeben müssen, um einen Admin-Benutzer zu erstellen. Schlussendlich ergibt sich, an dieser Stelle handelt es sich jedoch nur um ein Beispiel, folgender Befehl, den Sie ausführen müssen, um einen neuen Benutzer per Magento CLI zu erstellen:

php bin/magento admin:user:create --admin-user="test" --admin-password="test12345!" --admin-email="test@steireif.com" --admin-firstname="Alexander" --admin-lastname="Steireif"

Haben Sie diesen Befehl ausgeführt, werden Sie innerhalb der Kommandozeile eine positive Rückmeldung erhalten, und der Benutzer ist im System hinterlegt.

Abgesehen von der Anlage eines neuen Admin-Benutzers, können Sie zudem einen bestehenden Admin-Benutzer entsperren. Nutzen Sie hierfür den Parameter admin:user:unlock, und ergänzen Sie als Wert den Benutzernamen des Admin-Benutzers, den Sie entsperren möchten. Daraus ergibt sich ein Aufruf wie php bin/magento admin:user:unlock asteireif, falls der Admin-Benutzer den Benutzernamen asteireif trägt. Ansonsten müssen Sie den letzten Wert im Befehl editieren. Beachten Sie, dass das Erkennungsmerkmal immer der Benutzername und nicht gar die E-Mail-Adresse ist.

Admin-Benutzer sind Backend-Benutzer!

Bevor an dieser Stelle Irritation entsteht, mit Admin-Benutzer meint Magento Backend-Benutzer. Ein Backend-Benutzer kann einen Administratorstatus haben, das ist an dieser Stelle jedoch nicht gemeint. Mittels der Magento CLI können Sie also Backend-Benutzer anlegen und entsperren, unabhängig von der hinterlegten Berechtigung.

app

Der Abschnitt »app« enthält einen Befehl namens app:config:dump. Wenn Sie diesen Parameter verwenden und bin/magento ausführen, erstellt Magento eine Sicherung der Systemkonfiguration. Hierfür legt Magento im Verzeichnis /app/etc eine neue Datei namens config.local.php an, in der die Einstellungen Ihres Magento-Systems gespeichert werden. Neben den Store Views, Websites und Stores wird zudem die Systemkonfiguration bestehend aus den URLs, Währungen, Kunden- und Katalogeinstellungen etc. gesichert. Einzige Ausnahme stellen sensible Daten wie Passwörter oder Zugangsdaten dar, die nicht in diese Datei geschrieben werden. Das geschieht aus Sicherheitsgründen, seien Sie hiervon an dieser Stelle nicht irritiert.

cache

Wenn Sie Änderungen am System durchführen, eine Erweiterung installieren bzw. neue Inhalte verfügbar sind, so müssen Sie in der Regel immer den Cache leeren. Beim Cache handelt es sich um nichts anderes als eine Art Zwischenspeicher. Magento fragt Inhalte, sollten diese im Cache verfügbar sein, aus Performancegründen immer zuerst im Cache ab. Dadurch kann, speziell im Frontend, zum Teil ein veralteter Inhalt dargestellt werden. In der Regel leert sich der Cache automatisiert nach einigen Stunden, an dieser Stelle haben Sie jedoch die Möglichkeit, direkt auf das Verhalten der Caches einzuwirken und dieses zu steuern.

Möchten Sie den Cache leeren, können Sie dies mittels des Parameters cache:clean tun. Dadurch werden alle Cache-Dateien im Verzeichnis /var/cache sowie /var/full_page_cache/ geleert, wodurch keine Cache-Dateien im System mehr vorhanden sind. Wenn Sie jedoch nicht den gesamten Cache leeren möchten, müssen Sie dies an dieser Stelle auch nicht tun. Wenn Sie zusätzlich den Namen eines Cache-Typs übergeben, werden Sie auch nur diesen leeren. Sollten Sie sich nun fragen, wie die einzelnen Caches benannt sind, werfen Sie bitte einen Blick in folgende Liste, aus der Sie die jeweiligen Benennungen entnehmen können:

  • config
  • layout
  • block_html
  • collections
  • reflection
  • db_ddl
  • eav
  • customer_notification
  • full_page
  • config_integration
  • config_integration_ap
  • translate
  • config_webservice

Möchten Sie beispielsweise nur den translate-Cache leeren, muss Ihr Befehl php bin/magento cache:clean translate lauten.

Verwenden Sie den Parameter cache:disable, können Sie zudem den gesamten Cache in Ihrem Magento-System deaktivieren. Mit dieser Funktion sollten Sie vorsichtig sein und diese unter keinen Umständen im Live-System ausführen, da sonst die Performance Ihres Magento-Systems in den Keller rauscht. Beim Aufruf dieses Befehls deaktiviert Magento übrigens alle Caches. Möchten Sie dies vermeiden, müssen Sie explizit den Namen des Caches angeben, den Sie deaktivieren wollen. Im Fall des config-Caches würde der Parameter daher wie folgt lauten: php bin/magento cache:disable layout. Anstelle des Parameters layout können Sie jeden der in der Liste aufgeführten Parameter verwenden und damit den Cache des Magento-Systems leeren.

Wenn Sie einen Cache-Typ bzw. den gesamten Cache deaktiviert haben, benötigen Sie wiederum die Möglichkeit, diesen erneut zu aktivieren. Hierfür steht Ihnen der Parameter cache:enable zur Verfügung. Genau wie bei der Deaktivierung der Caches können Sie entweder den gesamten Cache oder einzelne Cache-Typen aktivieren. Auch hierbei können Sie sich auf die Bezeichnungen, die Sie in der weiter oben aufgeführten Liste finden, berufen und diese bei der Aktivierung verwenden. Sie müssen also nicht immer den gesamten Cache aktivieren, sondern können sich für den in diesem Moment relevanten Cache-Typen entscheiden.

Ähnlich dem vorgestellten Parameter cache:clean gibt es mit cache:flush einen weiteren Parameter, mit dem Sie den Cache Ihres Magento-Systems leeren können. Der Unterschied beider Parameter liegt darin, dass cache:flush noch eine Stufe weiter geht und auch externe Caches, die eingebunden wurden, leert. Mit cache:flush leeren Sie daher grundsätzlich alles, was sich im Cache befindet, ganz gleich, ob Sie nur den lokalen Magento-Cache verwenden oder externe Caching-Locations eingebunden haben. Die Nutzung ist äquivalent zu cache:clean. Wenn Sie keine weiteren Parameter ergänzen, wird der gesamte Cache geleert, übergeben Sie hingegen noch einen Cache-Typ, so leeren Sie auch nur den angegebenen Cache-Typ.

Interessieren Sie sich in erster Linie für den Cache-Status, können Sie diesen mittels cache:status abfragen. Als Ergebnis werden Sie eine Antwort, die wie folgt aussieht, erhalten:

Current status:
config: 0
layout: 1
block_html: 0
collections: 0
reflection: 0
db_ddl: 0
eav: 0
customer_notification: 0
full_page: 0
config_integration: 0
config_integration_api: 0
translate: 0
config_webservice: 0

Listing 19.2    Eine beispielhafte Antwort von Magento, wenn Sie den Cache-Status abfragen

Jeder Cache-Typ der am Ende eine 1 trägt, ist aktiviert. Ist hingegen eine 0 angegeben, so ist dieser Cache-Typ momentan deaktiviert. Mithilfe dieses Parameters können Sie daher recht schnell und einfach sehen, welche Caches aktiv bzw. inaktiv sind, und mittels der Kommandozeile deaktivierte Caches aktivieren.

catalog

Den Produktkatalog, Sie haben dies in den vergangenen Kapiteln gesehen, administrieren Sie in erster Linie mithilfe des Magento-Backends. Es wäre an dieser Stelle auch etwas verrückt, wenn Sie Produkte mittels Kommandozeile anlegen könnten. Aus diesem Grund sind in diesem Abschnitt nur zwei Funktionen vorhanden, die administrative Aufgaben übernehmen, jedoch keinen Einfluss auf die Produktpflege haben.

So können Sie mittels des Parameters catalog:images:resize die Produktbilder in der Größe verändern. Magento erstellt auf Basis der hinterlegten Bilder eine passendere Variante in Bezug auf Höhe und Breite. Was die passende Variante in Ihrem Fall ist, können Sie in einer XML-Datei definieren, die sich unter <theme_dir>/etc/view.xml befindet. Alternativ zu diesem Resize-Parameter können Sie zudem nicht benutzte Attribute aus dem System entfernen, indem Sie beim Aufruf per Kommandozeile den Parameter catalog:product:attributes:cleanup übergeben. In der Praxis werden Sie vermutlich beide Befehle nicht so häufig benötigen, es ist aber gut zu wissen, dass es diese beiden Möglichkeiten gibt.

cron

Mittels des CronJobs werden zeitlich terminierte Aufgaben gesteuert, was für die Funktionsweise Ihres Magento-Systems unerlässlich ist. Wenn Sie den CronJob manuell anstoßen möchten, können Sie dies per Kommandozeile tun. Übergeben Sie hierfür den Parameter cron:run, woraufhin Magento prüft, ob und welcher CronJob aktuell ausgeführt werden muss. Sie steuern damit also nicht direkt die Ausführung einer bestimmten Aktion, sondern starten den CronJob, der wiederum prüft, ob überhaupt Aufgaben anfallen, die erledigt werden müssen. Speziell wenn Sie Verhaltensweisen und Funktionen testen möchten, kann es praktisch sein, den CronJob manuell zu starten. So müssen Sie nicht immer auf die automatische Ausführung warten, die je nach Konfiguration fünf oder zehn Minuten betragen kann.

customer

Bezüglich der Kunden steht Ihnen ebenfalls nur ein Parameter bzw. eine Funktionsweise zur Verfügung. Hierbei handelt es sich um den Parameter customer:hash: upgrade, mit dem Sie die Hashes aktualisieren können, falls Sie Änderungen am Hash-Algorithmus vornehmen. Das kann beispielsweise dann nötig sein, wenn Sie von MD5 auf SHA1 wechseln bzw. Änderungen in diesem Bereich durchführen. In der Praxis werden Sie jedoch auf diese Funktionalität eher weniger zurückgreifen müssen.

deploy

Im Bereich »deploy« finden Sie zwei Befehle, die vor allem für Entwickler interessant sind. Magento verfügt über zwei Betriebsmodi. Sie können Magento in der Live- bzw. Entwicklungsvariante betreiben. Dadurch verhält sich das System unterschiedlich, und Sie haben auch andere Einstellungen bezüglich des Cachings und der Performance. Mithilfe des Parameters deploy:mode:set können Sie an dieser Stelle den Modus wechseln. Ergänzen müssen Sie den Parameter noch um den Wert, in welchen Modus Sie wechseln möchten. An dieser Stelle stehen Ihnen die beiden Werte production bzw. developer zur Verfügung.

Sollten Sie sich nicht sicher sein, in welchem Modus Sie sich aktuell befinden, können Sie sich diesen mittels des Parameters deploy:mode:show zurückgeben lassen. Haben Sie übrigens nach der Installation den Modus nicht geändert, werden Sie an dieser Stelle den Wert Default zurückgeliefert bekommen. Ein Default-Modus existiert so gesehen aber nicht, d. h., Sie können nicht in einen Default-Modus wechseln. Sobald Sie einmal den Modus gewechselt haben, müssen Sie sich immer zwischen den Modi production bzw. developer entscheiden.

dev

Wie der Name dieses Bereichs schon impliziert, sind hier vor allem Befehle und Funktionen für Entwickler gebündelt. Werfen Sie an dieser Stelle jedoch auch darauf einen Blick, einfach damit Sie wissen, was mit Magento möglich ist und welche Power in dem Magento CLI steckt.

Mithilfe des Parameters dev:source-theme:deploy können Sie sogenannte Symlinks für die LESS-Dateien erstellen. Die LESS-Dateien werden wiederum für die Generierung der CSS-Dateien, welche die Optik Ihres Magento-Systems steuern, benötigt. Haben Sie Unit Tests geschrieben, können Sie diese ebenfalls per Kommandozeile starten. Führen Sie hierfür den Befehl php bin/magento dev:tests:run aus. Daraufhin wird Magento alle im System vorhandenen Tests ausführen und Ihnen ein Feedback zurückgeben.

Ebenso interessant kann speziell für Entwickler die Funktion dev:urn-catalog:generate sein. Mithilfe dieses Befehls können Sie Mappings generieren, die Sie in Ihrer Entwicklungsumgebung, beispielsweise PhpStorm, nutzen können. Da der Befehl und die Möglichkeiten etwas komplexer sind, verweise ich Sie an dieser Stelle auf die offizielle Dokumentation, die Sie unter http://devdocs.magento.com/guides/v2.0/config-guide/cli/config-cli-subcommands-urn.html vorfinden. Dort sind die Möglichkeiten und Parameter recht gut und ausführlich inklusive Screenshots beschrieben. Ähnlich sieht es mit dem Befehl dev:xml:convert aus. Diese Funktion ist dafür zuständig, Ihre Layout-XML-Dateien in XLST-Dateien zu transformieren.

i18n

Der Abschnitt »i18n« handelt von der Lokalisierung und stellt Ihnen nützliche Funktionen und Möglichkeiten hinsichtlich der Sprachpakete bzw. des Umgangs mit Übersetzungen zur Verfügung.

Besonders interessant ist der Parameter i18n:collect-phrases, denn hiermit können Sie die Code-Basis durchsuchen und alle Übersetzungsstrings innerhalb des Terminals bzw. einer Datei ausgeben lassen. Damit identifizieren Sie also im Zweifelsfall, welche Wörter und Phrasen Sie übersetzen müssen. Wichtig ist an dieser Stelle, dass Sie weitere Parameter an den Befehl anfügen. Wenn Sie kein bestimmtes Verzeichnis, sondern die gesamte Magento-Instanz nach Phrasen durchsuchen möchten, nutzen Sie bitte den Parameter --magento. Auch ergibt eine Ausgabe in einer Datei und nicht innerhalb der Kommandozeile Sinn. Hierfür können Sie mit -o einen Pfad sowie eine Datei spezifizieren. Zusammengesetzt ergibt sich daraus der Befehl php bin/magento i18n:collect-phrases --magento -o /translation.csv. In diesem Szenario durchsucht Magento den kompletten Code und erstellt im Hauptverzeichnis eine Datei namens translation.csv, die alle zu übersetzenden Phrasen enthält. Im Prinzip sind dort alle Informationen enthalten, die Sie benötigen, um eine komplette Übersetzung des Systems vorzunehmen. In der Praxis müssen Sie dies an dieser Stelle nicht tun, da Sie bereits über ein Sprachpaket verfügen, aber als Basis für eine neue Sprache würde sich die generierte Datei definitiv eignen.

Wenn Sie hingegen ein Sprachpaket installieren bzw. einspielen möchten, steht Ihnen der Befehl i18n:pack zur Verfügung. Sie müssen auf eine Quelldatei verweisen und einen Sprachcode angeben, z. B. de_DE. Zudem können Sie bestimmen, was mit gegebenenfalls vorhandenen Übersetzungen passiert. Dafür steht der Modus zur Verfügung, der zwischen »replace« (ersetzen) und »merge« (zusammenführen) unterscheidet. Sie können also bestehende Übersetzungen bzw. Dateien ersetzen oder zusammenführen.

Bereits installierte Sprachpakete lassen sich zudem mittels i18n:uninstall deinstallieren. Als zusätzlichen Parameter müssen Sie an dieser Stelle noch das Package, d. h. den Namen des Sprachpakets, übermitteln.

indexer

Beim Indexer handelt es sich ebenfalls um eine Art Zwischenspeicher, da gewisse Informationen in Datenbanktabellen abgelegt werden, die regelmäßig aufgebaut werden müssen. Sind diese Tabellen nicht zu 100 % aktuell, können gegebenenfalls alte Informationen ausgelesen werden. Magento macht Sie im Backend immer darauf aufmerksam, sobald ein Index nicht aktuell ist, und bittet Sie um einen manuellen Aufbau. Oft erscheint diese Meldung jedoch nicht, da die verschiedenen Indexe automatisiert mittels CronJob sowie bei gewissen Speicheraktionen sowieso neu aufgebaut werden.

Wenn Sie wissen möchten, welche Indexe im Magento-System vorhanden sind, verwenden Sie bitte den Parameter indexer:info. Als Ergebnis werden Sie folgende Auflistung erhalten:

design_config_grid               Design Config Grid
customer_grid                    Customer Grid
catalog_category_product         Category Products
catalog_product_category         Product Categories
catalog_product_price            Product Price
catalog_product_attribute        Product EAV
cataloginventory_stock           Stock
catalogrule_rule                 Catalog Rule Product
catalogrule_product              Catalog Product Rule
catalogsearch_fulltext           Catalog Search

Listing 19.3    Ausgabe von »indexer:info«

In der ersten Spalte sehen Sie die interne Bezeichnung für den Index, in der zweiten und letzten Spalte den eigentlichen Namen.

Um die Indexe erneut aufzubauen bzw. zu aktualisieren, steht Ihnen der Parameter indexer:reindex zur Verfügung. Wenn Sie bin/magento samt diesem Parameter ausführen, wird der Reindexierungsprozess angestoßen, und die Indexe werden aktualisiert, anschließend würde auch die gegebenenfalls in Magento vorhandene Meldung diesbezüglich verschwinden.

Mithilfe des Parameters indexer:reset können Sie alle Indexe zurücksetzen, und Magento würde diese als alt bzw. invalid erkennen. Daraufhin könnten und müssten Sie den Reindexierungsprozess starten.

Wie ein paar Zeilen zuvor erwähnt, kennt Magento insgesamt zwei Modi, wie ein Index aktuell gehalten werden kann. Entweder wird der Index durch einen CronJob aktualisiert oder durch eine Speicheraktion. Beispielsweise könnten Sie immer dann, wenn Sie einen Kunden im Backend anlegen oder speichern, den Index für Kunden aufbauen lassen. Alternativ hierzu können Sie den Neuaufbau jedoch auch von einem CronJob in festen zeitlichen Abfolgen durchführen lassen. Den Modus, wie ein Index aktuell gehalten wird, definieren Sie mit dem Index-Modus. Diesen können Sie ebenfalls über die Kommandozeile steuern, indem Sie den Parameter indexer:set-mode verwenden. Ergänzen müssen Sie an dieser Stelle jedoch noch den Modus sowie den Index, werfen Sie hierzu erneut einen Blick in die weiter oben abgebildete Tabelle, wonach ein Kommando wie folgt aussehen muss: php bin/magento indexer:set-mode schedule customer_grid.

In diesem Fall habe ich mich dafür entschieden, den Customer Grid Index mittels CronJob, daher das Wort schedule, aufbauen zu lassen. Alternativ können Sie an dieser Stelle den Wert realtime verwenden, dadurch wird der Index immer nach dem Speichern eines Datensatzes erneuert. Welcher Index welchen Modus hat, können Sie sich übrigens mittels indexer:show-mode anzeigen lassen. Als Ergebnis erhalten Sie eine Auflistung aller im System vorhandenen Indexe samt dem hinterlegten Modus:

info

Der nächste Abschnitt mit dem Namen »info« liefert Ihnen – wer hätte es gedacht – in erster Linie Informationen zurück. Das heißt, hierin sind Befehle gruppiert, die nicht direkt Aktionen auslösen oder Ihr System verändern.

Nutzen Sie beispielsweise info:adminuri, so erhalten Sie den URI Ihres Backends zurückgemeldet. An sich kann dies schon recht praktisch sein, da Magento für die Backends mittlerweile kryptische URLs verwendet, d. h., Sie sollten in der Regel nicht via /admin auf das Backend kommen, auch wenn ich aus Gründen der Einfachheit in diesem Buch genau diesen URI verwendet habe. Normalerweise ist der URI jedoch ein wenig komplexer, und sollten Sie ihn vergessen haben, können Sie den URI mittels Kommandozeile erneut auslesen lassen.

Sollten Sie sich dafür interessieren, welche Backups im System vorhanden sind, so können Sie diese mittels info:backups:list auslesen. Ebenfalls können Sie sich mit info:currency:list die Liste aller Währungen, die im System vorhanden bzw. verfügbar sind, ausgeben lassen. Wenn Sie diesen Befehl ausführen, werden Sie die recht lange und unübersichtliche Liste der Währungen als Rückgabewert erhalten. Ich erspare Ihnen an dieser Stelle die detaillierte Auflistung, da es sich um knapp 300 Währungen handelt. Die Chance, dass auch Ihre Währung in Magento vorhanden ist, ist also definitiv gegeben.

Mithilfe der nächsten drei Parameter können Sie sich Abhängigkeiten innerhalb der Module bzw. des Magento-Systems anzeigen lassen. Den Anfang macht dabei der Befehl info:dependencies:show-framework. Übergeben Sie an dieser Stelle, auch wenn hier noch andere Parameter zur Verfügung stehen, idealerweise einen Speicherort, indem Sie den Parameter -o report.txt ergänzen. Daraufhin wird Magento im Hauptverzeichnis Ihrer Installation eine Datei namens report.txt anlegen, in die das Ergebnis geschrieben wird. Alle möglichen Parameter finden Sie übrigens auf http://devdocs.magento.com/guides/v2.0/config-guide/cli/config-cli-subcommands-depen.html, zusätzlich sind auf dieser Seite weitere Erklärungen zu diesem Befehl enthalten. So wie Sie sich die Abhängigkeiten von Magento anschauen können, können Sie zudem mit info:dependencies:show-modules bzw. info:dependencies:show-modules-circular weitere Reports generieren, die sich auf die installierten bzw. selbst entwickelten Erweiterungen beziehen. An und für sich werden Sie aber vermutlich nur dann, wenn Sie als Magento-Entwickler tätig sind, auf diese Informationen zurückgreifen. Als Shop-Administrator werden Ihnen diese Details an dieser Stelle recht wenig nützen.

Interessanter sind hingegen wieder die letzten beiden Parameter namens info:language:list sowie info:timezone:list. Ersterer liefert Ihnen eine Liste aller verfügbaren Sprachen. Beachten Sie an dieser Stelle aber, dass es sich nicht um die installierten Sprachen handelt, sondern um die Sprachen, die im Backend auswählbar sind. Das bedeutet jedoch nicht, dass für diese zwangsläufig ein Sprachpaket installiert ist. Auch bei den Zeitzonen, es handelt sich um den letzteren Befehl, erhalten Sie eine Liste. Inkludiert sind alle möglichen Zeitzonen, die Sie im Magento-Backend auswählen können.

maintenance

Den Wartungsmodus von Magento haben Sie bereits in Kapitel 16, »Datensätze exportieren und importieren«, kennengelernt. Wenn Sie eine Sicherung von Magento durchführen, können Sie im gleichen Zug den Wartungsmodus aktivieren. Jedoch haben Sie auch die Möglichkeit, den Wartungsmodus ganz unabhängig von einer Datensicherung zu aktivieren. Das ist beispielsweise dann sinnvoll, wenn Sie eine Erweiterung installieren, ein Deployment durchführen bzw. am System arbeiten und in dieser Zeit die Benutzer aussperren möchten.

Damit Sie sich bei aktiviertem Wartungsmodus nicht selbst aussperren, können Sie mittels maintenance:allow-ips IP-Adressen hinterlegen, die auf das System trotz Wartungsmodus zugreifen dürfen. Als zusätzlichen Wert müssen Sie an dieser Stelle noch die erlaubte IP-Adresse übermitteln, wodurch der Befehl wie folgt aussieht: php bin/magento maintenance:allow-ips 127.0.0.1. Ruft ein Benutzer mit dieser IP-Adresse das Magento-System auf, wird er trotz Wartungsmodus darauf zugreifen können.

Mithilfe der Befehle maintenance:disable sowie maintenance:enable können Sie den Wartungsmodus deaktivieren bzw. aktivieren. Ist der Wartungsmodus aktiviert und die eigene IP-Adresse nicht freigeschaltet, so werden Sie eine Ansicht wie in Abbildung 19.2 erhalten.

Abbildung 19.2    Ist der Wartungsmodus aktiv, kann weder auf das Frontend noch auf das Backend zugegriffen werden.

Sollten Sie sich übrigens nicht sicher sein, ob der Wartungsmodus aktiviert bzw. deaktiviert ist, können Sie mit dem Befehl maintenance:status den aktuellen Status auslesen. Magento gibt Ihnen in diesem Fall den Status, sowie die freigeschalteten IP-Adressen zurück. Speziell die Auflistung der freigeschalteten IP-Adressen finde ich persönlich sehr hilfreich, denn Sie sehen sofort, wer trotz aktiviertem Wartungsmodus Zugriff auf das Magento-System hat.

Status: maintenance mode is active
List of exempt IP-addresses: 127.0.0.1

Listing 19.6    Neben dem Status sehen Sie die freigeschalteten IP-Adressen.

module

Im nächsten Punkt namens »module« können Sie die installierten Erweiterungen, auch Module genannt, steuern bzw. verwalten. Wenn Sie beispielsweise ein Modul installiert haben, das anschließend zu Problemen führt, haben Sie die Möglichkeit, dieses mittels Kommandozeile und des Parameters module:disable zu deaktivieren. Sie müssen jedoch an dieser Stelle noch den Namen des Moduls angeben. Alternativ können Sie mit --all alle vorhandenen Module deaktivieren, das ist meiner Meinung nach aber weniger ratsam. Wie Sie an die Namen der Module kommen, um gezielt bestimmte zu deaktivieren, erfahren Sie ein paar Zeilen weiter.

So wie Sie Module deaktivieren können, haben Sie auch die Möglichkeit, Module zu aktivieren. Hierfür steht Ihnen der Parameter module:enable zur Verfügung, der ebenfalls um den Namen des Moduls ergänzt werden muss.

An die Namen der Module kommen Sie mittels module:status recht einfach heran. Führen Sie bin/magento mit diesem Parameter aus, erhalten Sie als Rückgabe eine umfangreiche Liste, in der alle installierten Module enthalten sind. Magento differenziert an dieser Stelle zudem zwischen aktivierten und deaktivierten Modulen. Sie können sich also recht einfach ausgeben lassen, welche Module momentan aktiv bzw. inaktiv sind.

Zu guter Letzt könnten Sie zudem Module direkt per Kommandozeile deinstallieren. Nutzen Sie hierfür den Parameter module:uninstall, und ergänzen Sie diesen um den Modulnamen. Magento wird anschließend die Deinstallation des Moduls vornehmen.

Uninstall nur bei Modulen möglich, die per Composer installiert wurden

Mithilfe des Befehls uninstall können Sie nur Module deinstallieren, die per Composer installiert wurden. Kopieren Sie daher einfach ein Zip-Archiv bzw. eine Ordnerstruktur in die Magento-Instanz, können Sie diese nicht per Kommandozeile deinstallieren. Nutzen Sie bei der Installation Composer, ist eine Deinstallation per Kommandozeile hingegen möglich.

sampledata

Magento besitzt von Haus aus Beispieldaten, die Sie in Ihrem Online-Shop installieren können. Hierzu zählen Produkte, Kategorien, Bestellungen etc. Die Beispieldaten sind immer dann praktisch, wenn Sie – in der Regel zu Testzwecken – schnell einen Magento-Online-Shop aufsetzen und mit Daten befüllen möchten. So sparen Sie sich die manuelle Arbeit der Datenpflege und können stattdessen die bereits vorhandenen Beispieldaten nutzen.

Um diese zu installieren – Sie können das theoretisch auch noch zum jetzigen Zeitpunkt, auch wenn ich Ihnen davon abrate, da ansonsten ein Datenchaos entstehen könnte –, führen Sie einfach den Befehl php bin/magento sampledata:deploy aus. Haben Sie das getan, müssen Sie zudem, um die Installation abzuschließen, noch diesen Befehl ausführen: php bin/magento setup:upgrade. So wie Sie Beispieldateien installieren können, haben Sie zudem die Möglichkeit, diese zu entfernen, wozu Sie den Parameter sampledata:remove nutzen können. Geht etwas schief bzw. haben Sie Probleme nach der Installation der Beispieldaten, können Sie zudem mittels sampledata:reset das Package zurücksetzen und die Beispieldaten erneut installieren.

Im laufenden Betrieb sollten Sie von der Installation der Beispieldaten abgesehen, da wild Daten zum System hinzugefügt werden, die wirklich nur zu Testzwecken verwendet werden können. Nutzen Sie aber, sollten Sie etwas Zeit haben, die Möglichkeit, ein zweites Magento-System zu installieren, und fügen Sie in diesem die Beispieldaten hinzu. Dann haben Sie zumindest die Installation einmal durchlaufen und sehen, was Magento an dieser Stelle alles an Informationen zur Verfügung stellt.

setup

Der folgende Abschnitt namens »setup« gruppiert primär Funktionen und Möglichkeiten, mit denen Sie Module installieren bzw. Upgrades am System durchführen können. Daher sollten Sie, wenn Sie nebenher mit dem einen oder anderen Befehl experimentieren, an dieser Stelle besonders vorsichtig sein. Sicherlich möchten Sie nicht Ihr mühsam aufgebautes System durch eine Unachtsamkeit zerstören!

Damit Sie im Zweifelsfall eine Sicherung haben, denn kaputt gehen kann immer mal etwas, steht Ihnen der Befehl setup:backup zur Verfügung. Damit können Sie, der Name verrät es bereits, ein Backup des Systems erstellen. Als weitere Parameter müssen Sie jedoch noch übergeben, was Sie eigentlich sichern möchten. Wollen Sie eine Komplettsicherung anlegen, rufen Sie bitte den Befehl php bin/magento setup:backup --code --media --db auf. Möchten Sie nur eine Sicherung des Codes erstellen, würden Sie die beiden letzten Parameter entfernen. Die Bedeutung der Parameter an sich sollte an dieser Stelle jedoch recht einfach zu durchschauen sein. Neben der Sicherung des Codes können Sie das Medienverzeichnis sowie die Datenbank sichern. Je nach Größe Ihres Systems kann die Sicherung an dieser Stelle einige Zeit in Anspruch nehmen, testen Sie aber gern den Sicherungsprozess. Ich persönlich finde das Handling per Kommandozeile wesentlich einfacher und effizienter als innerhalb des Backends.

Wenn Sie Konfigurationseinstellungen ändern möchten, zugegebenermaßen auf einer recht technischen Ebene, können Sie dies mit dem nächsten Befehl namens setup:config:set vornehmen. Gemeint sind an dieser Stelle jedoch weniger Konfigurationseinstellungen wie die Shop-URL, sondern vielmehr Dinge wie die Datenbankverbindungsdaten oder der Encryption-Key. Insgesamt haben Sie die Möglichkeit, die folgenden Konfigurationsparameter mithilfe der Kommandozeile abzuändern:

backend-frontname       Backend frontname (will be autogenerated if missing)
key                     Encryption key
session-save            Session save handler
definition-format       Type of definitions used by Object Manager
db-host                 Database server host
db-name                 Database name
db-user                 Database server username
db-engine               Database server engine
db-password             Database server password
db-prefix               Database table prefix
db-model                Database type
db-init-statements      Database  initial set of commands
skip-db-validation (-s) If specified, then db connection validation will be skipped
http-cache-hosts        http Cache hosts
magento-init-params     Add to any command to customize Magento initialization parameters example: "MAGE_MODE=developer&MAGE_DIRS[base][path]=/var/www/example.com&MAGE_DIRS[cache][path]=/var/tmp/cache"

Listing 19.7    Konfigurationseinstellungen lassen sich direkt per Kommandozeile setzen.

Die jeweiligen Konfigurationseinstellungen und Werte können Sie als zusätzliche Parameter übergeben. Daraus ergeben sich Befehle wie z. B. php bin/magento setup:config:set --backend-frontname admin. Sobald Sie übrigens einen Wert setzen möchten, fragt Sie Magento, ob Sie den bestehenden Wert tatsächlich überschreiben möchten. Aus Unachtsamkeit können Sie daher auch an dieser Stelle keine Optionen abändern.

Möchten Sie die CronJobs ausführen, die primär bei der Installation bzw. beim Upgrade von Magento benötigt werden, steht Ihnen der Parameter setup:cron:run zur Verfügung. Hierbei handelt es sich um den nächsten Befehl, den Sie ohne zusätzlichen Parameter ausführen können.

Speziell wenn Sie Magento upgraden bzw. eine Extension installiert haben, kann es vorkommen, dass Sie die Befehle setup:db-data:upgrade bzw. setup:db-schema: upgrade ausführen müssen. Sollten nämlich aufgrund einer neuen Magento-Version bzw. aufgrund von Extensions Änderungen an der Datenbank durchgeführt werden müssen, können Sie mit diesen beiden Befehlen sowohl die Daten als auch das Schema übernehmen. In der Praxis, außer Sie müssen diese Befehle explizit ausführen, werden Sie diese beiden jedoch nicht benötigen. Ob Sie diese Befehle ausführen müssen, können Sie übrigens testen, indem Sie php bin/magento setup:db:status aufrufen. Im Idealfall erhalten Sie, wie ich zum aktuellen Zeitpunkt, die Meldung »All modules are up to date«.

Je nachdem, in welchem Modus Sie Magento betreiben – es gibt den Entwicklungs- und den Live-Modus – müssen Sie gegebenenfalls den Befehl setup:di:compile ausführen. Magento setzt mittlerweile an vielen Stellen auf kompilierte bzw. generierte Dateien. Wenn sich etwas am System ändert, sei es durch eine neue Erweiterung oder durch Änderungen, so können Sie mithilfe dieses Befehls benötigte Dateien generieren bzw. nicht mehr benötigte Dateien entsorgen. Der Schritt ist recht arbeitsintensiv, weshalb Sie vermutlich in ein Memory-Limit-Problem laufen. Daher empfiehlt es sich, den Befehl direkt mit einem höheren Limit auszuführen: php -d memory_limit=2048M bin/magento setup:di:compile. Magento generiert die Dateien und gibt eine Erfolgsmeldung aus, Sie sehen das ansatzweise in Abbildung 19.3.

Abbildung 19.3    Magento generiert eine Vielzahl von Dateien, wenn Sie die Kompilierung starten.

In Kapitel 3, »Magento installieren«, haben Sie die verschiedenen Installationsmöglichkeiten kennengelernt. Eine Option, Sie finden diese im nächsten Befehl, ist die Installation von Magento mittels Magento CLI. Hierfür steht der Befehl setup:install zur Verfügung, den Sie jedoch um eine Vielzahl von Parametern ergänzen müssen. Insgesamt stehen hierfür die folgenden Parameter zur Verfügung, die Sie beim Aufruf mit Werten versorgen müssen:

setup:install [--backend-frontname="..."] [--key="..."] [--session-save="..."] [--definition-format="..."] [--db-host="..."] [--db-name="..."]  
[--db-user="..."] [--db-engine="..."] [--db-password="..."] [--db-prefix="..."] [--db-model="..."] [--db-init-statements="..."] [-s|--skip-db-validation] [--http-cache-hosts="..."] [--base-url="..."] [--language="..."]  
[--timezone="..."] [--currency="..."] [--use-rewrites="..."]

[--admin-use-security-key="..."] [--admin-user="..."] [--admin-password="..."] [--admin-email="..."] [--admin-firstname="..."] [--admin-lastname="..."] [--cleanup-database] [--sales-order-increment-prefix="..."]  
[--use-sample-data] [--magento-init-params="..."]

Würden Sie daher den Befehl erneut samt den benötigten Parametern ausführen, so könnten Sie Magento mittels der CLI installieren. An dieser Stelle rate ich aber von einem Test ab, auch wenn es Ihnen in den Fingern kribbeln mag. Denn Sie würden vermutlich Ihre existente Basis damit zerstören und hätten anschließend kein funktionsfähiges System mehr.

Beim nächsten Befehl handelt es sich wiederum um eine Option, die vor allem für Entwickler interessant sein dürfte. Magento kann sogenannte Fixtures erstellen, die Sie beispielsweise bei der Nutzung von jMeter benötigen. Mit jMeter können Sie die Performance des Online-Shops durch einen simulierten Benutzertest überprüfen. Um die Fixtures zu generieren, nutzen Sie bitte den Parameter setup:performance: generate-fixtures, und ergänzen Sie diesen um den Pfad zum Profil, das angegeben werden muss.

So wie Sie Sicherungen erstellen können, können Sie Sicherungen auch wieder einspielen. Hierfür nutzen Sie den Parameter setup:rollback. Bei diesem Befehl können und sollten Sie zudem mittels Parameter den Pfad zur Code-Sicherung, Mediaverzeichnis-Sicherung sowie Datenbank-Sicherung angeben, da Sie diese drei Elemente, die Sie sichern, mit diesem Befehl auch wieder einspielen können. Sind Sie sich an dieser Stelle übrigens nicht sicher, welche Daten Sie wieder einspielen können, so hilft der Befehl php bin/magento info:backup:list weiter. Führen Sie diesen aus, erhalten Sie eine Ausgabe wie in Abbildung 19.4, und Sie sehen direkt, welche Sicherungen Sie einspielen können. Wichtig sind an dieser Stelle speziell die Dateinamen, da Sie sich beim Rollback auf diese beziehen müssen.

Abbildung 19.4    Mit dem Befehl »info:backup:list« können Sie sich alle vorhandenen Sicherungen anzeigen lassen.

Da Magento speziell für das Frontend viele Dateien erzeugen muss, hierzu zählen CSS- sowie JavaScript-Dateien, aber auch Grafiken, gibt es für die manuelle Erzeugung dieser Elemente einen eigenen Befehl namens setup:static-content:deploy. Manche Module benötigen die Ausführung dieses Befehls nach einer erfolgreichen Installation, in der Regel wird dann aber in der Installationsanweisung darauf verwiesen. Beachten Sie, dass auch bei diesem Befehl weitere Parameter zur Verfügung stehen, die Sie gegebenenfalls nutzen müssen. So können bzw. sollten Sie immer die Sprache angeben, da je Sprachdatei die Dateien erzeugt werden müssen. Auch können Sie das verwendete Theme als Parameter mitsenden. Werfen Sie idealerweise, wenn Sie mit diesem Befehl arbeiten müssen, einen Blick in die Dokumentation unter http://devdocs.magento.com/guides/v2.1/config-guide/cli/config-cli-subcommands-static-view.html. Geben Sie keine Sprache an, wird als Default immer die amerikanische Version verwendet, wie Sie auch in Abbildung 19.5 sehen.

Fehlende Dateien im Frontend und Backend?

Wenn im Frontend bzw. Backend CSS-, JavaScript- oder Grafik-Dateien nicht geladen werden können, hilft oftmals die Ausführung von setup:static-content:deploy. Denn Magento erzeugt daraufhin alle benötigten Dateien erneut und legt diese korrekt ab. Danach sollten diese auch im Frontend bzw. Backend aufgerufen werden können.

Das Magento CLI ermöglicht Ihnen Optionen wie z. B. die Datenbankverbindungsdaten zu setzen. Mit dem Befehl setup:store-config:set können Sie zudem auch direkt Optionen, die Magento an sich betreffen, setzen. Mögliche Optionen hierbei lauten:

base-url                URL the store is supposed to be available at
language                Default language code
timezone                Default time zone code
currency                Default currency code
use-rewrites            Use rewrites
use-secure              Use secure URLs. Enable this option only if SSL is  
                        available.
base-url-secure         Base URL for SSL connection
use-secure-admin        Run admin interface with SSL
admin-use-security-key  Whether to use a "security key" feature in Magento  
                        Admin URLs and forms
magento-init-params     Add to any command to customize Magento  
                        initialization parameters

Listing 19.8    Diese Parameter können übergeben werden.

Wie Sie sehen, können Sie also die Währungseinstellungen, die Basis-URL oder auch die Zeitzone setzen. Zugegebenermaßen handelt es sich dabei um interessante Möglichkeiten, allerdings sind die Konfigurationsoptionen doch sehr stark limitiert. Wenn Sie sich einmal in Erinnerung rufen, welche Optionen Sie innerhalb des Backends setzen können, dann sind die mit diesem Befehl möglichen Optionen doch sehr begrenzt.

Da Sie Magento per Kommandozeile installieren können, können Sie es dort auch deinstallieren. Hierfür steht der Parameter setup:uninstall zur Verfügung. Sehen Sie an dieser Stelle aber von einem Test ab und geben Sie Ihrer Magento-Instanz noch eine weitere Chance …

Neben dem Befehl für die Installation bzw. Deinstallation von Magento steht Ihnen zudem noch ein Upgrade-Befehl zur Verfügung. Führen Sie für die Nutzung den Befehl php magento/bin setup:upgrade aus. Sollten aktuellere bzw. neuere Dateien vorhanden sein und sollte ein Upgrade möglich sein, wird Magento es bei Ausführung dieses Befehls einspielen.

theme:uninstall

Neben den Modulen und Magento an sich können Sie mittels CLI zudem Themes deinstallieren. Hierfür steht Ihnen der Parameter theme:uninstall zur Verfügung, den Sie jedoch um den Namen des Themes ergänzen müssen. Weitere und detaillierte Informationen hierzu erhalten Sie unter http://devdocs.magento.com/guides/v2.0/install-gde/install/cli/install-cli-theme-uninstall.html.

Erweiterung durch Extensions möglich

Die Befehle, die Ihnen zur Verfügung stehen, können übrigens durch Extensions erweitert werden. Es hängt dabei ganz von der Extension und der implementierten Funktionalität ab, ob zusätzliche Befehle innerhalb des Magento Command Line Interfaces bereitstehen. Im Falle des Wyomind Data Feed Managers beispielsweise, den Sie in Kapitel 21 näher kennenlernen werden, stehen Befehle zur Verfügung. Diese erlauben Ihnen, Datenfeeds zu generieren bzw. bestehende Datenfeeds aufzulisten.

Magento bietet mit dem Command Line Interface ein doch beachtliches und umfangreiches Tool, das Sie mithilfe der Kommandozeile nutzen können. Durch die Kommandozeile können Sie viele alltägliche Aufgaben recht schnell durchführen, da Sie sich nicht immer zuerst am Backend anmelden und durch die verschiedenen Masken klicken müssen. Daher ist das CLI eine sehr sinnvolle Ergänzung zum Magento-Backend.

19.1.2    Wann Sie zur CLI greifen sollten und wann nicht

Mit dem Magento Command Line Interface kann man eine ganze Menge an Dingen anstellen, angefangen vom Setzen der Zugangsdaten für eine Datenbankverbindung bis hin zur Installation von Magento. In der Praxis empfehle ich Ihnen vor allem die Nutzung der Cache-, Index- und Deploy- bzw. Compile-Funktionalität. Denn diese Dinge werden Sie in der Praxis häufig brauchen, und hierfür bietet sich die Kommandozeile in der Tat an. Ob Sie tatsächlich Dinge wie z. B. die Base-URL per Kommandozeile setzen müssen, wage ich zu bezweifeln. Nur weil Sie die Möglichkeit haben, müssen Sie diese nicht zwangsläufig nutzen.

Aus diesem Grund betrachte ich persönlich das CLI-Tool differenziert. Einige Funktionen ergeben tatsächlich Sinn und sollten genutzt werden, andere haben den Anschein, aus Gründen der Feature-Anzahl implementiert worden zu sein, wobei eine Nutzung in der Praxis einfach nicht komfortabel bzw. ratsam ist. Machen Sie sich an dieser Stelle aber Ihr eigenes Bild, und finden Sie für sich heraus, welche Möglichkeiten des CLI-Tools Sie nutzen und welche Sie direkt über das Magento-Backend ausführen.
