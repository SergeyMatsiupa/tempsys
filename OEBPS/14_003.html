14.3    Die Darstellung des Frontends individualisieren

Neben der Erweiterung des Magento-Systems mithilfe von Extensions können Sie zudem Ihr Magento-System individualisieren, indem Sie es optisch verändern. Magento unterscheidet grundsätzlich zwischen Extensions, die den Funktionsumfang erweitern und zusätzliche Möglichkeiten bereitstellen, und Themes, die ausschließlich die Optik des Frontends verändern. In Magento-Projekten wird in der Regel auf beides zurückgegriffen. Zum einen wird der Funktionsumfang erweitert, bzw. vorhandene Funktionen werden modifiziert, und auf der anderen Seite wird die Optik des Frontends angepasst und individualisiert. In diesem Abschnitt möchte ich Ihnen zeigen, wie auch Sie Ihr Magento-System optisch modifizieren und individualisieren können. Dabei zeige ich Ihnen die Möglichkeiten, die Ihnen Magento im Standard bietet, und möchte ich Ihnen zudem noch im Detail erläutern, wie Sie auf Basis eines Themes, das Sie kostenpflichtig oder kostenlos erwerben können, die Optik des Frontends verändern können.

14.3.1    Das Magento-Standard-Theme anpassen

Magento wird von Haus aus mit zwei verschiedenen Themes ausgeliefert, wovon Sie eines schon kennen, da Sie bereits mehrere Berührungspunkte mit dem Frontend hatten. Melden Sie sich bitte an dieser Stelle mit Ihren persönlichen Zugangsdaten am Magento-Backend an, und klicken Sie auf Inhalt • Design • Themes. Daraufhin sehen Sie eine Tabelle mit insgesamt zwei Einträgen. Hierbei handelt es sich um die beiden im Standard vorhandenen Themes namens Magento Luma sowie Magento Blank. Das Luma-Theme wird standardmäßig im Frontend geladen, hierbei handelt es sich also um das Theme, das Sie bereits kennengelernt haben.

Frontend-Theme wechseln

Wenn Sie im Frontend ein anderes Theme verwenden möchten, klicken Sie auf Inhalt • Design • Konfiguration. An dieser Stelle erhalten Sie eine Auflistung aller Store Views, da Sie pro Store View ein unterschiedliches Theme verwenden können. An dieser Stelle sollten Sie noch nicht ganz so viele Einträge haben, wenn Sie im nächsten Kapitel jedoch verschiedene Websites, Stores und Store Views anlegen, wird sich die Liste entsprechend erweitern. Klicken Sie beim Eintrag Default in der Tabelle auf den Link bearbeiten. Sie landen daraufhin in einer neuen Oberfläche, in der Sie direkt als erste Option das Dropdown-Menü Applied Theme vorfinden. Wählen Sie aus der Liste den Eintrag Magento Blank aus, und speichern Sie die Konfiguration. Denken Sie bitte anschließend daran, den Magento-Cache zu leeren. Wenn Sie nun das Frontend aufrufen, werden Sie eine komplett neue Oberfläche vorfinden, Sie sehen das bei mir in Abbildung 14.17. Zugegebenermaßen ist das Magento-Blank-Theme recht ähnlich wie das Luma-Theme, was daran liegt, dass Luma auf Blank aufbaut.

Abbildung 14.17    Mit dem Blank-Theme sieht das Magento-Frontend direkt anders aus.

Große Unterschiede bestehen vor allem im Header- und Footer-Bereich, die im Blank-Theme recht leer und kahl wirken. Das ist an dieser Stelle jedoch beabsichtigt, da das Blank-Theme als eine Art Vorlage und Grundlage für eigene und individuelle Themes dienen soll. Daher ist das Blank-Theme so spartanisch wie nur möglich gehalten, damit Sie bei der Nutzung und Weiterentwicklung nicht zu viele Stellen zurückbauen müssen. Nichtsdestotrotz unterstützt das Blank-Theme alle Funktionen und Möglichkeiten, d. h. sowohl der Checkout-Prozess als auch das Benutzerkonto sind voll funktionsfähig und könnten genutzt werden.

Stellen Sie an dieser Stelle bitte wieder das Theme zurück, und verwenden Sie für Ihr Frontend das Magento-Luma-Theme, da ich Ihnen nun verschiedene Konfigurationsoptionen und Möglichkeiten zeigen möchte, die im Backend bereitgestellt werden.

Das Frontend mithilfe von Backend-Konfigurationseinstellungen anpassen

Auch wenn die Möglichkeiten eher rudimentär sind, so können Sie innerhalb des Magento-Backends gewisse Konfigurationseinstellungen setzen, damit Ihr Frontend etwas individualisierter und angepasster wirkt.

Begeben Sie sich erneut in das Magento-Backend, und klicken Sie bitte auf Inhalt • Design • Konfiguration. Die Auflistung, die Sie nun erhalten, kennen Sie bereits aus vorherigen Beispielen. Wählen Sie auch an diesem Punkt erneut den Eintrag Default aus, und klicken Sie auf den Link Bearbeiten. Anschließend landen Sie in der Bearbeitungsmaske, die Sie in Abbildung 14.18 sehen.

Abbildung 14.18    Magento erlaubt die stellenweise Individualisierung des Themes innerhalb des Backends.

Mithilfe dieser Eingabemaske haben Sie die Möglichkeit, verschiedenste Einstellungen vorzunehmen, die sich direkt oder indirekt auf das Frontend auswirken. Im ersten Schritt, das haben Sie bereits auf der vorherigen Seite gesehen, können Sie dem Store View ein Theme zuweisen. Wenn Sie weitere Themes installieren, stehen diese an dieser Stelle ebenfalls zur Verfügung. Im Standard haben Sie die Wahl zwischen dem Magento-Luma- sowie dem Magento-Blank-Theme. Die Wahl des Themes können Sie übrigens auch an den User-Agent koppeln. Beispielsweise lässt sich dadurch einem Nutzer mit dem Mozilla Firefox ein anderes Theme als einem Google-Chrome-Nutzer zuweisen. Auf dem Desktop ergibt das nicht so viel Sinn, wenn Sie jedoch ein spezielles Theme für Smartphones entwickelt bzw. installiert haben, so könnte diese Funktion an dieser Stelle tatsächlich nützlich sein. Denn dann würden Sie allen mobilen User-Agents das Mobile-Theme zuweisen, die restlichen Nutzer erhalten hingegen das Desktop-Theme. In der Praxis, das möchte ich Ihnen an dieser Stelle nicht verschweigen, wird diese Funktion jedoch erfahrungsgemäß recht selten bis gar nicht genutzt. Im Zeitalter der Responsive-Designs ist es nicht zwangsläufig notwendig, eine Differenzierung der Themes anhand der Endgeräte durchzuführen. Jeder Nutzer kann auf dasselbe Theme zurückgreifen, das sich wiederum automatisch an das verwendete Endgerät anpasst. Ein Responsive-Design macht diese Funktion daher so gut wie obsolet.

Scrollen Sie jetzt bitte weiter nach unten, bis Sie zum Abschnitt Andere Einstellungen gelangen. Dort können Sie im ersten Schritt allgemeine Einstellungen zur Seitennummerierung vornehmen. Bei der Seitennummerierung handelt es sich um die Blätternavigation, die Sie auf der Kategorieseite vorfinden. Immer wenn es mehr Produkte in einer Kategorie gibt, als angezeigt werden können, bietet Magento eine Blätternavigation an. In der Option Seitennummerierungsrahmen definieren Sie, wie viele Links in der Blätternavigation angezeigt werden sollen. Der Standardwert liegt bei 5, so weit ist diese Option auch vollkommen in Ordnung. Mit der nächsten Option namens Seitennummerierungsrahmen überspringen können Sie einstellen, wie viele Seiten in der Blätternavigation, ausgehend von der von Ihnen aktuell ausgewählten Position, übersprungen werden sollen, bis die nächsten Seiten angezeigt werden. Sind Sie z. B. auf Seite 5 von 20, so können Sie mit dieser Option einstellen, dass nach der 5 nicht sofort die 6 oder 7 erscheint, sondern erst die Seite 10 oder 11. Abschließend können Sie zudem noch Alt-Tags, d. h. primär für Suchmaschinen relevante HTML-Auszeichnungen, für die vorherigen und nächsten Seiten hinterlegen. Hierfür stehen Ihnen die beiden Optionen Ankertext für vorherige Seite sowie Ankertext für nächste Seite zur Verfügung. Beispielsweise können Sie an diesen Stellen den Wert »Nächste Seite« bzw. »Vorherige Seite« hinterlegen. Eine direkte Auswirkung auf die Darstellung hat diese Information jedoch nicht, d. h., es wird kein zusätzlicher Text im Frontend bei der Blätternavigation ausgegeben.

Blättern Sie bitte weiter, bis Sie zum Abschnitt HTML-Kopf gelangen. Sofern Sie ein Favicon hochladen möchten, können Sie dies im Feld Favicon-Icon tun. Beim Favicon handelt es sich um das kleine Icon, das Sie in der URL-Leiste Ihres Browsers sehen. In der Regel können Sie an dieser Stelle nicht das gesamte Logo hinterlegen, sondern lediglich einen Ausschnitt bzw. eine Grafik, die in Ihrem Logo vorkommt. Magento erlaubt an dieser Stelle den Upload von Dateien im ico-, png-, gif-, jpg-, jpeg‐, apng- sowie svg-Format. Neben dem Hochladen des Favicons erlaubt Ihnen Magento in den nächsten Feldern die Definition von Metaangaben, die im Standard geladen werden. Der Standardtitel wird immer dann ausgegeben, wenn Sie einer Seite keinen Titel zuweisen. Der Titel erscheint nicht direkt im Frontend, wird jedoch im Browser als Bezeichnung des Tabs dargestellt. Daher sollten Sie bei allen Ihren Seiten einen Titel hinterlegen. Ergänzend zum Titel können Sie ein Präfix bzw. Suffix hinterlegen. Mit diesen beiden Optionen wird jeder Titel, egal, ob es sich um einen Standardtitel oder einen individuell hinterlegten Titel handelt, ergänzt. Wenn Sie beim Präfix den Wert »Online-Shop - « hinterlegen und beim Präfix » - foodbaer.de« würde im Frontend der Titel der Startseite wie folgt aussehen: Online-Shop – Home Page – foodbaer.de. Das Präfix, so zumindest meine Erfahrung, wird im Allgemeinen nicht verwendet. Interessant ist jedoch das Suffix, denn in der Regel wird an dieser Stelle der Unternehmensname ergänzt, wodurch in jedem Titel innerhalb des Online-Shops der Name Ihres Unternehmens enthalten ist.

Meta-Tag-Standardwerte über das Magento-Backend definieren

Mit dem Standardtitel definieren Sie den Standardwert für das Feld <title>, mit dem Feld Standardbeschreibung beeinflussen Sie die Metainformation <meta name="description"> und mittels Standard-Schlüsselworte das Meta-Tag <meta name="keywords">. Dadurch haben Sie auf alle relevanten Meta-Tags Zugriff und können hierfür Standardwerte hinterlegen.

Zusätzlich zum Titel können Sie zudem Standardwerte für die Metainformationen description sowie keywords setzen. Hierfür stehen Ihnen die Felder Standardbeschreibung sowie Standard-Schlüsselworte zur Verfügung. Wie Sie in Abbildung 14.19 sehen, hat Magento in diesen Feldern bereits Werte hinterlegt. Die sollten Sie vor der Inbetriebnahme Ihres Online-Shops definitiv anpassen, da die Werte an verschiedenen Stellen in Ihrem System ausgelesen werden. Wenn Sie auf einer Seite, die Sie mit dem Content-Management-System erstellt haben, keine Beschreibung und Schlüsselwörter hinterlegen, werden automatisch die Standardwerte verwendet. Dies sollte jedoch vermieden werden, da diese nicht wirklich Sinn ergeben. Hinterlegen Sie daher an dieser Stelle eine auf Ihren Online-Shop zutreffende Standardbeschreibung sowie Standard-Schlüsselwörter. Über den Bereich Scripts and Style Sheets, dabei handelt es sich um das nächste Eingabefeld, das Sie sehen, wenn Sie ein wenig nach unten scrollen, können Sie z. B. CSS-Dateien oder auch Tracking-Lösungen wie Google Analytics oder econda integrieren. Im Verlauf des Buches haben Sie das Feld bereits kennengelernt und dort die Google Site Verification integriert, die Sie auch in Abbildung 14.19 sehen. Sie können dieses Feld grundsätzlich dazu nutzen, um Inhalte vor dem schließenden Head-Tag einzubinden und zu platzieren.

Abbildung 14.19    Im Magento-Backend können Sie Standardwerte für alle Metainformationen setzen.

Den Demo-Modus Ihres Online-Shops können Sie zudem in der nächsten Option mit dem Titel Demoshop-Nachricht anzeigen aktivieren bzw. deaktivieren. Ist der Demo-Modus aktiviert, wird Magento auf jeder Seite im Kopfbereich einen recht prominenten roten Balken darstellen, der auf den Demo-Modus des Online-Shops hinweist. Besuchern und potenziellen Kunden wird somit angezeigt, dass in diesem Online-Shop zwar eingekauft werden kann, die Ware jedoch nicht ausgeliefert wird, da es sich um ein Demo-System handelt. Zusammengefasst lässt sich sagen, dass im Abschnitt HTML-Kopf primär Metainformationen sowie Skripte hinterlegt werden. Einen direkten Einfluss auf die Darstellung haben diese Optionen nicht.

Begeben Sie sich jetzt bitte zum nächsten Abschnitt namens Kopfzeile. Mit den dort vorhandenen Optionen haben Sie direkten Einfluss auf das Logo, das im oberen Bereich der Seite angezeigt wird. Mit der Option Logobild können Sie im ersten Schritt ein Logo hochladen. Berücksichtigen Sie beim Upload die erlaubten Dateitypen. Sofern Ihre Logo-Datei die Endung .png, .gif, .jpg, .jpeg bzw. .svg trägt, können Sie diese problemlos hochladen. Sofern Sie manuell auf die Größe des Logos einwirken möchten, können Sie die Höhe und Breite manuell festlegen. Legen Sie die Breite und Höhe nicht manuell fest, wird das Logo einfach in der hochgeladenen Größe dargestellt. Zur Verfügung stehen Ihnen für die manuelle Angabe der Größen die Felder Logo-Bildbreite bzw. Logo-Bildhöhe. Je nach gewähltem Theme gibt Magento im Kopfbereich einen Willkommenstext aus. Im Luma-Theme befindet sich der Willkommenstext direkt am Anfang der Seite neben dem Login- bzw. Registrieren-Link. Möchten Sie den Willkommenstext ändern bzw. entfernen, so können Sie dies im Feld Willkommenstext tun. Abschließend haben Sie noch die Möglichkeit, im Feld Logobild-Alt das Alt-Attribut des Logos zu setzen. Laden Sie an dieser Stelle, sollten Sie es noch nicht getan haben, Ihr Logo hoch. Die Proportionen bzw. Größe müssen Sie normalerweise nicht anpassen, wenn Sie das Logo in einer vernünftigen Größe hochladen. Den Willkommenstext können Sie in der Regel entfernen, und beim Alt-Tag Ihres Logos hinterlegen Sie idealerweise einfach den Namen Ihres Unternehmens. Weitere Punkte müssen Sie an dieser Stelle nicht beachten.

So wie Sie die Kopfzeile bearbeiten können, haben Sie auch Einfluss auf die Fußzeile. Die Optionen halten sich hierbei jedoch in Grenzen. So können Sie im Feld Diverses HTML HTML-Tags hinterlegen. Diese Option ist sozusagen das Äquivalent zur Option Scripts and Style Sheets. Der einzige Unterschied besteht in der Position, in der die hinterlegten HTML-Informationen eingebunden werden. Diverses HTML wird immer vor dem schließenden Body-Tag geladen. Je nachdem welche Tracker- oder Affiliate-Pixel Sie einbinden, kann eine Einbindung vor dem schließenden Body-Tag notwendig sein. Es kommt daher immer ganz auf die zu integrierenden HTML-Tags an, ob diese im Head-Bereich oder vor dem schließenden Body-Tag eingebunden werden sollen. Zudem können Sie die Copyright-Informationen, die ebenfalls im Fußbereich, auch Footer genannt, dargestellt werden, ändern. Im Feld Copyright haben Sie die Möglichkeit, beliebigen Freitext zu hinterlegen, d. h., auch an dieser Stelle können Sie Ihrer Kreativität freien Lauf lassen.

Möchten Sie Ihre Produktbilder mit einem Wasserzeichen schützen, so können Sie dies im nächsten Abschnitt tun. Scrollen Sie daher bitte weiter nach unten, bis Sie beim Abschnitt Produktbild-Wasserzeichen ankommen. Ihnen werden auf den ersten Blick recht viele Konfigurationsmöglichkeiten auffallen, an und für sich können Sie an diesem Punkt jedoch gar nicht so viel einstellen, und nur durch die redundanten Optionen erscheinen die Möglichkeiten recht groß. Magento differenziert an dieser Stelle zwischen den verschiedenen Bild-Typen, die jeweils über dieselben Optionen verfügen. Insgesamt stehen Ihnen folgende Bild-Typen zur Verfügung, die Sie bereits bei der Produktanlage kennengelernt haben:

  • Base
  • Thumbnail
  • Klein
  • Musterbild

Lassen Sie sich an dieser Stelle nicht von den leicht abgewandelten Übersetzungen irritieren, die hier aufgelisteten Bild-Typen entsprechen genau denjenigen, auf die Sie bei der Produktverwaltung Zugriff haben. Bei jedem dieser genannten Produkt-Typen können Sie ein Wasserzeichen hochladen, das sich über die Produktbilder legt. Damit dies möglichst gut aussieht, können Sie die Position und das Verhalten des Bildes bestimmen. Mit Image Opacity können Sie die Transparenz einstellen, indem Sie einen Wert zwischen 0 und 100 hinterlegen. Je transparenter das überlagernde Bild ist, desto besser ist das eigentliche Produktbild zu sehen. Auch haben Sie Einfluss auf die Größe sowie die Position. Nutzen Sie hierfür die Optionen Image Size sowie Image Position. Gerade die Image Position ist interessant, denn hier definieren Sie, an welcher Stelle Ihr Wasserzeichen auf dem Produktbild auftaucht. Zur Auswahl stehen dabei die folgenden Optionen:

  • Strecken
  • Kacheln
  • Oben links
  • Oben rechts
  • Unten links
  • Unten rechts
  • Zentrum

Die zur Verfügung stehenden Optionen sollten Ihnen alle relevanten Positionierungen ermöglichen, weswegen an dieser Stelle keine Wünsche offenbleiben dürften. Wie eingangs erwähnt, stehen alle diese Optionen für alle im System vorhandenen Bild-Typen zur Verfügung. So können Sie je nach Bild-Typ ein anderes Wasserzeichen hochladen und auch die Positionierung je nach Bild-Typ differenzieren.

Last, but not least haben Sie einen weiteren und letzten Konfigurationsabschnitt namens Transaktions-Mails. Der Name des Abschnitts verrät schon, was Sie an dieser Stelle erwartet. Wie Sie bereits im Verlauf des Buches gesehen haben, verschickt Magento bei den unterschiedlichsten Aktionen E‐Mails. Beispielsweise bei einer Bestellung oder bei der Registrierung eines Kundenkontos. Den Inhalt der E‐Mails können Sie an dieser Stelle nicht verwalten, sehr wohl aber Teile ihres Aussehens. Denn in jeder E‐Mail ist ein Logo inkludiert, das Sie an dieser Stelle in der Option Logobild ändern können. Neben dem Upload in den Formaten jpg, jpeg, gif sowie png können Sie zudem das Alt-Attribut und die Größe bestimmen. Bei der Größe haben Sie genau wie beim Logo im Kopfbereich die Felder Logo-Breite sowie Logo-Höhe zur Verfügung, über die Sie die Größe des Logos aussteuern können. Zudem können Sie die Vorlage für den Header sowie den Footer in den Feldern Header-Vorlage bzw. Footer-Vorlage definieren. Magento geht bei den Transaktions-E‐Mails einen ähnlichen Weg wie beim Frontend-Design und erlaubt die Nutzung eines Header- sowie Footer-Templates. Da der Kopf- und Fußbereich in jeder E‐Mail identisch ist, würde es keinen Sinn ergeben, diesen redundant in den gesamten Transaktions-E‐Mails zu pflegen. Aus diesem Grund können Sie eine Vorlage für den Header und Footer anlegen und diese an dieser Stelle auswählen. Die Vorlage legen Sie übrigens exakt wie eine neue Transaktions-E‐Mail an, d. h. unter Marketing • Kommunikation • E‐Mail Vorlagen. Im Standard müssen Sie, zumindest ist das meine Meinung, bei den Vorlagen für den Kopf- sowie den Fußbereich aber nicht eingreifen.

Neben den Optionen, die in diesen Abschnitten vorhanden sind, gibt es in Magento einen weiteren Bereich, in dem Sie das Verhalten des Frontends, zumindest geringfügig, beeinflussen können. Klicken Sie hierzu auf Shops • Einstellungen • Konfiguration • Katalog • Katalog. Dort angekommen, scrollen Sie bitte zum Abschnitt »Frontend«, den Sie auch in Abbildung 14.20 sehen.

Abbildung 14.20    Das Verhalten der Kategorieseite können Sie an dieser Stelle beeinflussen.

In diesem Abschnitt haben Sie Optionen, die speziell das Verhalten der Kategorieseiten beeinflussen. So können Sie beim Feld Listenmodus einstellen, ob die Produkte als Gitter oder Liste dargestellt werden sollen. Im Standard erscheinen die Produkte immer als Gitter, d. h. drei Produkte in einer Zeile, und je nachdem wie viele Produkte Sie darstellen möchten, ergibt sich daraus die Anzahl der Zeilen. Sie können den Listenmodus jedoch auch auf Liste stellen, wodurch die Produkte nur untereinander ausgegeben werden. An dieser Stelle haben Sie auch die Wahl, ob Sie Ihren Nutzern die freie Wahl des Modus erlauben oder ob Sie einen bestimmten Modus vorgeben. Zudem können Sie in den folgenden Feldern die Anzahl der dargestellten Produkte und die mögliche Anzahl an Produkten definieren. Auch Sortierreihenfolgen lassen sich an dieser Stelle hinterlegen.

Speziell die Wahl des Listenmodus hat einen recht großen Einfluss auf das Frontend. Ich habe im Beispiel, das Sie in Abbildung 14.21 sehen, den Listenmodus auf »Liste« abgeändert, wodurch eine komplett neue Ansicht entsteht.

Abbildung 14.21    Alternativ zur Gitteransicht können Sie den Listenmodus auch auf »Liste« stellen.

Bei der Listendarstellung haben Sie schlussendlich viel mehr Platz für Produktinformationen, da die komplette Breite einer Zeile für ein Produkt genutzt werden kann. Speziell wenn Sie erklärungsbedürftigere und auch in Summe weniger Produkte in Ihrem System haben, kann der Listenmodus die bessere Darstellung sein. Für welche Darstellung Sie sich entscheiden, hängt jedoch auch immer von der anvisierten Zielgruppe und der Branche ab.

Selbst wenn die Optionen an dieser Stelle doch eher überschaubar sind, einige wenige Einstellungen in Sachen Frontend-Darstellung können Sie auch an dieser Stelle vornehmen!

Das Frontend automatisiert per Zeitplan steuern

Interessant ist übrigens auch die Möglichkeit, das Frontend-Theme automatisiert zu wechseln. Klicken Sie hierfür auf Inhalt • Design • Zeitplan. Im Bereich »Zeitplan« angekommen, können Sie eine Designänderung durchführen, indem Sie auf den Button Designänderung hinzufügen klicken. Magento fragt Sie daraufhin, welchen Store View Sie ändern möchten. An dieser Stelle können Sie den Eintrag Default auswählen. Nachdem Sie den Store View definiert haben, müssen Sie das zu verwendende Theme auswählen, z. B. Magento Blank. Abschließend können Sie noch ein Start- sowie ein Enddatum auswählen. Speichern Sie die Designänderung, wird automatisch zum gewählten Startdatum das ausgewählte Theme für den definierten Store View geladen. Ist das Enddatum erreicht, wird Magento automatisch die Änderung zurücknehmen.

Speziell wenn Sie ein Weihnachts- oder auch Oster-Design besitzen, ergibt eine automatisierte Änderung definitiv Sinn. Denn Sie müssen sich nicht mehr um die manuelle Umstellung kümmern, sondern können die Designänderung entspannt im Vorfeld planen und hinterlegen.

14.3.2    Vorhandene Themes nutzen und installieren

Die schnellste und einfachste Möglichkeit, Ihren Magento-Online-Shop optisch anzupassen, besteht in der Nutzung eines bereits existenten Themes. Mittlerweile gibt es, ähnlich wie bei den Extensions, viele Anbieter und Seiten, auf denen Sie Magento-Themes herunterladen können. Oftmals deckt die Nutzung eines Themes bereits einen Großteil der eigenen Anforderungen ab, da ein Theme an sich auch nochmals stark modifiziert und angepasst werden kann. Ich möchte Ihnen auf den folgenden Seiten zeigen, wie Sie ein bereits vorhandenes Theme installieren, nutzen und anpassen können. Vorweg sei gesagt, dass die Einstellungen und Möglichkeiten natürlich je nach Theme variieren. Das, was ich Ihnen auf den folgenden Seiten zeige, werden Sie nicht für alle Themes anwenden können. Darum geht es mir in diesem Fall auch gar nicht. Vielmehr möchte ich Ihnen ein Gefühl dafür geben, wie Sie in Magento mit Themes arbeiten und welche Möglichkeiten theoretisch vorhanden sind.

Damit Sie die Änderungen an dieser Stelle ebenfalls nachvollziehen können, möchte ich Ihnen die Installation eines kostenfreien Magento 2-Themes zeigen. Die kostenpflichtigen Themes, deren Preis meistens zwischen 50 und 100 US$ liegt, haben zwar in der Regel einen wesentlich größeren Funktionsumfang und lassen sich individueller anpassen. Dafür müssten Sie das Theme an dieser Stelle aber auch erwerben, und da ich Ihren Geschmack nicht kenne, wäre die Wahrscheinlichkeit sehr hoch, dass Ihnen dieses Theme schlussendlich gar nicht gefällt. Bei einem kostenfreien Theme tut das weitaus weniger weh, da Sie hierfür kein Geld bezahlen.

Für dieses konkrete Beispiel habe ich mich für das Theme »VES FASONY MAGENTO 2« entschieden, das Sie unter http://www.venustheme.com/theme/ves-fasony-free-magento2-theme/ herunterladen können. Besuchen Sie daher jetzt die genannte Seite, und klicken Sie dort auf Add to cart. Auch wenn für das Theme keinerlei Kosten anfallen, müssen Sie genau wie beim Magento Marketplace einmal durch den gesamten Checkout-Prozess, um das Theme herunterladen zu können. Da der Checkout-Prozess recht kurz und selbsterklärend ist, erspare ich Ihnen an dieser Stelle ausschweifende Erklärungen. Hinterlegen Sie Ihre E‐Mail-Adresse, ein Benutzername sowie Passwort, und schließen Sie den Kaufprozess ab. Sie können daraufhin auf der Success-Seite direkt die notwendigen Dateien herunterladen, indem Sie auf den Link Ves Fasony Theme Files klicken. Im Anschluss startet der Download der Datei ves_fasony_theme_files.zip, die Sie daraufhin extrahieren. Wenn Sie nun in das extrahierte Verzeichnis wechseln, werden Sie wiederum zwei Zip-Archive namens theme_files.zip sowie ves_fasony_media.zip vorfinden, die Sie ebenfalls entpacken. Laden Sie bitte im nächsten Schritt den Inhalt des Ordners theme_files in das Hauptverzeichnis Ihrer Magento-Installation. In diesem Verzeichnis sind alle relevanten Templates und PHP-Dateien enthalten, die Sie für die Nutzung des Designs benötigen. Kopieren Sie zudem das Verzeichnis pub, das sich im extrahierten Archiv ves_fasony_media befindet, in das Hauptverzeichnis Ihrer Magento-Installation.

Sobald Sie die Dateien erfolgreich hochgeladen haben, starten Sie die Kommandozeile, und begeben Sie sich in das Hauptverzeichnis Ihrer Magento-Installation. Sollten Sie Magento nicht lokal betreiben, verbinden Sie sich an dieser Stelle mittels SSH am System, auf dem Magento betrieben wird. Führen sie anschließend bitte folgende Befehle aus:

php bin/magento setup:upgrade
php bin/magento setup:di:compile 
php bin/magento setup:static-content:deploy
php bin/magento setup:static-content:deploy de_DE
php bin/magento cache:clean

Listing 14.12    Durch das Ausführen dieser Befehle werden statische Dateien neu generiert und der komplette Cache wird geleert.

Dadurch wird das Theme installiert, und alle benötigten Dateien werden generiert. Wechseln Sie daraufhin erneut in das Magento-Backend, klicken Sie auf Inhalt • Design • Konfiguration, und wählen Sie dort Ihren Default Store View aus. Im Dropdown-Menü Applied Theme, das Sie in Abbildung 14.22 sehen, haben Sie nun die Möglichkeit, den Eintrag Venustheme – Fasony auszuwählen.

Speichern Sie die Konfiguration, und klicken Sie anschließend in der Hauptnavigation des Backends – ich meine damit die Navigationsleiste auf der linken Seite – auf den Eintrag Ves Setup • Werkzeuge • Importoptionen. Sie haben das Theme zwar bereits installiert, es müssen aber noch Blöcke und CMS-Seiten angelegt werden, damit die Darstellung im Frontend stimmig ist. Die Anlage der Blöcke und Seiten übernimmt an dieser Stelle der besagte Menüpunkt. Dort angekommen, können Sie alle Optionen im Standard belassen, klicken Sie bitte nur noch auf den Button Import Configuration. Innerhalb weniger Sekunden sollten die benötigten Einträge importiert sein, und Sie werden eine Erfolgsmeldung erhalten. Wenn Sie daraufhin in der linken Navigation auf Inhalt • Blöcke oder auch auf Inhalt • Seiten klicken, werden Sie viele neue Einträge vorfinden. Diese Inhalte wurden durch den von Ihnen ausgelösten Import angelegt. Leeren Sie anschließend den Cache, und rufen Sie das Frontend Ihres Magento-Shops auf.

Abbildung 14.22    Nach der Installation des Themes können Sie dieses in der Konfiguration innerhalb des Backends auswählen.

Installation des Themes hängt von der Entwicklung ab

Wie eingangs erwähnt, ist die von mir erwähnte Vorgehensweise keine Blaupause, die für alle Themes funktioniert. Letztendlich müssen Sie, nachdem Sie ein Theme heruntergeladen haben, immer in die beigefügte Installationsanweisung schauen. Reicht jedoch das Kopieren von Dateien, so können Sie in 99 % der Fälle wie von mir beschrieben vorgehen. Letztendlich müssen Sie die Dateien nur in die richtige Verzeichnisstruktur kopieren und anschließend die erwähnten Befehle in der Kommandozeile ausführen. Danach können Sie das Theme im Backend nutzen.

Sie sollten anschließend ein komplett neues bzw. in einem anderen Look erscheinendes Frontend vorfinden. Sollte an dieser Stelle noch das alte Design, sprich das Magento-Luma-Theme erscheinen, prüfen Sie bitte, ob Sie tatsächlich alle Befehle in der Kommandozeile ausgeführt und den Cache geleert haben. An und für sich sind Sie aber mit der Installation fertig, und Sie können nun das neue Theme verwenden, modifizieren und erweitern.

Ein weiterer Vorteil des Themes besteht übrigens in dem verwendeten Responsive-Design. Wie Sie in Abbildung 14.23 sehen, wird auch auf kleineren Bildschirmgrößen das Frontend sehr nutzerfreundlich dargestellt. An und für sich handelt es sich bei dem kostenfreien Theme daher doch um eine ganz runde Sache, und Ihnen wird der schnelle Wechsel des Frontend-Designs ermöglicht. An dieser Stelle wollte ich Ihnen unbedingt zeigen, wie schnell und einfach Sie in Magento 2 ein Theme installieren können. Ich hoffe, Ihnen ist die einfache Handhabung in diesem doch eher rudimentären Beispiel klargeworden, und gegebenenfalls ergibt es in Ihrem konkreten Fall sogar Sinn, auf ein bereits existentes Theme zu setzen.

14.3.3    Interessante Seiten für Themes

Es gibt sicherlich unzählige Seiten, die Magento 2-Themes anbieten. Mein persönlicher Favorit ist jedoch ganz klar Themeforest. Themeforest ist eine Plattform, die für die verschiedensten Systeme Themes anbietet. Es gibt mittlerweile jedoch auch eine Magento 2-Kategorie, die Sie unter https://themeforest.net/tags/magento2 erreichen. Angeboten werden in erster Linie kommerzielle Themes, die zwischen 50 und 100 US$ kosten, somit also bezahlbar sind. Themeforest ermöglicht Ihnen zudem die Filterung der Themes je nach Version und Ratings. Speziell die Ratings und Verkaufszahlen sollten Sie im Auge behalten, denn dadurch finden Sie in der Regel auch die qualitativ hochwertigen und tollen Designs. Seit der Veröffentlichung von Magento 2 hat sich das Porto-Theme zum Shootingstar gemausert. Ich selbst habe einige Projekte mit dem Porto-Theme realisiert und muss zugeben, dass es sich um ein sehr umfangreiches und optisch ansprechendes Design handelt. Sie haben im Backend sehr viele Konfigurationsmöglichkeiten und können im Prinzip alle Anpassungen ohne Programmierkenntnisse vornehmen. Weitere Informationen zum Porto-Theme erhalten Sie unter https://themeforest.net/item/porto-ultimate-responsive-magento-theme/9725864?s_rank=1.

Ähnlich wie bei Themeforest handelt es sich bei Templatemonster ebenfalls um ein Portal, das Designs und Themes für die verschiedensten Software-Lösungen zur Verfügung stellt. Auch hier existiert eine Magento 2-Kategorie, in der Sie Themes erwerben können. Die Auswahl ist jedoch nicht ganz so groß wie bei Themeforest, weswegen Templatemonster eher meine zweite Wahl darstellt. Verschaffen Sie sich unter https://www.templatemonster.com/de/vorlagen/?pr=50115-248605 jedoch selbst einen Überblick.

Last, but not least möchte ich an dieser Stelle zudem auf den Magento Marketplace verweisen, der ebenfalls eine Kategorie namens Themes besitzt. Unter https://marketplace.magento.com/themes.html können Sie ähnlich wie bei den Extensions auf Filter zurückgreifen, um die Ergebnisauswahl einzuschränken. Ob dies jedoch im Fall der Magento 2-Themes notwendig ist, wage ich zu bezweifeln. Aktuell gibt es im Magento Marketplace nur neun Magento 2-Themes, die Auswahl ist also sehr überschaubar. Es bleibt jedoch abzuwarten, ob im Laufe der nächsten Wochen und Monate das Angebot an Magento 2-Themes steigt. Auch bei den Extensions gab es direkt nach dem Magento 2-Launch kein allzu großes Angebot, was sich jedoch recht schnell geändert hat. Themes hinken erfahrungsgemäß dem Trend etwas hinterher, warten Sie daher diesbezüglich einfach noch etwas ab, bzw. greifen Sie direkt auf Themeforest zurück.
