19.2    Magento mittels Magerun verwalten

Vergleicht man Magento 2 mit seinem Vorgänger, so hat die Software in Sachen Command Line Interface einen Riesensprung gemacht, denn in Magento 1 existierte kein CLI-Tool. Unter anderem aus diesem Grund ist jedoch ein Community-Projekt rasch populär geworden und gehört mittlerweile fast zur Grundausstattung jedes Magento-Online-Shops. Bei diesem Tool handelt es sich um Magerun, das sich selbst als »The swiss army knife for Magento developers, sysadmins and devops« bezeichnet. In erster Linie ist es sicherlich ein Tool, das primär für Entwickler interessant und relevant ist. Da ich Ihnen in diesem Kapitel jedoch das in Magento integrierte Command Line Interface vorgestellt habe, möchte ich die letzten Seiten in diesem Kapitel auch dazu nutzen, Ihnen einen Einblick in Magerun zu geben.

19.2.1    Magerun installieren

Im ersten Schritt müssen Sie Magerun installieren. Die Installation an sich ist relativ simpel, denn Sie müssen nur eine Datei kopieren und diese idealerweise in das Hauptverzeichnis Ihrer Magento-Installation legen. Wenn Sie den Download starten möchten, rufen Sie einfach die Datei https://files.magerun.net/n98-magerun2.phar auf. Sollten Sie Linux bzw. macOS nutzen und auf wget bzw. curl zurückgreifen können, so können Sie den Download auch direkt mit folgenden Befehlen ausführen:

Download per wget
wget https://files.magerun.net/n98-magerun2.phar 
chmod +x ./n98-magerun2.phar
Download per CURL
curl -sS -O https://files.magerun.net/n98-magerun2.phar 
chmod +x ./n98-magerun2.phar

Listing 19.9    Mit »curl« bzw. »wget« können Sie direkt über die Kommandozeile herunterladen.

Wenn Sie Magerun heruntergeladen haben, entweder manuell über die aufgeführte URL oder mit wget bzw. curl, und die Datei im Hauptverzeichnis von Magento abgelegt haben, navigieren Sie bitte mit der Kommandozeile in das Hauptverzeichnis Ihrer Magento-Installation. Denn die Installation von Magerun haben Sie mit dem Download der Datei an sich abgeschlossen, weitere Dinge müssen Sie an dieser Stelle nicht unternehmen!

19.2.2    Die Magerun-Befehle im Überblick

Sobald Sie im Hauptverzeichnis Ihrer Magento-Installation angekommen sind, rufen Sie bitte Magerun auf, indem Sie folgenden Befehl in der Konsole ausführen: php n98-magerun2.phar. Anschließend meldet sich Magerun mit allen zur Verfügung stehenden Befehlen zurück. Das Verhalten ist also recht ähnlich wie beim Magento Command Line Interface Tool. Verwenden Sie im ersten Schritt keinen Parameter, erhalten Sie einfach eine Auflistung aller möglichen Optionen, wie Sie dies auch in Abbildung 19.6 sehen.

Abbildung 19.6    Beim Aufruf von Magerun erhalten Sie einen Überblick über alle Befehle und Möglichkeiten.

Wenn Sie sich an dieser Stelle, zumindest im Schnelldurchlauf, die vorhandenen Befehle und Möglichkeiten anschauen, werden Sie recht viele Ähnlichkeiten mit dem Magento CLI-Tool feststellen. Das liegt daran, dass Magerun neben den eigenen Befehlen und Möglichkeiten zudem die Magento CLI-Tools beherrscht. Verwenden Sie Magerun, so müssen Sie nicht mehr auf das Magento CLI-Tool zurückgreifen, da Magerun alle dort enthaltenen Befehle ebenfalls abdeckt. Zusätzlich ergänzt Magerun diese um eigene Funktionen, die ich Ihnen nun im Überblick aufzeigen möchte.

Ein Tool mit allen Möglichkeiten

Die Entwickler von Magerun haben, und ich finde das persönlich sehr clever, alle im Magento CLI-Tool enthaltenen Funktionen übernommen bzw. inkludiert, sodass Sie als Administrator bzw. Benutzer nur mit einem Tool arbeiten müssen. Wäre dies nicht geschehen, hätten Sie immer zwischen bin/magento bzw. Magerun hin und her wechseln müssen. Die Akzeptanz beider Tools wäre in einem solchen Fall sicherlich gesunken. Daher finde ich die Integration der Befehle äußerst hilfreich, denn wenn Sie Magerun nutzen, benötigen Sie kein weiteres CLI-Tool!

Available commands

Im ersten Abschnitt namens »Available commands« sind allgemeine und von Magento unabhängige Befehle gruppiert. Übergeben Sie den Parameter help, erhalten Sie als Rückmeldung eine Information zur Nutzung der Hilfe-Funktionalität. Am sinnvollsten ist die Nutzung des Parameters jedoch bei einem konkreten Befehl, denn Sie erhalten anschließend detaillierte Informationen zu den benötigten Parametern und Übergabewerten. Dementsprechend sollten Sie den Parameter help immer im Zusammenhang mit einem Befehl einsetzen, so wie es auch bei dem Magento CLI der Fall ist.

Ein äußerst mächtiger Befehl ist an dieser Stelle das install-Kommando. Rufen Sie dieses auf, werden Sie gefragt, welche Magento-Version Sie installieren möchten. Sollten Sie an dieser Stelle den Befehl nicht selbst ausführen können, sehen Sie die Rückgabewerte in Abbildung 19.7. Wenn Sie Magerun für die Installation von Magento nutzen, müssen Sie im Vorfeld keine Dateien herunterladen bzw. extrahieren. Bei der Installation werden Sie von Magerun gefragt, welche Version Sie installieren möchten. Dabei stehen einige Versionen, wie Sie in Abbildung 19.7 sehen, zur Auswahl. Haben Sie sich für eine Version entschieden, lädt Magerun alle benötigten Dateien herunter und beginnt mit dem Installationsprozess. In den nächsten Schritten werden Sie von Magerun zudem nach Konfigurationseinstellungen, beispielsweise den Zugangsdaten zur Datenbank, gefragt. Dadurch bildet Magerun den kompletten Installationsprozess von Magento ab, und Sie benötigen an sich nur Magerun, um Magento zu installieren. Weitere Informationen und Details zur Installation mittels Magerun entnehmen Sie an dieser Stelle aber bitte Abschnitt 3.3.5, »Magerun«, dort ist recht ausführlich beschrieben, wie Sie Magento mithilfe von Magerun installieren können. Daher möchte ich Ihnen an dieser Stelle redundanten Inhalt ersparen.

Abbildung 19.7    Mithilfe von Magerun können Sie direkt Magento installieren.

Eine explizite Auflistung aller in Magerun vorhandenen Befehle erhalten Sie, indem Sie den Parameter list beim Aufruf von Magerun übergeben. Das Ergebnis ist jedoch identisch mit dem, das Sie erhalten, wenn Sie Magerun komplett ohne Parameter aufrufen. Nutzen Sie den Befehl mysql-client, so startet automatisch der MySQL-Client, den Sie ebenfalls per Kommandozeile verwenden können. Sie werden dabei automatisch mit den in der Magento-Konfigurationsdatei hinterlegten Datenbankverbindungsdaten angemeldet. Mit dem MySQL-Client können Sie anschließend alle SQL-Operationen in der Kommandozeile ausführen, die Sie ausführen möchten. Darunter fallen die Anlage weiterer Tabellen, das Durchführen von Änderungen am Schema der Datenbank, das Auslesen und Hinzufügen von Inhalten etc. Im Prinzip ist diese Funktion für Sie dann wichtig, wenn Sie direkt in der Datenbank Operationen ausführen möchten. Alternativ hierzu können Sie, wenn Sie eher ein Fan der grafischen Oberflächen sind, jedoch auch phpMyAdmin oder einen anderen grafischen MySQL-Client verwenden. Möchten Sie den Browser starten und das Magento-System aufrufen, können Sie dies mit dem Befehl open-browser tun. Der Befehl selbst ist jedoch als »experimentell« gekennzeichnet, d. h., nicht auf allen Betriebssystemen steht diese Funktion zur Verfügung. Es hängt also ein wenig von Ihrem System-Setup ab, ob Sie diesen Befehl nutzen können. Sofern Sie direkt mehrere Magerun-Befehle ausführen möchten, können Sie den Parameter script verwenden. Sie haben danach die Möglichkeit, verschiedenste Magerun-Parameter direkt auszuführen.

Um Magerun zu aktualisieren, stehen ebenfalls zwei Befehle zur Verfügung. Diese sind von der Logik absolut identisch, tragen jedoch unterschiedliche Namen. Für ein Update von Magerun verwenden Sie bitte self-update bzw. selfupdate. Sollte eine neuere Version vorliegen, würde Magerun nach der Ausführung des Befehls automatisch aktualisiert werden. Zu guter Letzt können Sie mit dem Parameter shell in eine Art »Shell-Modus« eintauchen. Sie müssen anschließend nicht jedes Mal Magerun an sich aufrufen bzw. starten, sondern starten Magerun initial und können daraufhin einfach direkt Magerun-Befehle ausführen. Der Shell-Modus ergibt Sinn, wenn Sie viele verschiedene Magerun-Kommandos ausführen möchten und dies bereits im Vorfeld wissen. Ist dies der Fall, nutzen Sie den Parameter Shell, und starten Sie Magerun. Anschließend wird Ihnen Magerun mitteilen, dass es sich im Shell-Modus befindet, und Sie können daraufhin alle Befehle direkt eingeben, ohne jedes Mal Magerun starten zu müssen. Durch die Nutzung dieses Befehls können Sie sich daher viel Tipparbeit und damit Zeit sparen!

admin

Innerhalb des Magento-Backends existieren sogenannte Notifications, also Warnmeldungen bzw. Hinweise. Wenn der Cache veraltet ist oder die Indexe neu aufgebaut werden müssen, werden Sie im Backend eine entsprechende Notification erhalten. Es handelt sich um die Meldungen, die immer am oberen Bereich des Bildschirms eingeblendet werden, wie Sie auch in Abbildung 19.8 sehen können. Wenn Sie jedoch keine Lust auf diese Systemmeldungen haben und auch nicht über neue Magento-Versionen bzw. Probleme Ihres aktuellen Systems informiert werden möchten, können Sie die Notifications deaktivieren. Nutzen Sie hierfür einfach den Parameter admin:notifications. Sind die Systemmeldungen aktiviert und Sie führen den Befehl aus, werden diese deaktiviert. Sind die Systemmeldungen hingegen deaktiviert und Sie führen diesen Befehl aus, werden sie aktiviert. Es gibt also kein disable- bzw. enable-Kommando, je nach Status deaktivieren bzw. aktivieren Sie mit diesem Befehl die Systemmeldungen bzw. Notifications.

Abbildung 19.8    Systemmeldungen können mittels Magerun deaktiviert werden.

Möchten Sie das Passwort eines Backend-Benutzers ändern, können Sie dies mittels Magerun ebenfalls tun. Führen Sie Magerun mit dem Parameter admin:user:change-password aus. Sie werden anschließend nach einem Benutzernamen gefragt, den Sie daraufhin eingeben müssen. Ist ein Benutzer mit diesem Benutzernamen im Backend vorhanden, können Sie daraufhin ein neues Passwort für diesen setzen.

Einen neuen Benutzer können Sie ebenfalls erstellen, hierbei handelt es sich um die Funktionsweise, die Sie bereits vom Magento CLI-Tool kennen. Magerun ergänzt an dieser Stelle jedoch die Funktion, einen Benutzer zu löschen. Hierfür steht der Parameter admin:user:delete zur Verfügung. Entweder übergeben Sie an dieser Stelle direkt die ID des Benutzers, oder Sie führen den Befehl ohne weitere Parameter aus. Magerun fragt Sie daraufhin nach einem Benutzernamen bzw. einer E-Mail-Adresse. An dieser Stelle können Sie dann durch die Eingabe der E-Mail-Adresse bzw. des Benutzernamens den gewünschten Benutzer löschen. Wenn Sie sich nicht sicher sind, welche Benutzer im System existieren, können Sie sich mit dem Parameter admin: user:list eine Auflistung aller im System angelegten Benutzer ausgeben lassen. Neben der ID und der E-Mail-Adresse sehen Sie zudem den Benutzernamen sowie den Status des Benutzers. Dieser Befehl ist äußerst praktisch, wenn Sie sich einen schnellen Überblick über alle im System vorhandenen Benutzer machen möchten. Ist ein Benutzer übrigens gesperrt, können Sie diesen direkt mittels admin:user:unlock entsperren. Auch bei diesem Befehl können Sie entweder direkt die ID des Benutzers übergeben oder den Befehl ohne Parameter ausführen, wodurch Sie nach einer E‐Mail-Adresse bzw. einem Benutzernamen gefragt werden. Der von Haus aus doch eher funktionsarme Bereich »Admin« wird von Magerun durch einige sehr sinnvolle und nützliche Funktionen ergänzt. An dieser Stelle schlägt Magerun ganz klar das Magento CLI-Tool!

app

Der Vollständigkeit halber möchte ich noch den Bereich »app« aufführen, obwohl Magerun hier keine Funktionen bzw. Befehle ergänzt. Sie können daher an dieser Stelle nur auf die in Magento bereits vorhandenen Befehle zurückgreifen. Dabei handelt es sich um den Befehl app:config:dump.

cache

Auch im Bereich »cache« bringt das Magento CLI-Tool von Haus aus wichtige Befehle mit. Doch werden diese von Magerun nochmals ergänzt. Zum Standard gehören die Parameter cache:clean, cache:disable, cache:enable, cache:flush sowie cache:status, die Ihnen an dieser Stelle als Befehle zur Verfügung stehen. Zusätzlich haben Sie jedoch die Möglichkeit, sich alle vorhandenen Caches auflisten zu lassen. Nutzen Sie hierfür einfach cache:clean, wodurch Sie als Rückgabeergebnis folgende Liste erhalten werden:

+------------------------+--------------------------------+---------+
| Name                   | Type                           | Enabled |
+------------------------+--------------------------------+---------+
| config                 | Configuration                  | 1       |
| layout                 | Layouts                        | 1       |
| block_html             | Blocks HTML output             | 1       |
| collections            | Collections Data               | 1       |
| reflection             | Reflection Data                | 1       |
| db_ddl                 | Database DDL operations        | 1       |
| eav                    | EAV types and attributes       | 1       |
| customer_notification  | Customer Notification          | 1       |
| full_page              | Page Cache                     | 1       |
| config_integration     | Integrations Configuration     | 1       |
| config_integration_api | Integrations API Configuration | 1       |
| translate              | Translations                   | 1       |
| config_webservice      | Web Services Configuration     | 1       |
+------------------------+--------------------------------+---------+

Listing 19.10    Magento listet alle vorhandenen Caches samt Status auf.

Sie können anhand der Liste alle vorhandenen Caches erkennen und sehen zudem in der letzten Spalte, ob der jeweilige Cache aktiv bzw. inaktiv ist. Wäre ein Cache inaktiv, würde anstelle der 1 eine 0 stehen.

Wenn Sie direkt in den Cache eintauchen möchten, können Sie dies mit cache:report tun. Als Ergebnis erhalten Sie ebenfalls eine Liste mit verschiedenen Cache-Elementen und einem Zeitpunkt, wann diese Cache-Elemente auslaufen. Zugegebenermaßen handelt es sich hierbei um einen sehr technischen Report, der speziell für Entwickler interessant sein dürfte. Entwickler können anhand dieses Reports recht schnell nachvollziehen, welche Elemente sich gerade im Cache befinden und welche Lebenszeit diese haben. Um noch tiefer einzusteigen, steht zudem der Parameter cache:view zur Verfügung. Dieser erfordert noch einen weiteren Parameter, der den Cache spezifiziert. Übergeben Sie beispielsweise den Parameter system, erhalten Sie als Rückgabewert den kompletten Inhalt dieses Caches. Ergo haben Sie mit diesem Befehl die Möglichkeit, den Inhalt jedes im System befüllten Caches auszulesen und damit einzusehen, welche Informationen Magento in den Zwischenspeicher gepackt hat. Speziell um Probleme und Fehler nachzuvollziehen, ist dies ein äußerst praktisches Feature, das sich aber in erster Linie an Entwickler richtet.

catalog

Der Bereich »catalog« wird von Magerun nicht mit zusätzlichen Befehlen und Möglichkeiten erweitert. Sie haben aber natürlich die Möglichkeit, auf die beiden im Standard vorhandenen Parameter namens catalog:images:resize sowie catalog:product:attributes:cleanup zuzugreifen.

config

Der Abschnitt »config« wird durch Magerun neu eingeführt und steht im Magento-Standard-CLI-Tool nicht zur Verfügung. Beim ersten verfügbaren Parameter handelt es sich wiederum um einen speziell für Entwickler interessanten Befehl. Führen Sie config:data:acl aus, wird der ACL-Tree zurückgeliefert. Der ACL-Tree ist eine Darstellung der Berechtigungen in Baumform. In diesem Baum sehen Sie alle möglichen Berechtigungsoptionen, die in Magento existieren. Beispielsweise gibt es den Bereich »Products«, der sich in »Inventory« sowie »Catalog« und »Categories« unterteilt. Diese Struktur kennen Sie, abgesehen vom Oberpunkt »Inventory«, aus dem Backend, wenn Sie Kategorien bzw. Produkte anlegen und verwalten. Anhand des Baumes sehen Sie somit, wie Sie Berechtigungen eingrenzen bzw. einschränken und auf welche Bereiche Sie sich an dieser Stelle beziehen können. Sofern Sie sich Abhängigkeiten von Modulen anzeigen lassen möchten, können Sie dies mit dem Befehl config:data:di tun.

Spannend wird es nun mit den folgenden drei Befehlen, denn Sie haben mit Magerun die Möglichkeit, Konfigurationseinstellungen zu löschen, zu setzen bzw. bestehende Konfigurationseinstellungen auszulesen. Um eine Konfigurationseinstellung zu löschen, verwenden Sie bitte den Parameter config:delete. Dieser Parameter allein wird jedoch noch keine Aktion ausführen. Sie müssen an dieser Stelle noch spezifizieren, welche Einstellung Sie löschen möchten. Um dies zu tun, müssen Sie den Konfigurationspfad der Option übergeben. Ähnlich verhält es sich beim Auslesen einer Konfigurationsoption. Verwenden Sie den Parameter config:get, und ergänzen Sie diesen um einen Konfigurationspfad. Dadurch könnte der Befehl wie folgt aussehen: php n98-magerun2.phar config-get web_unsecure_base_url. In diesem Fall liest Magerun den Wert der Basis-URL aus und gibt diesen zurück:

+-----------------------+---------+----------+-------------------------+
| Path                  | Scope   | Scope-ID | Value                   |
+-----------------------+---------+----------+-------------------------+
| web/unsecure/base_url | default | 0        | http://www.foodbaer.de/ |
+-----------------------+---------+----------+-------------------------+

Listing 19.11    Magerun kann direkt auf Konfigurationseinstellungen zurückgreifen.

Theoretisch können Sie beim Aufruf auch noch den Scope definieren, also ob Sie den Wert für einen bestimmten Store View haben möchten. Wenn Sie keinen Scope übergeben, erhalten Sie einfach eine Liste aller Werte je nach Scope. Da ich bei der URL nur einen Default-Wert besitze, liefert Magento letztendlich auch nur diesen einen Eintrag zurück.

So wie Sie die Konfigurationseinstellung auslesen bzw. löschen können, bietet Magerun zudem die Möglichkeit, Konfigurationseinstellungen zu setzen. Verwenden Sie hierfür den Parameter config:set. Neben dem Pfad muss zudem ein Wert übergeben werden. Möchten Sie also die Basis-URL abändern, so könnte der Befehl wie folgt aussehen: php n98-magerun2.phar config-set web_unsecure_base_url http://foodbaer.de. Seien Sie an dieser Stelle jedoch etwas vorsichtig, wenn Sie mit Magerun experimentieren. Eine aus Unachtsamkeit gelöschte Option bzw. ein fehlerhafter Wert beim Setzen einer Option kann Ihr System beschädigen. Aus diesem Grund habe ich Ihnen oben beim Löschen der Option auch kein direktes Beispiel mitgeliefert, auch wenn der Aufruf nach genau demselben Schema wie beim Editieren bzw. Auslesen funktioniert. An dieser Stelle ist etwas Vorsicht geboten!

cron

Wie auch im Standard steht Ihnen im Bereich »cron« der Parameter cron:run zur Verfügung, Magerun nimmt selbst keine Erweiterungen in diesem Bereich vor.

customer

Mithilfe von Magerun können Sie via Kommandozeile doch recht viel in Sachen Kundenmanagement machen. Der im Standard vorhandene Funktionsumfang wird speziell im Punkt »customer« doch recht stark erweitert, was ich Ihnen an dieser Stelle zeigen möchte.

Beispielsweise können Sie mit Magerun einen neuen Kunden erstellen. Hierfür steht Ihnen der Parameter customer:create zur Verfügung. Nach der Ausführung des Befehls werden Sie Schritt für Schritt durch die Kundenanlage geführt und geben beispielsweise im ersten Schritt eine E-Mail-Adresse, gefolgt von Passwort, Vorname, Nachname und der Website an. Im Prinzip können Sie den Kunden direkt über die Kommandozeile erstellen, und dieser wird sich daraufhin problemlos im Frontend anmelden können. Weitere Arbeitsschritte, damit der Kunde aktiv werden kann, sind nicht nötig. Des Weiteren haben Sie auch in Magerun Zugriff auf das bereits erwähnte Kommando customer:hash:upgrade, das Sie daher an dieser Stelle ignorieren können.

Möchten Sie Kundendaten abfragen, steht Ihnen der Parameter customer:info zur Verfügung. Nachdem Sie Magerun mit diesem Parameter gestartet haben, werden Sie nach einer E-Mail-Adresse gefragt. Nachdem Sie eine E-Mail-Adresse sowie die Website, in welcher der Kunde registriert ist, hinterlegt haben, erhalten Sie eine tabellarische Auflistung der vorhandenen Kundenstammdaten, werfen Sie hierzu auch einen Blick auf Abbildung 19.9.

Abbildung 19.9    Magerun kann Ihnen die Stammdaten eines Kunden in tabellarischer Form darstellen.

Selbstverständlich werden sensible Informationen wie das Passwort bzw. der Passwort-Hash oder Zahlungsdaten nicht zurückgeliefert. Neben der Ausgabe eines einzelnen Kunden können Sie mit customer:list zudem eine Liste aller im System vorhandenen Kunden ausgeben. In meinem Fall hält sich das Ergebnis noch in Grenzen, da in meinem System nur eine Handvoll Nutzer registriert ist. Wenn Sie jedoch über einige Tausend Kunden verfügen, ist dieses Ausgabeformat nicht ideal.

Ausgabeformat kann definiert werden

Bei Magerun haben Sie übrigens immer die Möglichkeit, das Ausgabeformat zu definieren. In meinen Beispielen lasse ich mir die Ergebnisse direkt in der Kommandozeile anzeigen. Jedoch können Sie die Ergebnisse auch in eine CSV-, JSON- oder XML-Datei speichern lassen. Gerade bei komplexen Ergebnissen, denken Sie an einige Tausend Kunden, macht eine Ausgabe in der Kommandozeile wenig Sinn. Nutzen Sie daher in diesen Fällen den Parameter --format und übergeben Sie als Wert csv, json oder xml.

db

Für die Administration und Ausführung von Datenbankoperationen stehen verschiedenste Befehle in dem Abschnitt »db« bereit. Diese Befehle und Möglichkeiten richten sich in erster Linie an Entwickler, die bei der Entwicklung von Modulen und bei Anpassungen des Systems auch Zugriff auf die Datenbank benötigen. Für Sie als Shop-Betreiber bzw. Administrator dürften diese Möglichkeiten zwar interessant, in der Praxis jedoch nicht relevant sein. Werfen Sie dennoch einen Blick auf die verschiedensten Möglichkeiten, die Magerun mitbringt.

Um den MySQL-Client zu starten, können Sie, wie bereits einige Seiten zuvor erwähnt, den Parameter db:console verwenden. Es werden direkt die in der Magento-Konfiguration verwendeten Datenbankzugangsdaten verwendet, d. h., Sie landen direkt in der von Magento genutzten Datenbank und müssen sich weder authentifizieren noch die benötigte Datenbank auswählen. Möchten Sie eine Datenbank erstellen, können Sie zudem den Befehl db:create verwenden. Dadurch wird die in der Magento-Konfiguration hinterlegte Datenbank erstellt. Voraussetzung hierfür ist jedoch, dass die hinterlegte Datenbank noch nicht installiert ist.

Möchten Sie die angelegte Datenbank inklusive aller Informationen löschen, können Sie dies mittels db:drop tun. An dieser Stelle würde ich Sie jedoch bitten, das Kommando nicht auszuführen, da Sie Ihr bestehendes und mühevoll aufgebautes Magento-System sicherlich behalten möchten. Um eine Sicherung der Datenbank zu erstellen – letztendlich gibt es hierfür verschiedenste Möglichkeiten –, können Sie Magerun verwenden und mit dem Parameter db:dump starten. Dieser Befehl ermöglicht es Ihnen, eine Sicherung der Datenbank zu erstellen und diese zu speichern. Alternativ hierzu können Sie jedoch auch den in Magento enthaltenen Backup-Mechanismus verwenden, der sich sowohl über das Backend als auch über das CLI bzw. Magerun ansprechen lässt. Da an dieser Stelle ein Export bzw. eine Sicherung möglich ist, existiert selbstverständlich auch eine Import-Funktion. Nutzen Sie hierfür den Parameter db:import. Mit diesem Befehl haben Sie grundsätzlich die Möglichkeit, eine Datenbanksicherung einzuspielen, müssen an dieser Stelle aber noch die zu importierende Datei definieren.

Möchten Sie die Datenbankverbindungsdaten ausgeben, nutzen Sie bitte den Parameter db:info. Als Ergebnis erhalten Sie eine tabellarische Darstellung wie in Abbildung 19.10.

Abbildung 19.10    Mit »db:info« können Sie sich die Datenbankverbindungsdaten ausgeben lassen.

Neben dem Benutzernamen, dem Passwort (in der Abbildung entfernt) und dem Datenbanknamen erhalten Sie alle weiteren Informationen, die zum Aufbau der Datenbankverbindung notwendig sind. Sollten Sie daher die Verbindungsdaten nicht parat haben, und möchten Sie diese nicht in der Konfigurationsdatei nachschauen, so können Sie diese Informationen problemlos mittels Magerun ausgeben lassen.

Gibt es gegebenenfalls Fehler, bzw. vermuten Sie ein Problem, so können Sie mit db:maintain:check-tables die Datenbank überprüfen. Als Ergebnis erhalten Sie alle vorhandenen Tabellen in tabellarischer Form zurückgeliefert. Auch sehen Sie die jeweiligen Engines wie z. B. InnoDB. Sofern möglich, das hängt auch von der Engine ab, führt Magerun einen Check der Tabelle durch. Wo immer ein Check durchgeführt werden kann, wird zudem das Ergebnis in der letzten Spalte dargestellt. Erhoffen Sie sich an dieser Stelle nicht zu viel von dem Datenbankcheck. Im Prinzip wird eine rudimentäre Prüfung durchgeführt, die Sie aber auch beispielsweise mittels phpMyAdmin durchführen können. Für eine oberflächliche und schnelle Prüfung ist der Befehl jedoch vollkommen ausreichend. Das Ergebnis ist zudem, wie Sie in Abbildung 19.11 sehen, in der Tat sehr übersichtlich dargestellt.

Wenn Sie möchten, können Sie direkt SQL-Statements wie Abfragen, aber auch Inserts in Magerun ausführen. Nutzen Sie hierfür den Parameter db:query. Nachdem Sie Magerun aufgerufen haben, werden Sie nach dem SQL-Statement gefragt und können von da an direkt mittels SQL auf der Datenbank arbeiten.

Um den Status der Datenbankverbindung einzusehen, steht Ihnen der Parameter db:status zur Verfügung. Führen Sie diesen Befehl aus, erhalten Sie grundsätzliche Informationen zur MySQL-Datenbank. dev

Im Standard verfügt das Magento CLI-Tool bereits über den Abschnitt »dev«, in dem insgesamt vier Befehle vorhanden sind. Hierbei handelt es sich, um an dieser Stelle Ihre Erinnerung aufzufrischen, um dev:source-theme:deploy, dev:tests:run, dev:urn-catalog:generate sowie dev:xml:convert. Magerun, das sich in erster Linie an Entwickler richtet, ergänzt speziell den Funktionsumfang in diesem Abschnitt nochmals um viele interessante und nützliche Befehle.

Neben diesem Befehl steht mit dev:console ein experimentelles Kommando zur Verfügung, mit dem Sie in eine interaktive Shell eintauchen und in dieser Befehle ausführen können.

Sollte es zu Problemen im System kommen, legt Magento von Haus aus immer Reports an. Symlinks setzen in einem bzw. mehreren Verzeichnis Verweise auf Dateien bzw. Verzeichnisse, die an einer anderen Stelle liegen. Das kann helfen, die Struktur zu verbessern, unter Umständen können Symlinks aber auch zu Problemen führen. Gerade in Shared-Hosting-Umgebungen gibt es des Öfteren Probleme mit Symlinks. Mit dem oben aufgeführten Parameter haben Sie jedoch die Möglichkeit, diese zu aktivieren bzw. zu deaktivieren.

maintenance

Der Wartungsmodus sorgt dafür, dass Nutzer im Frontend nicht auf Ihren Online-Shop zugreifen können, sofern der Wartungsmodus aktiv ist. Im Standard können Sie den Wartungsmodus aktivieren, deaktivieren, sich den Status zurückliefern lassen sowie eine IP-Adresse auf eine Whitelist setzen. Da Sie mit diesen Möglichkeiten das ganze Spektrum abdecken, hat Magerun an dieser Stelle keine weiteren Ergänzungen vorgenommen. Wie auch im Standard stehen Ihnen daher die Parameter maintenance:allow-ips, maintenance:disable, maintenance:enable sowie maintenance: status zur Verfügung.

module

Ähnlich wie beim Wartungsmodus wurde der Bereich »module« von Magerun nicht erweitert bzw. modifiziert. Hierfür stehen Ihnen die Parameter module:disable, module:enable, module:status sowie module:uninstall zur Verfügung. Ergänzungen, Erweiterungen oder gar Anpassungen gibt es von Magerun an dieser Stelle jedoch nicht.

Ich persönlich finde diesen Bereich und die dort enthaltenen Befehle und Kommandos äußerst nützlich. Auch in dem Fall, wenn Sie ein neues Magento-System übernehmen, was speziell bei Agenturen und Entwicklern der Fall ist, können Sie sich mit den enthaltenen Befehlen schnell einen soliden Überblick über die installierten Module, die verwendete Magento-Version und über die angelegten Websites bzw. Store Views verschaffen.

theme

Im Bereich »theme« nimmt Magerun keine Ergänzungen vor, Sie können jedoch auf den bereits bekannten Parameter uninstall zurückreifen, um ein Theme zu deinstallieren.

19.2.3    Magerun vs. Magento CLI

Was ist denn nun besser, Magerun oder das Magento Command Line Interface Tool? Für mich persönlich ist das ehrlich gesagt keine Entweder-oder-Frage. Magento CLI bietet eine sehr vernünftige und umfassende Basis, um gewisse Operationen in der Kommandozeile auszuführen sowie bestimmte Informationen per Kommandozeile abzurufen. Magerun setzt hier noch einmal eine Schippe oben drauf. Zum einen werden alle im Magento CLI-Tool enthaltenen Befehle unterstützt, wodurch Magerun immer und zu jedem Zeitpunkt genauso umfangreich wie das Magento CLI-Tool ist. Zum anderen erweitert Magerun den bereits vorhandenen Funktionsumfang nochmals drastisch und bietet viele interessante Möglichkeiten und Befehle an. Grundsätzlich können Sie Magerun zudem nochmals erweitern und eigene Befehle implementieren. Speziell für Magerun 1, das ausschließlich mit Magento 1 funktioniert, gibt es in der Community nochmals eine Vielzahl von Erweiterungen, wodurch das Tool noch mächtiger wird. Für Magento 2 bzw. Magerun 2 gibt es ebenfalls schon Erweiterungen, und es ist nur noch eine Frage der Zeit, bis auch für Magerun 2 enorm viele Erweiterungen zur Verfügung stehen.

Dementsprechend kann man eigentlich, außer man hat nur recht bescheidene Ansprüche, immer auf Magerun setzen. Da Magerun alle Befehle des Magento CLI-Tools unterstützt und noch mehr Funktionen bietet, fahren Sie mit der Nutzung von Magerun auch am besten. Das heißt aber nicht, dass das Magento CLI-Tool schlecht wäre. Ganz im Gegenteil, aufgrund der sehr guten Basis nutzt Magerun ja genau diese Befehle und Möglichkeiten.

Übrigens: Für Magerun fallen keinerlei Kosten an, und es handelt sich um ein waschechtes Community-Projekt. Daher müssen Sie sich bezüglich Lizenzierung und Lizenzkosten keine Gedanken machen. Sie können Magerun völlig kostenfrei nutzen, wobei das Projekt von der Zusammenarbeit und Bereitschaft der Mitarbeit lebt. Gegebenenfalls können Sie daher als »Entlohnung« am Magerun-Projekt teilnehmen und die ehrenamtlichen Entwickler dadurch unterstützen.
