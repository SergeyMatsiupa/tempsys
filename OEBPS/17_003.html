17.3    Multi-Domain-Setup in Magento hinterlegen

Ein wichtiger Punkt, daher möchte ich ihn an dieser Stelle herausgreifen, ist das Multi-Domain-Setup. Aktuell, Sie sehen das, wenn Sie im Frontend zwischen den verschiedenen Store Views hin und her wechseln, ist die URL bzw. die Domain immer identisch. Das ist problematisch, denn wenn als Standard beispielsweise immer der deutsche Store View hinterlegt ist, werden Suchmaschinen wie Google nie die Inhalte in den anderen Sprachen indizieren, da Suchmaschinen das Store-View-Dropdown-Menü nicht bedienen können. Auch können Sie einem Nutzer nicht eine URL zum Inhalt in seiner Sprache senden. Daher sollten Sie das »konventionelle« Verhalten, das ist zumindest meine Meinung, anpassen. Magento kann nämlich Store Codes zu URLs hinzufügen, oder Sie definieren komplett eigene URLs pro Store View. Beide Mechanismen möchte ich Ihnen an dieser Stelle zeigen.

17.3.1    Store Codes zu URLs hinzufügen

Die einfachste Option besteht im Hinzufügen von Store Codes zu den URLs. Melden Sie sich bitte mit Ihren persönlichen Zugangsdaten am Magento-Backend an, und klicken Sie auf Shops • Einstellungen • Konfiguration. Sobald Sie sich in der Systemkonfiguration befinden, klicken Sie anschließend auf Allgemein • Web und scrollen bis zum Abschnitt URL-Optionen. Dort angekommen, aktivieren Sie die Option Store Code den URLs hinzufügen, und speichern Sie die Systemkonfiguration. Nachdem Sie den Cache geleert haben, rufen Sie das Frontend auf. Wenn Sie nun im Frontend den Store View wechseln, wird Ihnen bei den URLs sicherlich ein Unterschied auffallen. Ich habe nun beispielsweise folgende URLs, mit denen ich direkt die Store Views ansteuern kann:

  • http://www.foodbaer.de/es/
  • http://www.foodbaer.de/fr/
  • http://www.foodbaer.de/default/

Normalerweise hätte ich den Default Store View, zumindest was den Code angeht, umbenennen sollen, um eine gewisse Konsistenz zu gewährleisten, lassen Sie sich davon aber nicht irritieren. Wie Sie sehen, fügt Magento die vorhandenen Store Views der URL hinzu, und dadurch können Sie direkt auf den spanischen, den französischen oder den deutschen Store View zugreifen. Der Store Code taucht grundsätzlich in allen URLs auf, d. h. nicht nur bei der Startseite, sondern auch bei Produktdetailseiten, Kategorien oder auch CMS-Seiten. In jeder URL ist der jeweilige Store Code inkludiert. Im Prinzip handelt es sich hierbei um einen Mechanismus, den Sie sicherlich auch schon bei anderen Online-Shops gesehen haben, die Sprach- bzw. Länder-Codes in den URLs verwenden. Alternativ zu den Store Codes können Sie jedoch auch komplett eigenständige URLs pro Store View bzw. Website definieren.

17.3.2    Eigene URLs pro Store View bzw. Website definieren

Sofern Sie mit Subdomains bzw. Domains arbeiten möchten, ist dies ebenfalls auf der Store-View- bzw. Website-Ebene möglich. Bleiben Sie in der aktuellen Ansicht, und ändern Sie einfach den Konfigurationsbereich, und wählen Sie beispielsweise den Eintrag »Spanisch« aus. Wenn Sie jetzt zum Abschnitt Basis-URLs scrollen, den Sie in Abbildung 17.14 sehen, können Sie alle URLs rein für diesen Store View editieren.

Abbildung 17.14    Sowohl die Basis-URLs als auch die Basis-URLs (Sicher) lassen sich auf Store-View- bzw. Website-Ebene hinterlegen.

An dieser Stelle können Sie nun beispielsweise http://es.foodbaer.de hinterlegen, um den Store View per Subdomain zugänglich zu machen, oder natürlich auch eine Domain wie http://www.foodbaer.es. An dieser Stelle haben Sie keine Limitierung, einzig die Subdomain bzw. Domain muss auf das Magento-Verzeichnis zeigen und zugänglich sein. Ansonsten ist es Magento jedoch egal, welchen Eintrag Sie an dieser Stelle hinterlegen. Im Gegensatz zu den Store Codes, die URLs hinzugefügt werden, ist eine weitere Anpassung an Magento notwendig, damit beim Aufruf einer URL die korrekte Website bzw. der korrekte Store View aufgerufen werden kann. Diese Anpassungen sind aber eigentlich nicht komplex, und ich bin mir sicher, dass Sie diese ohne Probleme durchführen können. Behalten Sie bitte nur im Hinterkopf, dass Sie eben noch eine Anpassung an Magento vornehmen müssen, wenn Sie denn auf unterschiedliche URLs bzw. Subdomains setzen, und dass durch die reine Systemkonfiguration, die Sie anpassen, das gewünschte Verhalten noch nicht eintritt.
